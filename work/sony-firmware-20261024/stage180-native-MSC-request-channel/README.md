# 第180轮：原生 MSC 请求通道与控制端退出

2026-10-29。**MSC 单会话请求处理器已落实到 C，20项当前真实进程夹具检查通过。** C 子进程自己持有第179轮的 SDK 形状假接口，Python 只发送固定报文和接收结果，不接触或传递其指针。原生候选仅编译对象；执行程序只依赖 libSystem，没有 root、真实 IOKit 库、相机或 Sony 操作。

## 新增实现

[原生接口](native_session.h)／[实现](native_session.c)将以下限制放到拥有者进程内部，独立于 Python：

- 只允许一个 MSC 上下文。初始化要求未使用的上下文，固定代次、会话 nonce 与截止时间；同一处理器不能重新初始化。
- 请求固定572字节、响应固定676字节，显式小端编码；没有 C 结构体填充或原始地址字段。请求编号从1严格递增，最多64个已接纳请求；重复编号、其他会话／代次及非支持操作拒绝。
- 一次 START、最多七次 OUT→IN 认证交换、三轮明确的摘要协议次序和一次 STOP。固定 START／STOP setup、长度、盐、挑战／最终请求的零填充及摘要长度都在 C 层重新检查。
- 同一请求内的 OUT 和 IN 共用操作截止时间。错误、晚返回、字节数未知、协议回复、在途状态和相机完成证明分别表示；OUT 不虚构实际长度，错误 IN 不交付任何数据。
- 短包和超大数据报直接拒绝，不拼接、不补读；自写进程包装器使用匿名 Unix 数据报 socket，内核接收后再复制为私有请求，拒绝截断标志。测试通道不接受相机文件、模块、设置或固件命令。
- `finish_host` 在同一排他锁内检查在途调用、使本地上下文失效并从处理器分离。并发请求无法在“检查空闲”和“释放上下文”之间插入调用。该操作不关闭设备、不归还驱动、不证明正常模式或相机线程结束。

固定数据报的边界处理与[Apple 存档 recvmsg 手册](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/recvmsg.2.html)描述的截断标志一致，并由本机超长报文测试验证；这是主机接口规则，不是 Sony 设备的时序保证。

## 当前验证

[构建 v6](build-receipt-v6.json) · [20项当前进程测试](run-process-tests-v3/results.json) · [测试源码](test_process_channel.py)。两条 MSC 家族2／8的完整假流程各有2次 control（START／STOP）、7次 OUT、7次 IN。所有认证响应均由自写夹具生成，不是相机响应。

测试覆盖完整次序和预算、跳过次序、重放编号、错误会话／代次、短包／超长报文、启动后必须重新观察、STALL／超时／短读／超长计数／缓冲区损坏／晚返回、没有新观察时的 STOP 拒绝，以及只允许一次明确请求的 STOP。

另外执行了两种真实进程情况：

1. C 子进程阻塞在假 OUT 回调时，测试的观察线程调用 `finish_host`，必须返回 PENDING；进程及上下文保持，只有测试明确释放假回调后才继续。
2. 中间控制端在同样的阻塞点真实退出。持有者检测父进程变化并设置取消标志，仍保留在途调用；祖父测试进程只释放假回调。调用返回后不再做 IN，也不自动发 STOP。回执为 host idle／body completion false；后续进程盘点未见遗留夹具。

直接子进程均由测试等待退出0；控制端退出场景的孤儿进程有完成回执及后续不存在的独立盘点，不将其写成祖父进程 `waitpid` 成功。没有强杀、复位或真实驱动取消。[最终进程盘点](final-process-inventory.json)。

## 真实运行仍缺什么

**本轮是原生通道原型，尚未接入实际 root 拥有者。** 当前可执行包装器仅用于自己的进程夹具，父进程检查使用其真实父 PID；没有实现或验证真实 root 启动、Unix peer UID／PID出生时间／审计会话核对、固定安装包、单次授权绑定和端点角色准入。不能把匿名子进程通道直接当作经过 sudo 的安全传递路径。

实际 helper 的接口申请后插入点、端点到管道引用的映射保存、身份与端口的独立证明、跨模式上下文和全局预算、真实操作期限、相机工作线程退出及驱动归还顺序仍待整合。SERVICE 模式未实现；C 处理器只接纳 MSC 上下文，整体 live 工厂仍拒绝运行。`finish_host` 只关闭本地请求入口，不能用于声称设备清理成功。

认证尾部条件写入、完整健康备份、同机恢复回读、独立救砖和目标 MAIN 1080p29.97 H.265 实录／长录的缺口继续保留。因此没有可刷包或首次刷入时间承诺。全部16项要求、用户限制与授权字段不变，`goal_complete=false`、`persistent_write_release=false`。
