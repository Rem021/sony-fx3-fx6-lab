# FX3：HEVC初始配置的几何与码率字段来源

**初始HEVC目标码率的原复制段及编码块几何已做有界验证。** 沿用stage50保存的配置，原代码把1920×1080的尺寸和边缘之和转为119／67两个“16像素块数减一”字段；目标码率字由原codec `+2c`复制到声明配置`+84`。再独立调用原HEVC GOP构造函数，该配置的156字节块被复制，目标落在GOP `+c8`。

这是三个独立入口上的数据传递试验。没有执行完整转换函数、真实调用者或硬件初始化，没有证明这三个入口在实机上的连接关系、调度与MAIN绑定。没有可刷写版本；相机、Windows和UU均未操作，全部16项验收与授权保持。

## 原路径与字段

逐条4字节反汇编确认：请求处理器根据原codec首字节分派。类型2的初始转换调用`18cc74`，类型1调用`18d8cc`；类型2后面还调用`18d62c`处理另一部分配置。不能用相邻AVC转换函数的偏移替代HEVC初始配置。

完整转换函数开头读取`BE000064`地址转换寄存器，并含当前解码器未识别的乘加指令。本轮没有猜测寄存器值、替换指令或完整执行它，而是从原纯计算段独立进入，并明确提供输入/输出地址。

偏移与指令地址均为十六进制：

| 已执行原片段 | 可复核结果 |
| --- | --- |
| `18cd8c..18cdf0` | 读取baseband尺寸和边缘字段，计算`ceil(sum/16)-1`，写配置`+38/+3a`；1080按68块覆盖，字段为67，不能把它叫1080像素字段 |
| `18d144..18d1c4` | 原codec的`+30/+2c/+34`三个字分别进配置`+80/+84/+88`；不重新计算或解码目标码率 |
| `d866c..d8714` | 验证配置块数上限，再复制配置`+34..+cf`到声明GOP `+78..+113`；目标`+84`因此落在GOP`+c8` |

几何段在原chroma助手调用前停；码率段在三个字及相关位操作完成后停；GOP段在原base助手调用前停。边界对照在断言运行时入口前停，没有伪造断言返回。GOP段真正打开的栈帧保留在停点，未补造退栈。

stage82独立验证过GOP`+c8`经帧打包落在缓冲`+64`。本轮没有把stage50初始配置、stage81动态QoS试验、stage82帧对象说成一次真实完整Start；这里只把字段对应关系继续向上追溯。

## 输入来源与对照

原输入是stage50保存的64字节common和448字节codec，由此前原AArch64构造片段在声明的metadata、索引和16M预设fixture下生成。它不是相机内存抓取，不等于当前stage75/76编译适配器的一次实际输出；448字节中未分类/未写尾部继续保留。

两种旧输出模式A5/C3，各运行三份原配置的16M正例及显式改raw codec `+2c`的20M对照，再加宽/高块数上限对照，共16例48个有界阶段。原配置不覆盖，改动逐项登记在结果内。

- 1920×1080正例得到119／67，进入原156字节复制。
- 16M改为20M时，配置只在目标字`+84`不同，GOP只在目标字`+c8`不同。
- 宽块数字段540或高块数字段512触发原边界，不复制GOP。这些大尺寸只作声明输入，未提交硬件。
- 每阶段完整检查官方代码、只读输入、配置/GOP整页与全部栈；只安装CODE与无效访问钩子，没有逐次读写钩子、MMIO或返回适配。
