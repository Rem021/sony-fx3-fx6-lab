## 回调记录的原生产者

原内部函数 `fbf84` 在调用 malloc 前传入 384 字节，随后按 `0x60` 步长初始化四条记录。两种旧值背景均验证：活动字节、键/结果字、回调指针及载荷区被原指令清零；每条的 `+1..3` 和 `+0xc..f` 共 7 个填充字节保留旧值，四条共 28 字节。不能称为整个分配区都已清零，更不是实际健康机对象。

原 `fc074` 在声明的锁后帧中执行查找/登记：初次只读查找未命中返回空；允许创建时登记到首个未活动记录；再次查询同键返回同一记录。这里的键为人工值17，未绑定真实 writer、介质、实例或配置代次。实际锁和分配器没有执行，malloc 返回指针是独立声明输入。

## 原任务如何携带该指针

原 `execqueue<execRecMovie>::exec` 复制 `0x8ea0`（36512）字节任务描述符。本轮采用单元素 deque 块的原分支，在实际分配入口前停止，再独立给出新块地址，执行原 memcpy 和 finish 迭代器更新。

声明的任务前缀沿用阶段121的人工 Start 请求，`+0x30` 指向本轮已由原初始化器和查找器处理的记录；末尾 `+0x8e98` 给出原 ExecEncStart 的 ELF 地址。原队列复制逐字节一致，保留了这个外部记录指针，没有把 384 字节记录复制进任务。任务源不是已执行的完整 EnqueueExecEncStart 输出，保留该区别。

原工作线程随后选择 front 描述符，读取复制出的函数指针，以描述符地址为实参执行原 BLR，进入原 ExecEncStart 序言，停止在其首个诊断入口。**没有执行完整 Start 或伪造它返回。**

后续弹出片段从独立声明的 post-job 帧开始：原代码把旧 deque 块地址传到 delete 入口前停止；独立 post-delete 片段推进 start 迭代器，直到 start/finish 均指向新块。整个过程中声明的外部回调记录保持不变。真实 delete、完整工作线程、退出/取消和 Start 完成未运行。

## 释放与恢复仍有单独条件

原 `fbff8` 的非空分支经原锁调用后，把回调记录地址传到 free 入口前。本轮没有执行 free。静态直接调用引用涉及 `NotifyAllMovieWriteFinishedParam`、`FileQueueStreamWriteCmp`、Enter/ExitRec 通知等上下文，不能只看队列状态推断这些路径已经完成。

本轮没有证明真实 Sony 程序缺少引用保护或存在提前释放；完整上层顺序、全部间接调用、活跃记录、取消/复用及异步消费者仍需核对。诊断与受限恢复必须分别验证：队列中/正在执行的任务、外部回调记录及其回调指针、真实录制实例/配置，以及各消费者的完成。此处只补充前置条件，不放行回收、回滚、模块卸载或刷写。
