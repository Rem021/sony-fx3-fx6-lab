# FX3 7.02：原参数控制虚表、存储和外部参数寿命

2026-10-27。**两处未知虚调用已落实为原参数控制实现：保存56字节命令结构，以及设置布尔参数。但命令内的 Open 参数指针仍为借用，不能视为独立参数快照。** 本轮只在 Mac 上分析既有官方固件镜像并进行有界指令执行，未访问 Windows、UU 或相机。

正式结果：[parameter-control-results.json](run-original-table-and-storage-20261027/parameter-control-results.json)。4组存储条件、4组缺项对照、2组原表构造前缀，共62个阶段。早期44和60阶段成功结果及当时源码副本保留，各有独立范围；本轮结论使用正式62阶段结果。

## 已落实的原路径

从既有且重新校验的 `nflasha15.img` 提取原 `libMWF.so`，SHA-256 为 `06a80e89d1bba839bf4ea83492fb1fe0490037a8c8c46bf21d7ac46657d47a26`；提取过程只读常规文件，无挂载或主机原生加载。AV 与 libc 沿用阶段108固定样本。

原 ParameterControl 虚表需要 `R_AARCH64_ABS64` 重定位。旧通用有界工具只处理部分本地重定位，因此阶段108明确将这两处目标留零并停止；那不是 Sony 虚表为空的证据。本轮按 [Arm ELF ABI](https://github.com/ARM-software/abi-aa/blob/main/aaelf64/aaelf64.rst) 的 `S + A` 规则解析原表25个条目，并为 MWF 映射处理声明范围内的本地重定位。绑定是实验输入，未验证 Sony 当前加载器的符号优先级、运行时地址或活动实例。没有修改旧封存材料。

| 位置 | 原实现和本轮观察 | 限制 |
| --- | --- | --- |
| AV 参数控制构造器 `0xa3d98` | 原指令建立 `vptr=0x1a70f0`；显式空表时可返回空容器 | 空表是控制条件，不是相机当前参数表 |
| `SetParameter` 第一虚调用，表槽`+0x60` | 目标`0xa37a0`，`SetValue(id, void*, size)`；ID`0x1001`，大小`0x38` | 实际参数表的填充、锁和分配未完成运行验证 |
| 第二虚调用，表槽`+0x10` | 目标`0xa32b4`，布尔 setter；ID`0x1057` | 原类型和存储已核对，不等于硬件接受编码配置 |
| MWF 原查找 | 在声明的有序参数映射中，原二分查找分别返回 Struct／bool 对象 | 映射是独立声明输入；没有把互斥锁视为已经成功 |
| 原 blob setter 和 MWF Struct | `malloc(56)`临时区→清零→复制56字节→Struct清理→`new[](56)`存储区→再复制56字节→长度与附加字段写入→`free`临时区 | 所有锁、分配和释放都先停止；之后为独立声明输入，不是成功返回替身 |

原 MovieEncoder 构造函数中的 `0xad5a0` 调用给 ParameterControl 传入 `0x1b62b0` 参数表及不透明 owner ID `0x80550122`。该表有86个活动记录和一个`0x1000`终止记录，两个相关原记录为：

| 参数ID | 原表类型枚举 | 原表第三字段 |
| --- | --- | --- |
| `0x1001` | 11（原构造分支调用 Struct 构造器） | 56字节 |
| `0x1057` | 0（原构造分支调用 bool 构造器） | 1；不能据此称为当前布尔值或默认值 |

原表前缀实验确实读出首行`0x1001 / 11 / 56`，走到原 Struct 的56字节 `new[]` 请求前停止。它没有执行分配、`AddParam` 或完整原表填充。表枚举与 MWF 内部类型码属于不同层，未混为一谈。

## 参数保存仍是两层关系

4组正常声明条件中，原临时区和 Struct 存储区的56字节均与阶段108产出的命令逐字相等，原布尔 setter 写入1，源命令及152字节 Open 参数区不变。

这个56字节结构的 `CMD+0x30` 仍是原虚拟地址，`CMD+0x10` 仍是物理／设备域地址。它没有把所指向的152字节一起存入 Struct。因而当前证据支持“命令结构复制，外部参数仍通过指针引用”；不支持“完整参数已独立快照”或“固定区可在回复前安全复用”。原 ownership、实际进程映射、锁与回复代次仍需核对。

4组缺项对照使用显式空映射：`0x1001`／`0x1057` 查找返回空指针，原 setter 在声明 debug0 条件下不写参数、不进入分配分支并通过原指令返回。原 `SetParameter` 两处调用后没有返回值准入检查。这说明诊断需要验证实际条目存在及回读内容；**不能只凭调用返回判断参数已设置成功。** 不据此断言正常 FX3 缺少这些原表条目。

## 执行边界

完整空表构造器、原 Struct／bool 构造器检查 SP 和被调用者保存寄存器。其余路径保留原栈帧，但每个互斥锁、`malloc`、`new[]`、`free` 边界之后都作为独立输入执行。没有伪造这些调用的成功返回，没有日志跳过、输出补写或虚调用替身。具体段落和停止位置在结果中逐项列出。

每个阶段检查声明写区之外的完整 scratch、栈，以及三个映射原库镜像未变。补充的本地重定位与 debug 导入值均先登记为实验输入。实际内存管理器的分配失败、异常展开、已占用 Struct 的释放、锁副作用、并发线程及完整 `SetParameter` 没有运行验证。

## 对主录和安全流程的影响

目标仍为 MAIN 1920×1080、30000/1001 fps、HEVC 4:2:0 10-bit约16 Mbps；精确30.000 fps单独验证。本轮没有解除阶段105的自然 MAIN 来源缺口，也没有解除 quality22/FH 与16 Mbps资源匹配、硬件 Open/Start、成片、音画同步、长录／温控／冷启动及同机备份恢复的缺口。阶段75原型仍为 `UNDEPLOYABLE_GUEST_ONLY`，全部16项状态和权限保持。

下一步应追原 `AddParam`／参数表填充与控制对象到具体编码实例的绑定，核对实际消息成帧、外部固定参数区的映射／序列化和回复寿命，并设计需要回读验证的诊断条件。不能以本轮声明对象图替代健康机备份或独立救援，不据此执行相机调用或刷写。
