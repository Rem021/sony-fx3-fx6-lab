# FX3 FF 16M：编译客体写者与在途参数登记

本轮把上一阶段由宿主设置的私有副本与目标系数，推进为**真正执行的 AArch64 客体代码**：原型自己核对条件、复制256字节FF预置、只改16M目标系数，并发布副本指针。随后Sony原解码与部分参数封装指令读取到target=16,000,000；trace=25,999,360、CPB=26,000,000保持原值。

正式复核运行通过41次原型调用、30段Sony原片段和10类负例。原始映像、原预置、第二个对象的整个0xf000字节区以及A的描述符保持不变。

**这是仅供Unicorn执行的独立原型，不是Sony可加载模块或已接入的相机钩子。** 当前未绑定Sony的真实ABI、对象来源、配置代次、同步域、全部消费者或可信完成通知，也未执行完整Open/Start、HAL或实际录制。上机、刷写与救砖仍未获验证。

## 写入与拒绝条件

原型以C11编写，使用本机Apple clang21交叉编译为AArch64 ELF64 `ET_REL`，`.text`为2032字节、508条指令，常量预置256字节，没有未解析外部函数。加载器仅处理本原型的两个`.rodata`地址重定位，不改Sony映像。客体代码和原映像均只读执行，常量区只读。

原型检查MAIN/HEVC_MP4、HD1920×1080、29.97逐行、FF、42010、行ID0x19450、原预置全部256字节和当前选择指针。owner、session和epoch仍是明确的测试输入，不能把这些数值当作机身身份或真实配置代次证明。

首次进入时先预留登记槽，随后复制原预置到该对象的+0xe010，将副本+0xb0改为249999，最后发布+0xe000指针。执行记录确认完整256次字节复制、其后的32位系数写入和最后的8字节指针发布；这些写入的PC全部位于编译原型内。原型写入被进一步限制在控制结构、A副本、A选择指针和客体栈。

编译结果含`LDAXR/STXR`锁操作及`LDAR/STLR`指针读写。原子指令的存在不证明其他Sony线程使用相同协议；Acquire/Release需要相应配对，真实同步和多核行为仍待绑定与验证。[LLVM原子操作说明](https://llvm.org/docs/Atomics.html)

## 在途登记与数据复原

原型保留8个带单调编号的登记槽，分别跟踪生产者和已经准备好的参数包。`CLOSE`阻止新生产者；已经进入的生产者仍可在关闭后登记输出包，避免关闭与输出准备之间漏掉依赖。

正式正例按以下顺序执行：

1. 原型进入并生成私有副本；Sony原片段解码、封装16M参数，B仍为原24,498,176。
2. 关闭新入口；新的进入请求被拒绝，生产者仍在时数据复原返回`HELD`。
3. 原生产者登记参数包，再归还生产者登记；参数包仍在时复原继续返回`HELD`。
4. **显式模拟的消费完成通知**归还参数包登记，数据复原才重新选择原预置；新查询和新封装回到24,498,176。

完成通知由测试调用者提供，尚无真实Sony消费者或HAL回调证明。原型信任这一通知，不能防止真实集成方过早通知；这是接入前必须补齐的条件。

复原仅改变选择指针。旧16M参数包与私有副本的字节仍保留，原型不释放副本、不卸载代码，也不宣称安全代码回收、硬件复原或冷启动恢复。移除引用与回收存储必须区分，后者需覆盖旧使用者退出；这里借鉴原则，未认定Sony使用RCU。[Linux RCU说明](https://docs.kernel.org/RCU/whatisRCU.html)

## 负例结果

| 输入或状态 | 客体原型结果 |
|---|---|
| FH描述符 | 拒绝进入，不复制或发布 |
| 测试epoch改变、预置字节不符 | 关闭入口并保留故障 |
| 重复归还 | 关闭并保留故障，复原被拒绝 |
| 第9个在途登记 | 拒绝并关闭；归还原8个后故障仍保留 |
| 参数包完成地址不符 | 拒绝归还，保留两个在途登记 |
| 锁已被持有 | 返回忙碌，不替别人解锁 |
| 指针属于其他预置 | 拒绝覆盖并关闭 |
| session不符 | 拒绝本次调用 |
| 编号即将回绕 | 拒绝并关闭，不发布副本 |

这些是顺序执行的客体边界测试，不是弱内存、多核调度、真实竞态或故障救援测试。
