# WBI 零填充记录与 CP 暂存区

2026-10-30；原 FX3 7.02 WBI 数据、Sony FX3 Ver7.00 GPL 格式参考、公开 A7 IV v2.00 AP 原指令。没有恢复 WBI 或访问设备。

**本轮确认前轮的 `MMC ... zero fill` 候选由 WBI 段描述符驱动；原 WBI 的全部1,399个记录均未覆盖当前默认 AP 暂存区，82个零填充记录也没有覆盖。** 因此这条候选不能补齐 CP 暂存内容，不能证明前轮未确定的槽位尾部和空洞已被初始化。更早的整机初始化仍未知。

1,399段的解析与 Sony 格式定义已有[阶段203](../../sony-firmware-20261024/stage203-WBI-layout-and-early-memory/README.md)证据。本轮新增的是原参考 AP 的记录消费／flag 分派验证，以及对已绑定暂存地址的三处全表查询，没有把旧段表当作新发现。

## 原始消费代码与 flag

原参考函数 `FE0596E4` 使用字符串 `load_wbi_main`。其 `FE0597D0` 附近按每扇区8条、每条64B，从元数据页把原记录复制到 `FE06C100`：

- `+0x00`：物理目标地址。
- `+0x18`：flag 的低字节；bit0置位跳到 `FE059908` 的零填充分支。
- `+0x20`：原始展开长度。

Sony GPL `warmboot.h` 的 `wb_section` 定义与这三个偏移一致，`WBI_SH_ZERO=1`。`wbi_raw.c` 在该位设置时将 `rlen` 写为0并跳过数据写出。这支持原记录的零填充含义；本轮没有为这些记录生成零字节，也没有声称执行了恢复。

两份原 WBI 记录分别作为明确的独立片段输入，保留整个原始512B元数据页：

| 记录 | flag | 目标／长度 | 原指令结果 |
|---|---:|---|---|
| 1 | 0 | `0x40000E000`／8,192B | 复制64B精确一致；88条指令后停在普通记录诊断前 |
| 44 | 1 | `0x40293D000`／4,096B | 复制64B精确一致；86条指令后停在零填充诊断前 |

另一个独立入口从 `FE059928` 开始，使用原记录44，只执行6条指令就停在原 DMA 初始化 helper `FE056298` 之前。日志、元数据块读取和 DMA helper 都没有运行，没有补成功返回。这些片段不是连续 WBI 恢复路径。

## 三个范围均无覆盖

范围来自前轮原 BK4 记录与 AP／CP 上下文字段的绑定：

| 范围 | 地址区间，终点不包含 | 覆盖该范围任意部分的 WBI 记录 |
|---|---|---:|
| AP 主暂存区声明容量 | `0x412000000..0x414A00000` | 0 |
| AP 主传输源的默认长度投影 | `0x412000000..0x4132F1E00` | 0 |
| AP 第二传输源的默认范围投影 | `0x414A00000..0x415901000` | 0 |

查询包含全部1,317个实存记录及82个零填充记录。排序后的相邻边界为：左边记录1398结束于 `0x4110C4000`，右边记录1185开始于 `0x41A000000`；中间150,192,128B没有声明恢复段。主／次暂存投影都在其中。原表顺序没有被当作物理地址排序。

这里证明的是**这份固定 WBI 的声明记录没有覆盖上述默认地址**。它不证明相机从未初始化该地址，不排除其他启动版本、其他初始化机制或未解释数据，也不能由地址值推断实装 RAM 容量。WBI 段表之后的历史尾部继续保留，未假定它是任意缺失内存的备份。
