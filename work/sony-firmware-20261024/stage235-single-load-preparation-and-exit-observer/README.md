# FX3 单次加载的准备、启动与退出观察研究

2026-10-30。**已把准备、启动和退出观察合并为一个自写构造函数，但当前版本仍未通过安全准入：额外条件模型复现了父关系变化后误认退出码的反例。这版不能投放真机或刷写。** 8项范围内检查、24个正常及拒绝场景通过，并不推翻该反例。

本轮所有程序执行均为Mac上Unicorn中的自写ARM64。没有运行Sony、glibc、Linux或驱动原代码，没有创建实际Linux子进程，没有查询相机/USB、提权、认证、上传或写固件。

## 已实现的完整本地衔接

[combined.c](combined.c)先完成234的固定RAM计划准备：严格目录/权限、私有复读、不覆盖发布、全部目录关闭及最后时钟检查。只有该函数实际返回准备成功，才在同一调用中启动空操作子进程；文件存在和STAGED回执不能绕过此内存中的分支。

计划中的执行镜像SHA使用本次完整合并程序的实际文件SHA，内嵌的231 SHA只是固定组件来源。工作入口同时比对原计划dev/inode及**准备成功时保存的完整计划SHA**，避免同inode文件被改写、重算CRC后仍启动。这个缺口有[旧合并程序反例](plan-substitution-before-fix.json)，现已拒绝。

创建子进程前开始屏蔽调用线程的可屏蔽信号，一直维持到GO、私有DONE和wait4观察结束；创建与观察之间没有返回服务回调的空隙。子程序继续从匿名自写代码副本内clone，不exec、不共享VM/FD表/信号处理表。收集循环使用`WNOHANG|__WCLONE|__WNOTHREAD`，最多100轮、每轮可休眠10毫秒，并检查单调时钟及任务期限。它限制程序轮次，不保证真实内核调用的硬实时延迟。

同一次构造加载可从不同模拟服务线程进入，无须下一次请求再回到同一线程。超时保持HELD和占位；即使子进程稍后结束，下一次加载也只会被准备目录重放保护拒绝，不再通过旧OBSERVE路线转成成功。

私有结果文件只表示CHILD_EXIT_OBSERVED，不证明结果写完后的目录关闭、最终时钟或USB归还。最终本地状态另在关闭目录和核对时钟之后确定。实际direct setter不会调用两个状态导出，主机回传仍未实现。

## 两类进程身份问题必须区别

[旧231反例](old-creator-gap-counterexample.json)证明，活创建线程的proc锚和`__WNOTHREAD`不足以单独绑定其子进程。原子进程DONE后实际退出68，退出被外部模型等待者取走；若同一仍活线程在两次加载之间创建了复用编号的新子进程，旧观察器会误接受新exit0。其他创建线程的替换仍被拒绝。235的连续调用和信号屏蔽去掉了这一普通回调/信号间隙。

**仍未解决的是内核父关系变化。** [当前合并程序反例](remaining-parent-identity-counterexample.json)显式输入外部`__WALL`回收及父共享/收养条件：原任务退出68，另一个同编号、同等待父关系的进程退出0。即使当前线程仍屏蔽信号，程序仍返回了3/0。该反例是条件模型，未观察到相机实际发生；相关进程上下文也没有被测定。

[Linux v4.9 fork源码](https://github.com/torvalds/linux/blob/v4.9/kernel/fork.c)具有CLONE_PARENT继承父关系及退出信号的分支，[exit源码](https://github.com/torvalds/linux/blob/v4.9/kernel/exit.c)具有线程退出时的父关系转移。因而不能仅以调用线程不运行新回调，宣称所有进程归属变化已排除。源范围固定在[kernel-identity-review.json](kernel-identity-review.json)。旧阶段关于“已修复PID复用”的结论只能用于它们当时覆盖的其他线程替换场景，不能作为完整身份保证。
