# FX3 原 VCD 消费端校验与完整请求缺口

2026-10-25（本地日期）。本轮仅离线执行原固件指令，未连接相机。

**找到了与 av-cam 对应的原 VCD 参数校验链，并实际运行了其中的纯配置校验函数。原 FF 和私有 16M 四组编码块均返回 0；但这不能证明 16 Mbps 或完整启动请求已被接受。** 原函数在这条 HEVC 路径不读取码率字；配套基带块还会被另一个原校验函数拒绝。下一步应补真实 start-input 的生产链，而不是把配置校验返回 0 当作硬件验收。

## 跨映像的原代码绑定

- av-cam `0x2186c8` 原路径 getter 返回 `/usr/codec/vcd_firmware_imola2.bin`，对应官方包中已提取的同名文件；版本文字为 `SW_VER_46_21_02_0______________`。这里只绑定原路径、文件与指令，不声明实机当前已加载该实例。
- 上游原调用者 `0x21f7f4` 将 COMMON `owner+0xe198` 的 64 字节复制到栈槽 `+0x80` 所指缓冲，将 CODEC `owner+0xe1d8` 的 448 字节复制到 `+0x70` 所指缓冲；`0x221a9c..0x221b08` 再传入 `0x26c91c`。
- `0x26c91c` 原代码组装命令：`+1=0x1e`，参数地址进入 `+0x18/+0x20` 等位置，经共享地址转换后调用 `0x27470c` 通知。此段本轮是静态审阅，未执行通知寄存器写入。命令号 `0x1e` 与 30 fps 不是同一个命名空间。
- VCD 的 MIPS 原路由 `0x19118c` 读取命令 `+1`，从原表 `0x24654c` 取函数；`0x1e` 项指向 `0x1a3f00`。本轮实际执行路由到该入口前停止；另测下一命令和越界命令，分别到其它原检查入口/断言入口。
- `0x1a3f00` 原启动检查器核对 `EncConfigAddr`，范围和 cache 操作长度均为 `0x1c0`（448）；随后在 `0x1a42b8` 调用 `0x1a8594`。旁边原断言文字与 `imola_api_parameter_check.c` 提供结构名锚点。完整启动检查器含真实运行时全局值、地址映射、cache 等依赖，本轮没有运行完整正文。

VCD 映像中连续的 MIPS32 小端指令、原绝对跳转/函数表，以及 `0x8023a9c0` 断言字符串引用共同支持客体的 `0x80000000+文件偏移` 地址模型，依据不只来自文件头。使用 Unicorn MIPS32 24Kc 作为声明的虚拟 CPU；实际处理器型号/当前映射未观测。

## 实际原函数结果

| 输入/对照 | 原函数结果 | 可支持的结论 |
|---|---|---|
| stage48 原 FF、文件零初值 | 配置校验返回 0 | 该原配置谓词通过 |
| stage48 私有 16M、文件零初值 | 返回 0 | 同上，不能推出码率能力 |
| stage48 私有 16M、A5/C3 旧值 | 两组均返回 0 | 这条配置检查路径不依赖那 52 字节 |
| 52 个未写字节分别改 FF，再全部改 FF | 53 组均返回 0 | 仅在该 HEVC 输入/原检查函数范围内成立 |
| codec/公共标志/HEVC 字段/VUI 错误值 | `0x3001/0x3002/0x3044/0x30c1` | 原错误分支与返回值实际执行 |
| 另一 codec 的公共结构对照，`+0xe=0/A5` | `0/0x3007` | 同一未写位置在其它 codec 路径可以有意义 |
| target/trace/CPB 三个字分别全零或全 FF | 两组仍返回 0 | 当前配置谓词不检查这些码率字 |
| stage48 未改的 COMMON 64 字节 | 基带校验返回 `0x3006` | 现有最小输入不是完整有效启动请求 |
| 仅把 COMMON `+0xc/+0x10` 人工设为 1920/1080 | 基带校验返回 0 | 只是明确的几何对照，不是已实现原生产者 |
| 同一几何对照将 1920 改为 1921 | 返回 `0x3006` | 原几何约束确实生效 |

合计 **71 次原函数/路由片段执行**，包括 66 次核心运行和 5 次基带/码率范围对照。编码块与原代码均保持输入原样；函数沿原 MIPS 调用、分支延迟槽和栈返回，没有替代输出、跳过服务或伪造返回值。

四组正向 HEVC 配置检查实际仅读取 448 字节中的 16 个字节：`0..3,18,1e,1f,21,22,23,26,27,3d,64..66`。这些位置不包含 stage48 的 52 个未写字节，也不包含 `+0x2c..+0x37` 的三个码率字。因此返回 0 既不是完整字段有效性证明，也不是 16M 硬件能力或 52 字节全局无用的证明。实际编码过程仍可能读取其它字段并保留异步引用。

stage48 最小 start-input 设置了 `+0xe0/+0xe2`，没有设置 `+0xe8/+0xea`。原 A64 builder 的 `0x221e14..0x221e20` 将后两项复制到 COMMON `+0xc/+0x10`，所以基带块几何为零，原 VCD 基带谓词返回 `0x3006`。这是人工最小输入不完整的证据，不是相机固件缺陷，也不是 HD HEVC 不可能的证据。本轮没有改写旧结果来掩盖它。

## 本轮边界与下一步

1. 优先追原 start-input 的 `+0xe8/+0xea` 等生产者、裁切/有效尺寸、步幅/时序和帧率关系，接入实际原参数链；保留人工 quality24/FF 行 386 与原 quality22/FH 未命中资源表的区别。
2. 原配置/基带谓词应纳入后续离线验收，但不能代替完整 `0x1a3f00`、实际 VCD 分派/编码动作与完成通知。主调用者 `0x17e42c` 在 `0x17e444` 调用原路由，随后按返回值选择动作，列为后续入口。
3. 继续 av-cam 的原日志/OSAL、实际 owner/配置代次和共享内存装载；地址函数原导出涉及 `DAIF/AT/PAR_EL1`，本轮只定位，不用常量返回代替地址翻译。继续核对通知、响应、所有编码器/音频/mux/工作者退出及 VCD 异步缓冲寿命。
4. 原目标仍是经典 FX3 7.02 的 1080p、30000/1001 fps、HEVC42010 约 16 Mbps 主录；精确 30.000 单列。实拍、音频/时间戳/同步、长录/温度、同机健康备份、受限恢复回读、WBI 冷启动及独立救援均未完成。

未执行 UU/Windows/相机主动操作；当前仍仅授权 Windows 缓存 PnP 盘点。没有新可加载相机模块，没有上传、WBI 或刷写，没有新增“变砖可救回”的保证。
