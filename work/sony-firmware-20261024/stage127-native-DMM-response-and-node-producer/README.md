# FX3 DMM 回复布局与原区域节点生产

2026-10-27，仅 Mac / Unicorn。**正式复核 140 个有界片段：定位原 DMM 请求/回复布局，并由原 GetDmmExtList 生成 17 个节点，再交给原 SetMemTbl。** 这些节点依赖明确声明的服务回复与 malloc 地址输入；没有实际分配相机内存，没有打开相机接口，没有主录或恢复验收。

## 本轮改变了什么

阶段126由宿主人工拼接完整节点。本轮执行原表计数、节点容量计算、原 memset、字段填写、块复制/求和、链接、表中区域键更新和函数返回。模式21生成7节点，模式25生成10节点；覆盖1/2/8块输入，包含中途遇到零地址停止复制的对照。随后原 SetMemTbl 消费这些原指令生成的节点，输出从独立声明的全零 BufferTable 开始。

服务层仍是未执行的间隙：OSAL 动态ID、消息分配、来源设置、发送、接收、消息释放、ID释放，以及 malloc/free 均在原调用前停止。间隙后另立声明输入帧，不伪造服务返回。原代码只在 Unicorn 中执行，同固件 libc memcpy/memset 也在客体运行。`before_host_allocator/free` 是脚本的停止标签，不代表调用过宿主分配器。

## 回复输入需要的边界

| 项目 | 原指令/声明输入范围内的观察 |
| --- | --- |
| 分配请求 | 命令0x20，消息体0x28字节；单位号在+4，+0xc为ffffffff，+0x16为1。发送/接收均未执行，来源设置对消息的影响也未验证 |
| 回复 | 类型/有符号状态位于+0/+2，块数在+8，区域键在+0xc，16字节块项从+0x18开始 |
| 固定输出 | 原代码先清0xa8字节，按数量复制；块数非零时，本次0x8020路径复制0x18+16×N字节 |
| 附加字段 | 标志启用时，输出+0x98 = 第一块地址数值 + 全局字值，+0xa0 = 同一全局字值。本轮全局字0x10000000是人工输入，不是实机映射 |
| 9块人工回复 | 第9块从+0x98开始，与附加字段重叠；原复制/附加写入后该块描述值被覆盖 |
| 10块人工回复 | 复制长度0xb8，超过原0xa8布局16字节；在独立0x200字节客体容器内记录了这16字节变化，没有向真实栈或设备送入该数据 |
| 非零状态/异常类型 | 到原诊断函数前停止；正状态的诊断后续没有执行，不能把日志边界当成原函数已拒绝或完成错误清理 |

原 GetDmmExtList 的临时输出从其0x120栈帧的+0x78开始，刚好剩0xa8字节。按照本轮调用者布局，离线候选只接收预期类型0x8020、状态0、1到8块、长度完整且第一块非零的文件字节；其余拒绝。该上限是保护本轮调用者布局的保守约束，**不是 Sony 官方协议最大块数或物理有效性保证**。真实服务是否始终保证此边界尚未证实；人工异常结果不证明存在可触发的固件漏洞。

本轮也澄清了节点+0x20的来源：它来自上述输出+0x98的加法结果。阶段126选择“起点+跨度”只是当时的人工输入，不能据此把该字段解释成真实缓冲结束地址。
