## 修正CODE日志的解释

初轮观察器在裁剪助手的`break`延迟槽报告处主动停止。独立保留原DIVU/BEQL/BREAK字节，分别在3个地址以除数1、2、0作9组对照：

- 除数1/2自然返回10/5，无中断；CODE日志仍包含BREAK槽地址。
- 除数0在相应保护处产生原CPU异常，中断号18，没有当作成功结果。

因此在本机Unicorn2.1.4/MIPS32_24KC上，CODE观察可能包括已被取消执行的分支延迟槽。**观察到某PC不等于该指令已发生架构效果**；不能单凭日志出现BREAK判断除零，也不能单凭PC次数判断副作用次数。

正式运行只对这3个已校准的原BREAK地址保留CPU自行判断，并安装实际中断停点；任何实际异常都拒绝该阶段。没有删除BREAK、放行其它敏感指令或补返回。旧的CODE轨迹应按这一范围解读；原输出字节与栈检查并未因该观察差异自动失效。此前stage80关于全局内存钩子的另一问题仍分别保留。

两次被观察器阻止的源码和失败记录、初版3例及最终9例校准均保留。
