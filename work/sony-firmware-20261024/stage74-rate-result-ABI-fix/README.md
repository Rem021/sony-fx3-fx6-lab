# FX3：离线适配器返回结构修复与旧版隔离（2026-10-26）

**发现并修复了我们自己的离线适配器错误：stage69把原查询的返回结构声明成24字节，原函数实际写入范围延伸到52字节，覆盖了调用者栈上保存的返回地址和寄存器。旧适配器不能再作为调用安全证据，也不允许用于相机。** 原固件文件没有这个新增声明；本轮没有接触机身。

旧版问题在两组输入中复现。新版使用56字节、8字节对齐的结果容器，覆盖本轮原函数的写入范围；两组目标输入的保存槽和容器外栈帧保持不变，仍读到目标16,000,000，并按原实参继续到原OSAL／未执行的内核锁边界。另核对原UHD及关闭入口对照。总计6例、41段有界执行和完成回读。

**修复结果仍是Mac上的客体原型。** 没有验证实际原通道返回、完整适配器退栈、共享同步、硬件编码或恢复，未形成可刷固件。

## 错在哪里，旧检查为什么漏掉

原`av-cam+0x225b7c`通过X8接收结果地址。前24字节是我们此前读取的三个64位值，但原函数结尾还写入`+0x18`、`+0x1c`、`+0x20`、`+0x24`、`+0x28`、`+0x2c`和`+0x30`附近的字段。最后一条为`str w10, [x19, #0x30]`，结束偏移为`0x34`，即52字节。

本轮目标路径实际写入50字节，覆盖跨度52；`+0x2e/+0x2f`没有写入，不能自行视作已初始化字段。旧24字节声明使其中26字节写到对象之外。

stage69编译结果把24字节对象放在调用者SP+8，保存寄存器从SP+`0x20`开始。原查询的额外写入与这些保存槽重叠，包括保存的X30返回地址。先前仅核对前三个数值、栈对齐以及通道参数；随后停在原通道内部的内核入口，没有执行适配器返回，因而未暴露坏返回地址。**读数正确、16字节栈对齐和到达下游边界，都不能证明完整调用安全。** 这是此前验证范围的遗漏。

| 本轮目标路径观察 | 旧版 | 修复版 |
| --- | --- | --- |
| C结果容器 | 24字节 | 56字节 |
| 编译后的适配器栈帧 | 80字节 | 112字节 |
| 原查询实际写入 | 50字节，跨度52 | 相同 |
| 容器外原查询写入 | 26字节 | 0 |
| 保存的X30与其它寄存器槽 | 被覆盖 | 全部保持 |
| 原查询前三值 | 25,999,360／16,000,000／26,000,000 | 相同 |

本轮在查询入口前保存整个适配器栈帧，记录原指令的每次结果写入，在原查询返回到适配器的第一条指令前比较整个帧及保存槽。旧版在这里停止，没有继续执行其损坏的调用现场或伪造通道返回。

## 修复内容与ABI边界

新增C源码只改两处：结果结构增加32字节未分类尾部，使容器为56字节；编译期断言由24改为56。写入器、目标描述、资格判断、参数转交、拒绝入口和Sony原文件不改。原始stage69源码、编译对象、结果及封存清单保留，隔离说明另存。

[Arm AAPCS64](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst#69result-return)要求间接返回时由调用者提供足够大且满足对齐要求的结果空间，并经X8传入；聚合结构大小还受对齐影响。本轮重新读取官方规范，并核对实际Clang产物和原函数写入，不能仅凭原型声明推断Sony类型。

这里的56字节是当前编译容器大小，用来覆盖该固定原函数的52字节写入范围，**没有据此断言Sony源码中的结构恰好为56字节**。尾部字段及填充语义仍未分类，不清零或赋予猜测名称。该查询通过尾调用也有原引用；没有因未找到直接BL，就认定它是未使用函数。

## 修复后的执行范围

两组目标输入沿原管理对象／factory／队列／matcher，进入已声明的客体适配器，调用同一严格写入器和原查询。查询结果全部落在56字节容器内，容器外整个适配器帧及六个保存寄存器槽逐字节保持；原FH描述和私有16M系数保留。

继续同一现场，适配器把与原入口相同的X0／X1／W2／W3交给原通道；原资源消息与LIRO绑定的OSAL继续到原内核锁入口，仍停在第一条指令前。原UHD不调用目标查询／写入器，原关闭入口在自定义拒绝函数体前停止。这些对照不证明真实录制或Sony安全错误返回。

生产者引用仍为live=1。没有伪造完成通知、通道返回、引用退出、指针复原或代码卸载；保存槽完好不等于整个退栈和后续所有权已经验收。

## 哪些旧结论需要修正

- stage69的24字节适配器已隔离。其前三个读数和暂停前数据流是实际局部观察，但不能支持调用栈安全、可正常返回、可装载或可刷写结论。
- stage57的独立结果区只读取前三字段；它并未提供完整返回类型证明。后续复用查询必须按完整写入范围分配空间。
- stage70至73的原管理／队列／退出／释放研究没有执行映射着的自编译适配器，此错误不自动否定那些原函数的局部观察；它们仍各有原来的范围限制。
- 当前候选只认本轮新编译的客体适配器，状态仍为不可部署。真实MAIN／配置代次、共享锁、查询／封装一致性、实际编码器消费、回退和救援门槛保持。

1920×1080／30000÷1001（29.97）HEVC42010约16Mbps主录、精确30单列、音画／长录／温度、同机健康备份、受限恢复／回读、WBI／冷启动及独立救援的完整16项要求不变。Windows继续延后，本轮无UU、相机接口、驱动／模式／权限、机身文件、模块上传、WBI或刷写操作。
