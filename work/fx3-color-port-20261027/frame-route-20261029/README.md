# FX3 色彩调用的资源门槛和回调登记

2026-10-29。**已恢复局部色彩调用之前的原资源检查，以及指向该调用函数的原回调登记记录。** 原检查会根据 71 项资源掩码与资源记录决定是否继续；失败时设置状态字节，原同步片段会重新清掉它。本轮 11 组有界检查仍未证明正常主录像素路由、完整 VENICE ISP 或可刷入的修改固件。

## 原色彩调用前还有资源条件

此前执行的 `VA 0x9d3474..0x9d3484` 是色彩调用片段。其原函数从 `0x9d3454` 开始，先调用 `0x9d41a8`，通过后才会调用原 `SetVfxMlutParam`。因此旧片段通过不能替代这个前置条件。

门槛读取对象 `+0x120a`。该字节为零时，原 `0x9cfbac` 检查对象 `+0x11c3` 起的 71 项掩码；对每个非零项，要求对应 64 字节资源记录的 `u16 +0` 为零、`byte +5` 非零、`byte +4` 为零。字段完整物理语义未恢复，保留原始偏移，不擅自命名为“帧已完成”。

检查通过返回 1；不满足时，原门槛在 `0x9d41c8` 将对象 `+0x120a` 设为 1，调用者跳过色彩设置。该状态未清除前不再执行资源检查。原同步代码 `file 0x300236..0x300242` 的 72 字节清零覆盖掩码和这个状态字节，说明不能把它解释为永久失败标志。

七组检查从原调用者入口执行，分别覆盖：原新申请产生的空掩码、声明的单项掩码与原分配记录、三个资源字段不满足、已设置状态字节，以及失败后恢复记录／执行原清零。正例会进入原控制器与 SDK；反例在原分支跳过后、对象虚调用前停止，没有提供虚调用成功替身。[门槛、状态写入与 SDK 记录](caller-gate-results.json)

## 空掩码的来源没有冒充正常帧

三组申请追踪记录了原调用者、选择器和 broker 的实参。新申请沿原 VFX 分配器得到 `0x80000001`，但所查局部流程没有写非零掩码。另一项 kind 16 在已有原资源表中对应 `GRP05_STP`；旧实验把该申请作为明确的成功边界截获。因此空掩码不能充当整条正常资源生产链的证据。

移除该 STP 成功替身后，原选择器和 broker 推进到 `VA 0x483078` 的 STP 分配器入口；本轮停止在该入口，没有伪造它的返回。其原源片段已保存，尚未执行硬件初始化。重复同一申请且未执行释放，也实际返回 0，没有被当作成功复用。[三组申请追踪](mask-acquisition-results.json)

一次先调用旧封装重复申请的探索触发了“必须返回 1”的断言；保留[原失败记录](attempts/parent-repeat-assertion.json)。新的有界追踪直接保留原返回 0，没有放宽原代码分支或修改旧封存脚本。

除原新申请空掩码外，其他门槛案例的掩码、异常资源字节或初始状态均为明确的 RAM 夹具。有效资源记录本身来自原 VFX 分配器，仍不代表当前机身状态。

## 找到的是回调登记边界

原 `0x9d3266..0x9d328e` 片段构造五个字的记录，其中包含 `0x9d36c1` 和 `0x9d3455`；后者正是上述 MLUT 调用函数的 Thumb 指针。原 wrapper `0x9d5f6c` 将记录、对象与原参数送往 `0x44d438`，使用全局分派对象 `0x13d7dd8`。

本轮执行这份原记录的构造和 wrapper，在分派器入口停止并读取实参。没有执行队列、调度或回调到达，也没有把两个函数槽擅自解释为具体生命周期名称。[原片段与引用候选](frame-route-source-results.json)

## 后续像素连接仍需追查

通过色彩调用之后，原调用者继续进入 `0x4285c4`，再按对象 `+0x15d8` 等字段进入 `SyncUtilityCamCore.cpp` 关联的图像处理 helper。该 helper 含原图像对象／缓冲查询与分派，但输入字段的正常生产、实际缓冲和编码输出尚未接通。本轮执行停在该 helper 前，其代码只作静态记录。

原指针 getter 在所查调用片段中已执行，但返回的正常 BSS 参数向量尚未在这条完整调用路径上初始化；停止前未解引用它。此前在独立 RAM 构造的同布局向量，也不能代替真实进程初始化。

Sony 官方手册继续明确 [PPLUT 可应用于录制影像](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000876510.html)，同时说明本机 S-Gamut 设置不支持整个 S-Gamut 色域。这里据此保留输入域核对要求，不把同名色域或监看外观当作完整 VENICE 成像链兼容证明。

下一项是 STP 原分配和图像缓冲 helper 的生产／消费关系，以及正常回调派发；完整供体、传感器／ISP 适配和修改包准入仍是目标中的独立要求。
