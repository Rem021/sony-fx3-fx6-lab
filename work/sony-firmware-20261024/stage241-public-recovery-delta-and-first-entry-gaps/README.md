## 新增内容实际是什么

固定比较[旧400313e到新575c707](https://github.com/cokeenet/zve10-qemu/compare/400313ea073269f7a87eab544b44dfc388f19ed9...575c707dcbd79dcacab7e28e49f6b66434b25463)。[完整差分](qemu-new-commits.diff)为34345字节，仅`docs/QEMU_M2_PROGRESS.md`增加764行、删除0行。[实际执行的初始审查器](audit_delta.initial.py)取得两端原文，以Git blob SHA1对上差分中的对象前缀，再逐字节验证新文档等于旧文档加该附加段，避免把文件名或搜索摘要当作完整变化。

新增第103至114节报告了：识别内嵌initramfs覆盖外部修改、重建可控启动镜像、排查服务队列/内存分配、恢复原IMDB及匹配setting、调整模拟GPU的中断和寄存器模型。末节作者报告已产生19个启动包，但帧仍为0，且停在backup队列应答。这是作者的ZV-E10/ZV-1M2仿真日志，我们没有运行或复现。

文档包含作者本地QEMU补丁片段，不能将“只改文档”解释成没有技术内容；但此次仓库差分中没有新增可直接构建的恢复源文件，也没有FX3 7.02健康备份、硬件恢复、逆写或冷启动证据。日期标题包含作者的10月31日记录；抓取时间另以UTC保存，不把标题当成独立测量时间。

对我们的直接帮助是核验方法：必须确认实际载入的是哪份镜像、哪份配置，以及每个原生服务是否真正完成。伪造队列成功、GPU有中断、出现启动包或窗口，都不能代替真实帧、录像或恢复验收。因此目前也没有“在Windows上完整模拟FX3、改好直接刷入”的现成路线。
