## 备份程序发布前新增必须核对的内容

1. 明确使用哪个读文件家族。Jiritsu GET_FILE2与PMCA pFunc ff01/cmd2不是同一入口；不能互相套用安全或兼容结论。
2. 对GET_FILE2，kind0/selector3的待日志分支会准备可创建/追加的写打开并刷新日志。不得把它放入“只有读取”的备份方案。00/ff/00跳过该分支仍不足以证明整个命令无副作用。
3. 核对早先挂载、共享对象初始化、filename转换、stat、DMM申请、fsync/close和异常释放。未建立原根对象时，不能把空指针当自然安全拒绝。不能用失败后“再试一次”替代清理证明。
4. 目标AP文件是66796字节，超过旧离线codec的65536主机上限；请求本身不限制设备整文件申请。需要同时约束机身文件大小、设备分配、线缆帧/分片和主机存储，不能只放大主机上限。
5. 精确核对文件最终路径。当前旧保守编码器不能直接给/setting两个目标路径生成已接受请求；不通过未审查的相对路径绕过来推进备份。
6. 取得两次一致的原件/长度/哈希后才能叫健康备份。官方AP原件是比对基线，不是机身备份；只读取到AP配置也不是全机可恢复备份。
