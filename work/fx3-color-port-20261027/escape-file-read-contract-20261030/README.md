**本轮确认参考 FAT 代码能够从原 FX3 p8 目录取得4个文件的实际长度；其 DmmCfg 读取请求和尾部复制都只覆盖实际文件长度。选中的文件读取代码没有初始化整个预留槽位，上层也没有在该文件返回点检查短读或聚合文件错误。** 整个启动过程是否更早初始化暂存区仍未知，不能把现有4份文件加零拼成原始 CP RAM 镜像。

完整 FX5／VENICE 功能与色彩链移植、目标 FX3 AP 身份、实际 RAW／ISP 运行和修改包准入都未完成。本轮没有生成修改固件或可刷包，没有文件块读取、设备动作或实际刷写。

## 尾部复制的确切范围

从原 p8 直接取得 sector308 的512B作为明确的片段输入，其前312B与 DmmCfg 的最后312B相同。独立执行 `FE04E54C` 的原 memcpy 路径后，在 `FE04E568` 前停止：

- 仅写入目标文件偏移43,008..43,319，共312B。
- 文件前缀与整个槽位余量的 `0xA5` 检查哨兵均未改变。
- DmmCfg 102,400B槽位中，文件后59,080B没有被这一复制片段初始化。

哨兵是本轮明确的分析输入，不是机身内存样本。本轮没有装入整个文件，也没有执行尾扇区读取；上述结果只说明这个原复制路径的写入范围。更早的 DDR、启动或其他模块是否初始化该区域，仍需独立证据。

## 长度与错误处理

原文件 wrapper `FE059E20`：

1. 查询文件长度，把结果保留在 W20。
2. 用该长度调用 `FE05A674`，没有传入描述符槽位容量。
3. 读取结果只检查符号位；非负时直接走到 `FE059E84`，最后返回原 W20。
4. 查询失败走 `-408`；读取失败的分支经诊断再返回读取错误。

第3项是静态控制流结论：若后端返回短读或0，这个 wrapper 单独没有把它与查询长度作相等比较。没有制造一个实际短读回复来宣称整条路径已执行。

escape loader 在 `FE052298` 调用该 wrapper 后，把返回值仅作为日志参数，随即推进下一条记录；其普通末尾在 `FE0522D4` 设置 W0=0。选中范围内未见按该返回值中止或聚合的分支。诊断本身未执行，因此这里不推定实际异常日志、整次启动或机内失败处理已成功完成。

[静态与独立验证结果](validation-results.json) 核对22条关键原指令及4个函数的完整直接调用集合。文件 wrapper、FAT read、cluster read 的这些直接调用不含 memset；这仍不是全启动过程从未清零的证明。

## 内容来源仍不完整

沿用上轮固定的9个 class5 地址描述符，整个 escape 范围为19,865,088B，其中：

- 9个声明槽位合计15,302,096B。
- 槽位之间有3段未列出的空洞，合计4,562,992B。
- 原 p8 中4份现存文件的实际内容合计2,011,742B。

这些是默认地址的内容覆盖投影，不是观测到的 RAM 内容。槽位尾部、空洞与缺失路径都不得自行补零后作为完整映像。
