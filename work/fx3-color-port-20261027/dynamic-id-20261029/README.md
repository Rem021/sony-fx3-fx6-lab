# FX3 原动态 ID、软件块池与消息申请前缀（2026-10-29）

尚未达到“FX5/VENICE 整套专业功能与色彩链替换固件可正常刷入 FX3”的停止条件。本轮识别并执行了之前挡在 NRV 缓冲申请前的动态 OSAL ID 分配逻辑，将三个原申请前缀推进到消息缓冲分配入口。8 组有界验证通过；没有发送消息、取得图像服务回复、构造真实控制器或输出修改固件。

开始前核验 [上轮封存](../controller-route-20261029/README.md) 的全部 42 个文件；前一轮为产生新证据的 progress。本轮不重跑其已封存实验或修改原件，不操作机身/USB/手机，不干扰另一 agent 的 HEVC/恢复工作。CP 原件 SHA-256 为 `c90d00d807874a5309dc1b65b203287e83608ceee513cc57b53409333fb6bcba`；VA = 文件偏移 + `0x108000`。

## 新确认的职责与调用关系

原 `0x4a032c` 的诊断调用在 `0x4a035c` 以 PC 相对寻址传入 `0x4a07ec`，原字符串是 `osal_dynamic_id`。相邻还有原 `free_dynamic_msgq_id` 及 UIPC 错误字串。结合其位图、稀疏上下文表和分配/释放分支，可确认这里处理软件动态 ID；它不是直接读取传感器像素的函数，也不能据此宣称找到了缓存芯片驱动。

原文件初始 ID 表：

| 表 VA | 基值 | 数量字段 | 位图指针 |
| --- | --- | --- | --- |
| `0xee5540` | `0x6000` | `0x2000` | `0x1921680` |
| `0xee5580` | `0x7000` | `0x1000` | `0x1921c80` |
| `0xee55c0` | `0x6000` | `0x1000` | `0x1921a80` |

本轮参数 `0x2a, 5` 选择最后一张表。这些是原文件初始字节和原分支结果，不是当前机身的锁/ID/位图读回；不扩展解释全部标志位含义。

原 `0xa87206` 初始化一个每块 64 字节的软件池；原 `0x49eaf8` 从中弹出块，原 `0xa87248` 按 ID 查找或创建上下文与三级索引。guest 声明 `0x53000000` 起 1024 字节 RAM，由原初始化代码构造 16 个空闲块，不直接返回伪造的分配地址。

原算法先检查位图最高空闲位，因此原代码产生的头两个输出是 `0x9005601f`、`0x9005601e`。第一个 ID 创建消耗 5 个 64 字节块，原计数为 1 个上下文和 3 个索引块；第二个额外消耗 2 块，索引块计数仍为 3。它们是软件 ID/队列上下文元数据，不是图像缓冲地址或 RAW 数据。

## 运行环境边界

严格用例执行原上下文查询前缀，在 `0x52c488` 的 `mrc p15, 0, ..., c0, c0, 5` 前停止，无上下文/临界区成功适配。Arm 的 [CMSIS MPIDR 说明](https://arm-software.github.io/CMSIS_5/Core_A/html/group__CMSIS__MPIDR.html) 与 [原维护者头文件](https://raw.githubusercontent.com/ARM-software/CMSIS_5/develop/CMSIS/Core_A/Include/cmsis_cp15.h) 支持这是 MPIDR 读取的识别；本轮没有读取该寄存器或提供其值。

其余用例明确保留：上下文查询返回 0、初始模拟 CPSR 的 IRQ mask 为 1，以及 `0x53fea0/0x53ffec` 临界区进入/退出返回 0。原 CPSR 查询、RAM 中的 `LDREX/STREX` 自旋锁及释放指令实际在 Unicorn 执行；临界区适配不构成真实调度器、SMP 竞争或锁状态证明。位图、索引表、计数器和 RAM 池初态同样是夹具。

没有钩子返回动态 ID、软件块地址、消息缓冲或图像服务结果。原算法的成功仅限上述已声明的 guest 资源条件。

## NRV 前缀的推进

context 1/5/7 的原 kind3 路径均继续通过原 `0x4056f4 → 0x44f004 → 0x44d710`。原 `osal_dynamic_id` 返回 0，并把 `0x9005601f` 写入原栈输出槽后，原包装器实际进入 `0x57b7be` 的消息容器构造与 `0x44f9c4`。

三组均停在原消息缓冲分配入口 `0x49f80c` 前，捕获参数：R0=`0x61003c`、R1=原输出槽指针、R2=`0xd8`、R3=0。这里的 `0xd8` 是 216 字节控制消息申请长度，不能当作图像帧尺寸；目标服务归属、完整报文、消息发送、服务回复和实际图像缓冲仍未证明。上轮正常 NRV 控制器创建和对象 ID 绑定因此仍未完成。
