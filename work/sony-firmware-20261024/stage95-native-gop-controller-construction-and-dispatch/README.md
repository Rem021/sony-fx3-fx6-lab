**原帧处理入口共享于三张虚表，但后续回调不同。现在用原构造函数安装虚表，原调用者实际进入了对应回调；没有在host中填写成功回调。** 基类回调只返回，不能据此判断数据交给编码器。两个派生候选分别进入不同的GOP公共控制处理路径，仍未证明哪一个属于目标MAIN实例。

14组场景、232个有界阶段通过。本轮最关键的限制也得到验证：原代码存在分配器锁回调绑定函数；执行它后，派生对象构造会进入原RTOS锁包装函数，当前无法完整执行。因此下面“完整构造返回”只适用于原映像回调仍为零的离线前置状态，**不是正常相机运行或完整启动证明**。

仅Mac；无Windows、UU、相机、驱动、权限或素材操作，无可刷包。16项要求及授权保持，目标未完成。

## 私有内存分配及构造

原`67d34`用声明RAM建立堆头并写GP堆指针。原`69ca0→69d84→699d8`完成私有分配，经原分割、链表更新和回收助手返回；没有向CPU注入分配地址或返回值。

- ring524原申请`524`字节，实际对齐块`530`；原构造建立私有记录及对象中的三个环形结构，完整返回。
- ringC4原申请`c4`字节，实际对齐块`d0`；原构造建立其私有记录，完整返回。
- 原构造保留的空隙仍为A5/C3旧值；整个堆、整个8192字节对象和完整栈均逐字节检查，不清空未知字段来通过。

**这些完整返回使用原文件中分配器回调尚为零的状态。** 它是明确的离线输入条件，不是假定相机正常运行时不需要锁。原`d530`把分配器两个回调原生绑定到`d4b8/d4d8`；执行这一绑定的4个对照中，原构造经原分配器的JALR到达`d4b8`，在执行该锁包装前停止。堆没有分配，私有指针和后续环形结构没有构造。

`d4b8/d4d8`静态分别调用原RTOS助手`5bbe8/5be88`，本轮未执行。代码区未找到对`d530`的直接JAL，数据区`2130f0`包含它的指针；该数据表在正常启动中的调用顺序与目标模式仍未验证。本轮只证明“执行原绑定后会进入锁路径”，不把它扩大为完整启动顺序或正确同步语义。

## 原帧调用如何到达各自回调

沿用上一轮同RAM中的原类型4/5池及原帧分配、地址转换、帧构造。对象的虚表由上面的原构造写入。

- 更新位关闭：原帧处理返回后，从尚未执行的`1441e4`继续，原JALR读取原vtable的slot38，并把对象、原栈描述符、RAW作为参数传入。分别核对三个参数、SP及真实RA。
- base：原空回调返回，停`1441fc`帧引用释放前。它没有处理帧，也没有设置有效录制返回状态。
- ring524：停`1465a4`，尚未读取未分类的RAW几何字段或调用图像助手。源RAW的`84`句柄仍声明为零，没有将缺失图像数据当作有效硬件输入继续执行。
- ringC4：原转发器进入owner函数，停`134e6c`第一个尚未建立的trace全局读取前。后续含trace计时MMIO及owner动态回调，本轮不执行、不修改全局标志来绕过。
- **更新位开启**：两个派生候选均停`131c20`新参数引用增加前，源参数引用仍1，未执行slot38分派。关闭更新的控制不能代替目标HEVC参数真正更新成功。

10组构造完成于前置状态，其中6组执行slot38（含2组基类空回调），4组开启更新而停引用边界；另4组原锁回调绑定对照停于RTOS锁包装。总14组232阶段。每阶段核对完整映像，只允许原代码写注册表、堆头及两个堆回调共4个运行时全局字；磁盘原固件未改。所有数据区、64KiB栈、只读旧帧页及返回陷阱均检查，无MMIO、指令替换、逐次内存读写钩子或假返回。
