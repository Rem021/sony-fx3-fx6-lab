# FX3 DGU 参数解释与串口相关硬件边界（2026-10-29）

**本轮仍未取得可正常刷入 FX3 的 FX5／VENICE 修改固件。** 新确认了三段原 MIS 的指令记录格式和分派关系，整理出5,654条连续合法格式记录；原 DGU 解释器的六组有界执行明确区分了缺失的相邻 NOR 字节与后续硬件写入边界。找到 DDR／Nanya 参数线索，但没有证明真实芯片、帧缓存能力、DDR 初始化、RAW 读取或完整 ISP。

开始及封存前核验外盘 UUID `F9404A58-A1C4-409F-8E78-9A6B7EEB3F7B`，沿用非 Git Mac 项目根。独立回读[上一阶段](../boot-info-source-20261029/README.md)23个封存文件；保留原固件、旧实验、另一 agent 的文件和设备状态。上一轮确立了 EXBL 缺口和 MIS 原读取格式，属于具体进展，本轮不重复将单独函数识别等同于真实启动。

## 原参数记录格式

输入仍为官方7.02 p8 的原 DGU／MIS，其 SHA 分别为：

- DGU：`39eeb6d572a060149194463507800ed66b866a20dceb8ed49b01a04eb6fb2ba7`，24,336字节。
- MIS：`4cd3e9bc3a0a4aec4793bff77e7ca4dccdba8637212cd632cdc5ecbe550daf98`，119,296字节。

原 DGU `0xfe045504` 一段从参数游标读取16位原 flags、8位 word count、8位 opcode；word count 合法范围1至21，整条记录占 `word_count*4` 字节。非注释载荷逐32位复制，注释 opcode `0x25` 逐字节复制。原代码将四字节头重排为 `[opcode, word_count, flags_u16]`，再分派处理；原 flags 会被拆成多组控制位，不能当作行号或标签。

三个独立参数块的首记录偏移是各自起点加 `0x100`。按原格式，限定在下一块起点／文件末尾以内作连续解析：

| 原块偏移 | 首记录 | 连续合法格式记录数 | 首个停止偏移 |
| --- | --- | ---: | --- |
| `0xa00` | `0xb00` | 2,337 | `0xba48` |
| `0xc200` | `0xc300` | 1,464 | `0x123a4` |
| `0x13200` | `0x13300` | 1,853 | `0x1bb6c` |

三处停止点的前四字节均为零，word count 不合法，宿主扫描即停。**这是连续记录格式清单，不是5,654条已经执行的命令，也不证明停止后的字节全是填充。** 跳转、子程序及完整解释器语义尚未恢复。实际出现的18种 opcode 均与原分派表逐项对应；记录了原表项地址、16字节原数据和处理函数地址。

第一段注释涉及 DDR 复位、CKE、MCLK；第二段有 Nanya 相关的 ODT 参数注释。这能定位原内存初始化配置内容，不能据此认定机身实装 Nanya、实际容量、时序兼容性或运行时选中了该参数分支。

## 三组严格来源输入，再加三组原 NOR 上下文

没有执行 DGU 的缓存维护包装入口。只在隔离 Unicorn RAM 中，分别以原模式参数 `0x10` 和三段原参数地址直接调用已静态解析的 DGU 主体 `0xfe04536c`。原 BSS 起初未知，只有原指令写过的字节才能读取；没有提供硬件或函数成功返回。

第一组三例仅读入 DGU／MIS 原字节，均在诊断辅助路径 `0xfe04472c` 读取未知 `0xfe05fe48` 时停止，原指令进入计数分别为1,120／750／750。第一段已分派原注释记录，后两段已分派 opcode `0x10`。

静态检查说明这不是服务回调表：原代码把该地址的64位数与一个 magic 比较。该地址位于已保存原 NOR 文件范围内，因此第二组三例明确补入完整原 NOR 字节作为**只读 RAM 数据**；没有运行 NOR 代码，也没有补出 EXBL 信息块。原 NOR 在该处的数值不匹配 magic，原分支自然继续。

| 原参数块 | 第二组原分派顺序 | 原指令进入计数 | 停止点 |
| --- | --- | ---: | --- |
| `0xa00` | `0x25 → 0x10 → 0x11` | 2,302 | `0xfe045918`，将写 `0xf1020024` |
| `0xc200` | `0x10 → 0x11` | 1,352 | 同上 |
| `0x13200` | `0x10 → 0x11` | 1,352 | 同上 |

三例都停在写入之前，原将写的32位值为1；没有映射或回复该寄存器。进入计数包含最后被内存守卫截停的指令，不表示该次读写已完成。停止时的寄存器值只是快照，未当作函数返回结果。所有已发生写入只限声明的 guest RAM／栈，不是物理内存写入。

原 `0x11 → 0xfe042654 → 0xfe0452d4 → 0xfe0458a4` 先选择输出端口，后续原访问范围涉及 `0xf1000000 + port*0x1000`。另一个原输出叶函数轮询该范围的 `+0x18`，随后写首地址。对照已固定 SHA 的[FX3 Ver.7.00 官方 GPL 来源](https://oss.sony.net/Products/Linux/B2B/ILME-FX3_Ver700.html)，其 `cxd90057.dtsi` 将这五个范围列为 PL011 UART。这支持将本轮边界称作**串口相关初始化**；首个 `0xf1020024` 寄存器的具体名称没有在本轮独立确定。

这一步还没进入后面的 DDR 操作，更没有得到 DMM 帧缓存、CMOS RAW 或颜色处理数据。没有用关闭输出、伪造串口就绪、修改原参数或替换返回值来绕过该边界。

## 来源查找修正与适用范围

采集脚本最初假设 p3 中有独立 `/cxd90057.dtb`，实际目录不存在该文件，抛出 `StopIteration`。原脚本、已完成的记录清单和失败说明均保存于 `attempts/`；修正后保留原清单逐字节一致。

随后独立列出原 p3 FAT 目录，并在原 `vmlinux.bin` 全字节中搜索明文 FDT magic，结果为0。这个限定搜索不能证明所有固件或机身中没有 DTB。最终只用此前封存的 Ver.7.00 GPL 源码作型号参照，已核对其 SHA 与来源回执；**不称作当前7.02 DTB、实际启用节点或实机测量。** 未运行旧阶段的顶层写入脚本。

## 完整移植仍缺什么

当前这些证据把原 DDR 参数层与串口前置条件定位得更具体。后续需核对参数中的读写操作如何连接 CP 的内存区域和 DMM 分配；实际初始化、数据到达、真实容量与运行时选择仍需各自证据。不能把原 DDR 参数直接当成跨型号可用的芯片驱动或色彩科学。

本轮复查的 [FX5 官方开源页](https://oss.sony.net/Products/Linux/B2B/ILME-FX5.html)仍提供开源组件；本轮未取得完整私有 ISP／专业菜单包。[VENICE 2 官方更新页](https://www.sony.jp/ls-camera/update/VENICE_2.html)仍列 V5.00，并把 Signature 描述为监看预设外观；本轮未获得新的完整 ISP 解码或 FX3 准入方法。
