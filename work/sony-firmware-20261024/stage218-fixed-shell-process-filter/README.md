# FX3 固定shell子进程过滤候选

2026-10-30；经典ILME-FX3 7.02；仅Mac离线分析、编译和自建ARM64／假内核测试，无相机操作。

**已从FX3原码重新绑定第一层子进程，并在显式读取入口前加入进程过滤。最终11项检查、63个夹具案例通过。** 这修补了上一版“显式导出可直接调用读取器”的限制；它还不是可信调用授权、跨进程排他或真实装载／恢复证明。

## 原厂先exec shell，不是直接exec date

原`libJiritsu.so`的`CShellExecute::ExecShellNew`构造的argv为三个字符串加空指针：

```text
argv[0] = /bin/sh
argv[1] = -c
argv[2] = /bin/date -s 070421422017.26
argv[3] = NULL
```

这是待核对的数据，不是本轮执行命令。原码先fork，再execv `/bin/sh`；日期程序由该shell继续处理。原root镜像中的`/bin/sh`和`/bin/date`均指向BusyBox。只过滤直接date进程会错过第一层动态装载。

本轮对应了6份原始范围和17项原指令字／地址／调用检查；kernel cmdline的候选编码为三个NUL分隔字符串，含最后NUL共40字节。[原码证明](shell-profile-proof.json)绑定原件SHA、参数数组的具体存储和execv实参，没有执行Sony指令或原程序。

## 读取入口前检查什么

[boot_module.c](boot_module.c)的构造函数仍只写自己的64位内存标记，不读取、退出或自动分派。显式`fx3_boot_read_window`先一次性占用入口，再依次检查：

1. 初始化已经完成；真实／有效UID均为0，PID／父PID范围合法，当前TID等于PID。
2. `/proc/self/cmdline`为procfs中的root普通文件，只读打开并严格匹配上述40字节、EOF及前后元数据。
3. 通过`/proc/self/exe`内核magic link打开执行文件的后备文件，核对root、普通文件、非组／其它用户可写、单链接、精确长度及SHA。
4. 以getppid结果构造`/proc/<数字>/exe`，对参考im.elf做同样核对；再复查PID、TID、父PID和UID，并重新打开自身／父执行文件核对元数据，拒绝已观察到的身份或exec变化。
5. 以上均通过后，才调用原启动区工作器，继续原请求、环境文件指纹、容量和单次读取检查。

两个exe路径有意跟随内核magic link；不会把跟随任意用户文件链接作为回退。[Linux proc exe说明](https://man7.org/linux/man-pages/man5/proc_pid_exe.5.html)提供语义背景，当前Sony内核行为仍未实测。

| 参考文件 | 长度 | SHA-256 |
|---|---:|---|
| BusyBox | 423000 | `c3297a7086efe9a001c39fa98d74d125992cf3225cf353ab6ff2238d827c7799` |
| im.elf | 40920 | `5171f576d8b76cfbf15581389183b390c445bd6ff9dd97fd6668c5f64e77dc91` |

两者从已保存的官方镜像重新提取并校验，仅作为普通数据读入测试；**父进程为该im.elf是候选的严格参考条件，不是当前相机的实际观察。** 配置不符就拒绝，没有通用或宽松型号回退。[原件来源](executable-source-capture.json)

内层工作器由0.5固定源码只替换一个入口声明而成：改成私有static函数，其它源字节保持。动态符号表只有受过滤的公开入口和状态查询，不能用dlsym取得旧的无过滤内层入口。[单范围派生记录](inner-derivation.json)

## 验证结果

[最终测试回执](runs-final-v2/receipt/results.json)包含11项测试、63个夹具案例：

- 两个装载基址下，声明的正确shell／BusyBox／父im配置通过过滤，各读取2块合成boot0并由既有解码器完整核对。初始化与状态查询不发系统调用。
- 主应用、其它shell选项、直接date、额外参数、缺NUL、额外换行或不同日期均在过滤阶段拒绝，不进入RAM请求、kmod指纹或`/dev`启动区阶段。
- 非root、非主线程、异常PID／父PID、procfs不符、执行文件大小／SHA／元数据／链接数异常及重新打开后身份变化均拒绝。
- 短读、读取错误、关闭失败、时钟倒退／超期、UID／PID／父PID变化，均不补读、不自动重试或退出进程。被阻塞的自建读取只由测试协作释放，迟到结果拒绝，下游保持未打开。
- 原工作器的指纹／更新标记／迟到／清单关闭失败仍返回非0；保存清单不覆盖失败返回。
- 初始化前调用返回47且无syscall；失败后再初始化也不解除已消耗的一次性入口。重复入口返回40，不新增调用。
- 无过滤内层函数没有动态导出；两次交叉构建得到相同字节。

当前候选仍为262,936字节ET_DYN，136处代码字段链接处理、1处初始化指针相对重定位，SHA为`6d78dcc3610b229e1b67eb6378af67a071c58ce1686021f6c3be33d7ef6d31af`。[最终构建](runs-final-v2/built/build.json)

运行的只有我们自己的ARM64机器码。身份、PID、proc、文件元数据、时钟、Linux syscall和tmpfs都为夹具；BusyBox／im／模块原件只参与数据哈希，没有运行Sony代码、Linux内核、真实glibc或Sony装载器。

首轮短读夹具把256字节请求减成255字节，未真正截断40字节输入，故预期拒绝断言失败；另纠正了直接date测试中的NUL转义。修正后10项通过，再加入初始化前拒绝检查，最终11项通过。初轮、10项版本和最终版本分别保留，不把无效注入计为保护证明。0.4／0.5正式源码包及源文件不变，未将旧58项或上一轮8项重计。

## 为什么还不能上机触发

[proc cmdline文档](https://man7.org/linux/man-pages/man5/proc_pid_cmdline.5.html)明确说明参数内存可由进程改动；exe后备文件SHA也不证明所有已映射代码或加载库的身份。本过滤器用于减少错误进程分派，不能认证调用者、独占请求、同机来源或管理员批准。

入口一次性状态只覆盖本模块实例，尚无跨进程的不可复用请求claim、可信nonce／PID绑定和完成回执。本轮没有把匹配结果当成授权，也没有自动触发读取或退出。**当前模块尚未自动拦截日期命令；直接采用原触发链仍可能改变时钟。** 原fork失败可退出调用进程、无超时wait等问题仍未修复。

启动区读取原有的硬件访问选择变化／panic、真实数据视图、归还和逆写缺口仍在。源码／夹具通过不充真机备份、独立AP救援、首刷或真实HEVC主录／长录验收。全部16项要求与既有授权保持，195仅主机root01仍未具体批准、未启动、未重问。

下一步补每次请求与实际启动者、PID／程序的绑定，以及跨进程一次性claim和可信完成回执；先保持不访问源分区的离线验证。真实Sony装载／退出、同机完整备份、独立恢复和冷启动仍需相应证据及具体授权。目标保持active，未放行持久写入。
