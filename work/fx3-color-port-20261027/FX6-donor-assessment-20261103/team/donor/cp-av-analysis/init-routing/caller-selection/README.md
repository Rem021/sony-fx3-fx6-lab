# FX6 AV 原 DMA 构造调用者与 look 选择：有界离线证据

2026-11-03。**已定位原 `0x2a7978` 构造器的 5 处直接调用、look 路径的事件字段及全局覆盖条件，并把一个人工 look 22 输入追到构造器调用边界。** 原字节还表明两个选择输入来自运行态 provider 回调，因此 **MAIN / monitor 分流语义仍未闭合**。本轮没有执行 DMA 构造器之后的提交路径，也没有 CP、VM、设备或像素域证据。

## 原件、映射与证据级别

- 唯一原件是只读 FX6 6.01 `fat-files/nflasha3/av-cam.bin`，12,939,512 B，SHA256 `56684d830eab1e304868548746d8275188a925f9e4ab9354560180c31b4a93cf`。镜像 `0x0` 的指针 `0xffffffc001000058` 和 `0x8` 的 `ORIL` 支持独立 `VA = 0xffffffc001000000 + 文件偏移`；本文裸 `0x...` 地址均为该 AV **文件偏移**，完整 VA 可由此式复算。`static-evidence.json` 给每段原字节 SHA、逐指令 VA/偏移/机器码。
- 本轮的两种证据分别为**静态原字节解码**（`analyze.py`）与**隔离 CPU guest**（`replay_caller.py`）；后者只执行原分派和查表，到 `BL 0x2a7978` 指令前停止。既有 FX6 `init-routing/dma-trace.json` 在显式映射/flush 桩下构造 70 项，属于前一阶段，不能合并称相机 DMA。
- 只读复核旧 FX3 `initializer-guest-results.json` SHA256 `29c76396ae58e8caca2bd96e0eb0408854c163e60556b5d27b4da9d6bd76ab95` 与 `look-consumer-guest-results.json` SHA256 `6443be58aaa2a547aa7488a7551452ab4ce995bc108e8cb9244f7892b7b84a4f`。这是固定的旧 CPU 回执，**本轮没有重跑 FX3**，也没有从它推断 FX6 的 MAIN 选择。

## 调用与条件表

`analyze.py` 在对齐的 `[0, 0x370000)` AArch64 窗口逐字解码直接 `B/BL`，并在全文件查找构造器精确 64 位 VA、在代码窗口查找简单 `ADR`/相邻 `ADRP+ADD` 取址；这些取址搜索为零。零结果只限该搜索形式，**不排除其它间接动态引用**。5 处直接 `BL` 均在原事件分派的分支内：

| 事件 `+0` | 原调用指令 | 本地参数来源与条件 | 此轮证明范围 |
|---:|---:|---|---|
| 0 | `0x2a74e4` | `0x2a7458` 由事件 `+4` 或全局标志选 look；原 `0x2a650c` 查表，事件 `+8` 成为 `arg+0`；查得的计数和描述符成为 `arg+4/+8` | 静态数据流与 3 个正例 CPU 到调用前；仅人工事件 fixture |
| 1 | `0x2a75ac` | `0x2a7fe8` 由事件 `+8/+0x20/+0x28` 形成栈参数 | 仅静态直接调用及局部取值，未回放 |
| 2 | `0x2a7600` | `0x2a80d0` 由事件 `+8/+0x2c` 形成栈参数 | 仅静态直接调用及局部取值，未回放 |
| 3 | `0x2a7690` | `0x2a7620` 由事件 `+8/+0x20/+0x28` 与局部描述符形成栈参数 | 仅静态直接调用及局部取值，未回放 |
| 4 | `0x2a7748` | `0x2a76b0` 的 `0x2a8154` 返回 0 后才走到构造器 | 仅静态条件与直接调用，未回放 |

第 5 类事件进入 `0x2a7768`，在这 5 处直接调用清单中没有一处归于它。事件分派入口 `0x2a7374` 唯一直接 `BL` 是 `0x2a731c`；其 `x0` 来自 `[sp+8]`，而 `0x2a72cc` 把 `sp+8` 交给 `0x2ede0`。这个原 thunk 读取镜像头 `+0x20` 的 provider 表指针，再取表 `+0x3c0` 并 `br x3`。**事件对象的真实内容和 provider 实现不在固定 AV 字节内。** 六项跳转表位于 `0x370198`，SHA256 `58ad0a3be3dea4e272caa3b8233f9d3238dd83ff4e36b5ae7c54c57de2a90031`。

## look 22 到构造器参数的逐点数据流

| 原指令 | 原字节可确定的动作 | 运行态/寄存器边界 |
|---|---|---|
| `0x29b2a4` → `0x2efd4` | 以 `w0=0x2ae0000, x1=sp+0xc, w2=4` 调用头 `+0x20` 指向的 provider 表 `+0x4c0` | 返回值及写出的 4 字节 word 未观测；这是覆盖标志的首个外部输入 |
| `0x29b2b0–0x29b2fc` | 返回值 `>0` 时，word 低四位等于 1 使 `0xb45884` 标志为 1；高半字节映射为 `0xbb0bfc` 模式 0、2 或 3；返回值 `<=0` 时只清标志 | 文件快照的标志 0、模式 2 不等于相机运行态；不能给标志命名 MAIN/monitor |
| `0x2a73b0–0x2a73c8` | 事件 `+0` 作为 0–5 跳转索引；0 进入 `0x2a7458` | 事件来自另一 provider 表 `+0x3c0`，自然类型未观测 |
| `0x2a7468–0x2a748c` | 事件 `+8` 写到栈 `+0x20`；`0x29b308` 读取标志，低位为 1 时 `w20=31`，否则 `w20=[事件+4]`；`0x2a650c` 用 `w20` 查表 | `0x2a650c` 自己保存/恢复 x19、x20、x21 与 SP；`0x29b308` 只改 x8/w0；CPU fixture 在调用前后核对这些寄存器不变 |
| `0x2a7490–0x2a74e4` | 从查表输出 `[sp+0x10]` 取计数、`[sp+8]` 取首描述符，复制至 `sp+0x24/+0x28`；令 `x0=sp+0x20, x1=0xffffffc001b533d8` 后 `BL 0x2a7978` | `0x29b328` 的模式读取与可能的 `0x2a65f8` 日志介于其间；CPU 正例把客体模式 2→3 以绕开日志，并未证明自然路径的所有副作用 |
| `0x2a7994–0x2a79b0` | 构造器读 `arg+0` 传给原 `0x297460`，读 `arg+4` 为项数、`arg+8` 为首描述符 | 原 `0x297460` 对数值 0 返回寄存器基址低 32 位 `0xf3019000`，其它数值返回 0；**数值 0 的 MAIN 语义没有证明** |

固定表 look 22 项位于 `0x370098`，原记录 key 22、描述符 `0xaa2ca0`、数量 70，32 B SHA256 `411e7b6ac81ddc43f4a23eccaad3cbff8d18dfef14078b0f2235670e87a4b693`。标志置位会强制索引 31，查另表 `0xb81ae8` 的首项为 84 个描述符、首指针 `0xa822b8`。这证明**选择条件与数据源**，不能把索引 31 或 ip 0/1 擅自映射成 monitor/MAIN。

## 五个有界 CPU 用例及负例

`caller-replay.json` 记录每例全部执行 PC、写事件、寄存器快照、预算和客体补丁。共同约束：原字节入口 `0x2a7374`，只准 PC 在分派、原 flag 读取、原 look 查表函数内，预算 1,000 条，写入只准客体栈；从未运行 `0x2a7978` 指令、后续 `0x2a7ba4` 或外部 provider。每例事件对象在独立客体 RAM，栈上下 16 B 哨兵和事件 12 B 保持。四例把**仅客体 RAM** 模式字 `0xbb0bfc` 从原文件的 2 改为 3，使日志路径跳过；一例另把 flag `0xb45884` 从 0 改为 1。无代码补丁、无 stub、磁盘原件未改。

| 用例 | 执行到的停止 PC | 构造器入口前实际参数 | 结论 |
|---|---:|---|---|
| 事件 type 0、look 22、ip 0、flag 0、mode 3 | `0x2a74e4`；219 条 | `{0,70,0xffffffc001aa2ca0}` | 人工 fixture 与前一阶段 70 项输入一致，**不是自然选择** |
| 同上，仅 ip 1 | `0x2a74e4`；219 条 | `{1,70,0xffffffc001aa2ca0}` | ip 独立来自事件 `+8`，查表不改它 |
| 同上，仅 flag 1 | `0x2a74e4`；79 条 | `{0,84,0xffffffc001a822b8}` | 覆盖分支生效，不再选择 look 22 |
| 事件 type 1 | `0x2a7574`；18 条 | 未进入 look 22 构造边 | 分派负例 |
| 原文件 mode 2，不补丁 | `0x2a65f8`；21 条 | 在日志调用处截断 | 明确不把模式 3 测试冒充自然完整调用 |

前两个正例在 flag getter 前后对 x19/x20/x21/SP、look lookup 前后对同四寄存器做逐值相等检查；在构造器调用前记录 `x19=事件指针`、`x20=22`、`x21=0xffffffc001b533d8`。从而仅对已执行的有界路径排除这些寄存器被 helper 意外改写；未执行的 provider、日志、硬件链仍未知。

## 工程结论与最小缺失观测

**可复用的供体证据**：FX6 自身映射、原 look 记录与条件查表、152 B 描述符初始化（前一阶段）、70 项 DMA 描述构造的 CPU 格式（前一阶段）、以及本轮闭合的事件字段→look/构造器参数路线。这些可作为 FX3 对应消费者的字段级比较输入。

**不能据此移植或宣称完成的部分**：不能把人工 `look=22, ip=0` 视为 FX6 自然 MAIN 视频选择；不能把标志值 1 称 monitor，或把 register base `0xf3019000` 的存在称像素链打通；不能把前一阶段带桩的 70 项链表称 DMA 提交、CP 运行、RAW/ISP 算法或实机输出。29 组 Vintage 表变化也只限定于这些表，不能概括 FX6 视频色彩全部差异。

本阶段收束在两处精确运行态边界：`0x29b2a4`→provider `+0x4c0` 的返回值与 4 B word，和 `0x2a72d0`→provider `+0x3c0` 的事件指针及该对象 `+0/+4/+8/+0x10`。下一最小观测需在**另行授权的实际运行证据**中绑定这两个返回及事件字段与真实 MAIN/monitor 输出路径；本轮固定 AV 字节无法给出该对应关系。不继续扩散 RAW/ISP、VM 或设备操作。

## 复现

在本目录运行 `sh prepare.sh`，再运行 `PYTHONPATH=.vendor python3 analyze.py`、`PYTHONPATH=.vendor python3 replay_caller.py`、`python3 verify.py`。`prepare.sh` 只在本子目录暂装 Capstone 5.0.6 和 Unicorn 2.1.4；运行结束已移除临时依赖，重现时可重装。`run-receipt.json` 对原 AV、两个新回执、脚本及只读 FX3 旧回执重新哈希并记录 `PASS`。
