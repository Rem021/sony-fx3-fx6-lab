# FX3 请求绑定与不可复用窗口候选

2026-10-30；经典 ILME-FX3 7.02；Mac 离线候选，未连接、查询或操作相机。

**在第218轮进程过滤后接入了请求绑定与同 nonce／同采集窗口的跨进程防重复执行。最终11项测试、50组自建ARM64案例及2个普通Mac子进程通过；另用同一最终二进制确认了不同任务仍可重叠的缺口。** 该缺口保持未解决，不作为安全刷入放行。

## 本轮实现

[handoff.py](handoff.py)生成256字节关联数据：采集ID、随机nonce、调用方提供的计划摘要、128字节读取请求的SHA、目标PID／父PID、启动区与窗口、总容量以及目标CLOCK_MONOTONIC创建与到期时刻。固定字段、保留字节与CRC也校验。该工具只生成本地普通文件，不采集目标时钟或进程信息。

[handoff_impl.inc](handoff_impl.inc)在显式入口检查root属主、0600、单链接、tmpfs、精确长度／EOF与读取前后元数据；再绑定PID／父PID、整个请求、采集／窗口和期限。在内层工作器重新打开请求后，逐字节核对已绑定的128字节副本，阻止关联检查之后的请求替换。到期检查覆盖申请之后、源设备打开前、读取期限及报告正常返回前；迟到清单不能覆盖非0结果。

第218轮的首层shell过滤与参考BusyBox／父im文件SHA检查保留；构造函数仍只设置内存标记，不自动读取、分派或退出。**真实父im身份仍是未实测的严格参考条件；进程参数与后备文件SHA不认证所有已映射代码。**

原0.5读取组件的内层私有候选仅作4处有记录的源转换：私有入口与绑定参数、整请求比较、源打开前期限检查、读取截止时间取较早者。[派生记录](inner-derivation.json)保留顺序与每处原字节，其余字节不变。正式0.4／0.5包和23份源码未改。

## 两份占用记录必须先同时留位

候选在root 0700的tmpfs子目录用`O_CREAT|O_EXCL`建立两种不可复用名称：

```text
nonce-<32字节随机值>.pending
capture-<16字节采集ID>-b<0或1>-w<0至3>.pending
```

先独占创建两份文件，再写内容与同步。部分写入、同步或关闭失败均不删记录；即使文件为空或内容不完整，名称也继续阻止同一窗口。正常读取之后同样不删除、不标记为可信完成、不自动释放。模型中的完整4窗口采集使用不同窗口与nonce，仍能完成。

本轮审查发现初版“先写nonce再建立窗口记录”在部分写失败时留下绕过机会，已修正上述顺序，并追加换nonce重试检查。修正前的初次10项与11项结果、源快照和旧缺口复现全部保留；本轮验收只认[runs-final-v2](runs-final-v2/receipt/results.json)。

[Linux open接口说明](https://man7.org/linux/man-pages/man2/open.2.html)支持这里对创建既有名称失败与链接处理的理解；不据此宣称所有网络文件系统安全，也不把Mac普通文件测试当作Sony tmpfs实测。记录只在RAM生命周期内保留，不能证明断电或重启后防重复。

## 最终验证

- 11项测试，50组自建ARM64／假Linux调用案例，两个相同构建的SHA一致。
- 最大容量33,423,360字节合成boot1，4窗口分别读取128／128／128／126块；既有独立解码与组装器还原全部字节，SHA为`0bf7d4c932dc8a583aa5101bad7c8e7a8d6191c15c54479847c83b62434cc625`。
- 同窗口换PID与nonce、同nonce换采集ID、关联字段冲突、过期／未来时刻、文件权限／元数据异常以及请求替换均在相关拒绝分支停止。nonce和计划摘要改成另一非零值可以通过，测试明确保留这一事实：它们是关联字段，不是可信秘密或授权。
- 记录短写／同步／关闭失败后，同nonce和新nonce均被拒绝，源未打开。申请后到期不打开源；清单写完才到期返回非0，独立解码器拒绝按成功接收。
- 同窗口竞争在两个自建ARM64实例中只有一个读取。另两个真实普通Mac子进程共享同一普通文件占用目录：一个返回0、读2块合成数据，另一个返回51、读0块。实际Mac PID作为模型PID输入；root、proc、Linux内核与tmpfs仍是夹具，不是目标机证据。

最终模块262,936字节，166处代码链接处理、1处初始化指针相对重定位，SHA为`be0805584b07e116d26da2ee8036a67cbd9c65801efdaedab47e995f33e3030d`。[构建回执](runs-final-v2/built/build.json)

## 明确未解决：不同任务可以重叠

[最终构建的并发反例](live-gap-current-v2/receipt/gap.json)：第一个自建读取仍阻塞、尚未返回时，使用不同采集ID和nonce的第二个任务成功读取2块。协作释放第一个自建阻塞后，它返回23；没有强杀、复位或自动重试。`readiness_pass=false`。

这证明当前占用只能防同nonce／同窗口重放，**尚未实现所有任务共同使用的全局在途排他**。不能仅用另一项顺序测试或“进程不见了”推断安全解除。下一步离线设计全局占用与完成协议：不同任务争用同一资源；阻塞、超时、进程死亡及不可信完成均保留UNKNOWN；同时保留完整多窗口采集能力，不用永久只允许第一窗口来回避问题。

## 证据边界与目标

没有Sony程序、真实Linux／glibc／Sony装载器执行，没有相机、USB、缓存设备查询、管理员或驱动操作。所有源分区路径由假内核映射为本地合成文件；相机原件只作普通数据哈希。上述PID／nonce／计划摘要、CRC或SHA都不能替代可信启动者、同机来源或用户授权。目标时钟是调用方提供的关联数据；[CLOCK_MONOTONIC说明](https://man7.org/linux/man-pages/man2/clock_gettime.2.html)也不意味着Mac时钟可以直接套用到相机。

实际Sony装载、受控启动／退出、可信完成、同机完整备份、启动区数据视图／访问归还、独立AP救砖、逆写与冷启动仍未验证。既有全部16项要求和MAIN 1080p29.97 HEVC／长录验收不变；exact30单列。195仅主机root01仍未具体批准、未启动，本轮不重问、不扩大设备权限。目标保持active，未放行持久刷写。
