# FX3 编码资源描述符与原枚举名称

目标参数在原固件的**独立代码片段**中形成1920×1080、`HEVC_MP4`、`29_97`、`PROGRESSIVE`、`CHROMA_420`、`BIT_DEPTH_10`描述符。匹配代理参数形成`XAVC_PROXY_HEVC`，两份描述符只有流类型字节不同。原发送前缀还可把描述符复制进CID0x2103、MID0x0100、长度0x90的消息包。

**没有运行完整描述符构建器、消息发送、资源接收端或硬件。** 构建途中有尚未解析的运行时清零调用和原诊断调用；本轮分别停在入口，后续从明确写出前提的独立片段继续。质量22在这一层转为枚举4，原名称`FH`，还不能据此确认HEVC主录16Mbps或支持整组参数。实机录制、同机健康备份与救援仍未验收，持久写入不放行。

## 质量与帧率的剩余问题

原0x134fcc将上游quality22转为资源质量4，原0x27dd64返回名称`FH`。描述符中没有直接写入16000这个码率值。此前上游16Mbps换算的证据保留，但不能跨越这一层推断实际HEVC_MP4码率；需要追对应资源接收端如何处理`HEVC_MP4 + FH + HD + 29_97`，包括拒绝、默认、重新映射和实际参数集/码流。

描述符+0x1c被原诊断称为input_frame_rate，本轮值为0，来源是上游事件+d0/原视频包+0x86，而不是timing的名义30。正常模式下这个字段如何解释还未追完；不能把0解释成实际0fps，也不能用名义30补写这个字段。

Sony公开规格仍仅为能力基线：经典FX3代理设置有1920×1080、HEVC/H.265、4:2:0 10-bit、16/9Mbps，代理与电影同时录制。它没有证明本轮MAIN组合或恢复能力。2026-10-25已重新读取[官方代理设置](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000882045.html)。

## 原始入口与两个明确断点

上阶段timing动作0x194de8生成0xd4事件。输入组件0x1454f4继续到父组件0x134568，但父组件先调用输出接口0x14f96c，其运行时状态尚未闭合。本轮直接为描述符所有者0x1349d0建立有限字段fixture，未冒充完整输入组件初始化。

1. **原构建入口→清零调用之前。** 执行0x1349d0，原memcpy复制0x98视频包，保存外层格式和局部mode。原调用提出清零栈上0x88字节的参数，在0x2f67c入口停止。该入口经映像头+0x20、API表+0x6b8间接跳转；运行时函数身份未建立，本轮不提供替身。
2. **独立的清零后前提→诊断之前。** 将0x88字节全零作为新片段的显式栈输入，从0x134a1c执行。原转换器写IP、流类型、帧率、扫描等字段。raw-mode帮助函数0x134ec0计算出保存在W20的0，随后在0x134f70的首个诊断调用之前停止。
3. **独立的诊断后前提→描述符转储之前。** 从原帮助函数尾部0x134fb0执行，使用原保存栈帧和已计算的W20，然后运行调用者剩余写入。这一片段假定未执行的诊断已完成且没有改变保存状态、栈帧或描述符；该前提未通过执行诊断证明，不能把三段合称连续构建器。最终在0x135400原转储入口停止。
4. **独立的发送前缀。** 把得到的0x88描述符作为新客体输入，运行0x135df8头部常数与原memcpy，形成0x90包。在0x0960a4消息对象构造器之前停止；未序列化、设置源/目的地、发送或处理回复。

没有PC←LR、伪造成功返回或运行时输出适配器。跨断点前提是实验输入条件，不能消除原生依赖，也不能证明这些依赖没有副作用。

## 对照与先前结论的收紧

6个描述符场景包括目标MAIN、匹配代理、UHD控制，以及单独修改codec/chroma/depth为0xff。前四个在明确前提下形成完整0x88描述符；色度和位深非法对照分别停在原转换器0x135338和0x1353a8发起的诊断入口，未执行完整错误处理。

6个原流类型转换对照表明：外层格式15固定转14，外层18固定转21；在这两支中，内层codec参数为0、15或0xff结果相同。因此，先前“非法codec仍前进”的观察应理解为该字段在这些分支不参与流类型选择，**不能用来断定缺少某项必需校验**，也不是非法格式被硬件接受。旧阶段和原观察不改写。

另执行10个原纯名称转换。正式结果共44个边界片段/转换执行：6场景各1个上游timing动作及3个描述符片段、4个独立发送前缀、6个流类型转换、10个名称转换。所有原写入仅限客体栈和fixture区。
