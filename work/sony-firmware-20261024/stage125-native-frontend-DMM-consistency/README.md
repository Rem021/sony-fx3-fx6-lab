# FX3 候选前端与原 DMM 模式选择对照

2026-10-27，仅 Mac 的 Unicorn 客体。**16组声明输入的前后对照均保持原 DMM 模式一致。** 本轮重用阶段117已编译前端，实际执行原445字节参数复制和原 GetDmmModeId；共192个有界片段通过。它补充了候选参数与内存模式选择的一致性证据，**不是实际内存分配、硬件主录或安全刷写验收**。

## 本轮确实接通的部分

输入来自阶段117已封存的有界应用调用者结果，覆盖 proxy_disabled、HEVC16、HEVC9、AVC6 四种声明组合及两种旧值填充。前端仍使用原阶段117对象，在人工门控下把 MAIN 类型5改为6，保留质量6、帧率3和其它参数字节。

原 MPR `ccb04..ccb14` 将445字节值复制至声明 MovieRecInfo `+0x58`，随后原 GetDmmModeId 在独立日志间隙之间执行。原函数读取代理标志、质量及若干控制字段，没有读取本轮改变的 MAIN 类型字段。每个前后模型只有 `+0x1c8` 的一个字节不同。

四种组合×两种填充值×两个首字条件，共16组配对。Model 首字的完整业务来源未绑定，不将1/2直接命名为实机介质或通道数。原调用者更早的其它初始化和后续模型/元数据工作仍有缺口；这些组合也不是自然菜单可达性或当前相机配置的证明。

模式一致只说明这一步选择没有因类型5→6而改变。真实物理缓冲区大小、地址、所有权、分配成功、编码器资源和16Mbps参数消费仍需独立验证；不能把相同模式当作充分支持。

## 选择表与释放返回值

原 UnitTypeTableSelect 对所观察的有效模式返回原 ELF 表指针；原 FreeDmmMemory(mode,7) 进入该表后，按原代码准备 RemoveAreaExtList 实参，在真正移除前停止。没有执行任何区域移除或 DMM 释放。

另外，完整纯分支对模式39返回1、对模式−1返回0，二者都没有进入区域移除。它们是人工范围控制，模式39不是候选所选模式。该结果说明释放函数返回1可以来自无移除的范围分支，不能一概把布尔真当作内存已释放；没有据此推断真实调用者会传错模式或 Sony 存在泄漏。
