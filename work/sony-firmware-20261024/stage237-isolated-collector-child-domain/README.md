# FX3 隔离监管进程与封闭子进程域原型

2026-10-30。**已实现自写ARM64隔离监管核心和空操作工作器，并在显式模拟Linux中运行。它在限定父子关系下拒绝把外部复用PID当作本次工作器，但真实隔离启动尚未接入；整体准入仍未通过，不能投放相机或首刷。** 235原候选及其失败反例保持。

本轮没有执行Sony/Linux/glibc原指令，没有创建实际Linux进程，没有相机/USB/缓存查询、管理员操作、认证、上传或固件写入。Mac编译的是自写C，Unicorn只执行自写ARM64；内核、进程、时钟、proc和socket均为明示提供者。

## 已做成的核心

[collector.c](collector.c)要求入口已经是独立创建的进程，并且创建之前已屏蔽可屏蔽信号。进入后检查PID/TID、UID/EUID、固定父PID、proc中的单线程/无tracer信息、PR_GET_CHILD_SUBREAPER=0和wait4(-1,__WALL|WNOHANG)返回ECHILD。任何已有子进程、共享线程迹象、收养身份或查询失败都会在创建工作器前拒绝。

它在独立信号处理表中将处理方式设为默认，复读确认；关闭自身FD表中的继承项，不改变外层Sony进程的表。然后自建私有数据报对、启用凭据、仅一次clone0创建空操作工作器。工作器等待本任务GO，完成后发固定私有DONE，关闭自身端点并退出。监管者必须同时取得匹配任务/凭据的DONE和内核正常exit0，关闭自己的工作通道后才返回局部状态10。

**状态10仅表示内部工作器的退出已观察。** 它不证明监管者自身最终退出、外层回收、服务构造函数返回或主机回传。C中的父PID321、消息关联值和模拟进程编号是固定夹具，不是相机实际身份或授权。当前静态ELF通过自写_start启动核心，是离线执行载体，不是已接入Sony构造入口的可上传程序。

超时和错误保持HELD；不会因稍后exit0转成功。工作器可能仍活着或退出结果被外部取走时，监管者继续保持自身进程及通道，不放弃、强杀、重启或制造完成。真实服务线程必须由尚未实现的外层启动/观察桥保证有界返回，不能直接在Sony服务线程调用这个循环。

## 为什么这个域能减少编号混淆

从保存的官方7.02内核原字固定了以下结构：新任务children链自指初始化；新signal结构和单线程初值；普通clone与CLONE_PARENT/CLONE_THREAD选择父关系；PR_GET_CHILD_SUBREAPER实际跳表分支和所读标志位。分配器的条件清零路径也已定位；实际运行时GFP允许掩码未测，因此核心仍主动查询并拒绝不满足的收养状态。

[53项静态核对](private-domain-contract.json)绑定3个相邻符号代码范围和10段Linux v4.9.337参考源码。参考源码不是完整重建的Sony内核；原字只读取和反汇编。新进程不继承子收养者身份也与[Linux维护者文档](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html)一致。

独立单线程监管者不是namespace init，不启用收养，仅有固定工作器且工作器不再创建进程。外部进程普通clone的父亲是调用者；CLONE_PARENT得到调用者的父亲，不能任选这个监管者。无关父进程退出时，也不会将后代收养给非祖先的监管者。[14个有限父关系图样例](topology-law-receipt.json)与实际工作器等待模型分开记录。

这是一份**带前提的域合同**。创建前的proc/wait快照本身不能证明后续代码完整性；实际加载镜像、请求绑定、真正clone0创建和进入该核心的路径还要接通。尤其未来完整采集程序必须维持“不再fork/clone/exec”的规则，不能把当前空操作的证明直接转给任意插件。

## 已执行的故障结果与保留反例

[8项检查、22个场景](runs-private-domain/receipt.json)包括正常退出及recv/wait间调度、八种前置拒绝、DONE后close失败exit68或SIGKILL、错误凭据/SCM_RIGHTS/GO发送失败、监管者关闭失败、活工作器超时、晚到exit0、外部取走原退出后由Sony或无关进程复用编号、监管者中途死亡。

有效外部父关系下，原工作器exit68不会被同编号外国exit0替代；结果保持HELD。内核模型依据进程树筛选可等待对象，没有直接把期望返回值硬塞给C。外层借用FD保持；私有新增FD和worker退出分别记录。

**强行输入同父替换仍会误认，反例保留。** 最后一例显式破坏封闭域，向监管者放入同编号外国子进程，此时原exit68仍被误认。它不是该域合同已被真实入口保证的证据。源码图模型还说明一种破坏方式：若工作器额外创建CLONE_PARENT兄弟，兄弟后续可以继续创建兄弟。因此本轮只证明限定域的行为，没有把整体身份准入改成通过。
