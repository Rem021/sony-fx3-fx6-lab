## 本轮原路径

沿用stage50保存的common/codec fixture，重新运行原构造、HEVC主体及分行布局后：

1. 原codec`64`为1，完整原`18ee08`读取`codec+88`的VUI数据，写入声明槽的`+18c`参数块并自然返回。输入VUI首字的bit8决定参数块`+4`的bit23。配置本体逐字节保持。
2. 独立从原调用者`18bca0`进入，明确绑定槽、request地址；原加载、JAL及延迟槽把该bit23传给`18d62c`。原函数将标志保存到S1，并真正保存S0/S1/S2和原返回点`18bcac`。
3. 在`18d650`地址翻译/未识别乘加段之前停。随后从`18d6a0`继续，保留SP、RA和原保存槽，只明确绑定缺口后的输出槽与codec指针。原入口A2先是标志，前缀将其保存到S1后，原地址段本会把A2变为codec指针；此处声明后者不覆盖已由原调用者产生的S1。
4. 模式核心按原ROM表分派，沿自己的原尾声恢复保存寄存器和SP，回到原调用点`18bcac`。该处在原调用者继续执行之前停，没有假返回或改PC。
5. 完整原零模式GOP构造将结果复制到GOP，原保存帧和SP仍正确恢复。

所有偏移为十六进制。完整地址翻译、乘加和真实通道绑定没有执行，这是一条有明确缺口的离线分段调用，不是完整初始化或实机Start。
