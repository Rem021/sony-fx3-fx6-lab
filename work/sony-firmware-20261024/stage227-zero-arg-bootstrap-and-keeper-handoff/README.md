## 实现与边界

[bootstrap.c](bootstrap.c) 导出 `int fx3_bootstrap_step(void)`、`int fx3_bootstrap_status(void)`，不解释调用者寄存器中的参数。构造函数只写内存标记。进入前必须完成初始化，再由明确的 step 调用推进状态；没有自动运行、循环后台重试或上传后端。[Arm 2025Q1 AAPCS64](https://github.com/ARM-software/abi-aa/blob/2025Q1/aapcs64/aapcs64.rst)规定前八个寄存器可用于参数／结果及临时值；零参数入口消除了我们的四参数合同与已有调用点之间的一项差异，不能据此推定原加载器会调用这些导出。

启动桥检查 root、主线程及参考 im 完整文件 SHA；固定 RAM 目录中的 1536 字节计划必须为 root/0600、单链接、长度/EOF/稳定元数据/CRC/时限一致。最多八个不重复 boot0/boot1 窗口，固定读取 profile；0 个任务也通过相同看护启动及 FINISH 流程，不能代替完整任务测试。计划中的 SHA、凭据和魔数只建立关联，不代表用户批准。

固定看护和工作镜像为第226轮两份 262144 字节 ELF，启动前完整哈希、只读描述符和 RAM 文件身份检查。启动桥保留独立的 `fx3-bootstrap-owner-v1/bootstrap.pending`，已有占用即保持 HELD；完成也不删除占用，不按超时或 PID 消失接替。clone 子分支只保留三角色 FD，exec 自写静态看护；父进程原 FD 标志保持。[看护及工作程序](../stage226-static-keeper-and-parent-image-contract/README.md)

512 字节 JOB/FINISH 经私有通道发送，结果绑定精确序号、看护 PID、整条任务 SHA、看护 SHA 和工作程序结果；还需 `wait4` 确认指定看护进程退出0。FINISH 声明准备结束并不等于退出成功。状态为 IDLE=0、RUNNING=1、HELD=2、DONE=3、DENIED=4、UNINITIALIZED=5。
