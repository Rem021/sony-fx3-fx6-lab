# FX3 帧槽来源、两类事件与标志准备

2026-10-25（本地日期）。本轮仅离线执行原固件指令，未连接相机。

**已把上一轮的“通道记录/索引”暂称收紧为 40 项帧信息池及其帧槽索引。** 原分配器依次返回 0–39，并在每次借用时清空所选的 3352 字节记录；第 41 次返回 `-1/空指针`。该索引由原逐帧 API 写入消息，不能当成固定 MAIN 编码通道号。

完整控制器构造、真实帧填充/归还与当前 MAIN 绑定仍未完成。本轮的空闲 map 节点池、对象链接及可选标志是明确的 RAM 输入，不能称为实机登记结果。

## 原帧槽池及元数据来源

- 原 `0x15ed14` 清空 `40 × 0xd18 = 0x20bc0` 字节，循环建立 40 项原 map 记录，并把控制器自身发布为数组地址：`controller+0x8af38 = controller`。原 `+0x8af40` 保存数组字节数 `0x20bc0`。
- 原 `0x15ee7c` 初始化另一片 `0x63420` 字节存储，原 getter 另返回该地址及伴随标量 `0x120c`；该标量的完整语义尚未绑定，不混称为 40 个帧槽。
- 原 `0x15f8c0` 依据原 map 和活动标志选择可用槽，实际返回编号及记录指针。逐次借用前把记录填入 A5 作为旧内容对照，原分配器清空选中记录，同时未选记录保持 A5。全部 40 项借出后，原使用计数为 40，下一次返回无可用项。
- 原前端 getter `0x14fdb0/0x14fdb8` 经 `0x15f4ec/0x15f508` 取得池地址；原元数据生产前段 `0x136378` 把帧池地址放入 Start 参数 `+0x18`，伴随标量为 40。

这给后续安全流程增加一个具体要求：几何信息必须在帧槽借用清零后由正确生产者填好，并保持到相关消费者完成。直接保存一个旧槽号、仅恢复预置指针或只观察参数谓词返回值，都不能证明帧槽已归还或没有异步引用。本轮没有运行原归还函数，也没有完成真实帧写入与编码时序。

## Start 与逐帧事件的原类型绑定

| 来源/消息 | 原接收及事件 | 本轮实际到达范围 |
|---|---|---|
| 原 Start 发送前缀 `0x136df0`，CID `0x2103` / MID `0x102`，长度 `0x90` | `resource_video_enc_start_param_t`（事件 4）；普通状态 IDLE 的原动作是 `0x24bec0`，其中保存元数据 | 原字节复制及接收分派到首个诊断前；完整 Start 未执行 |
| 原逐帧 API `0x1382f4`，经 `0x1383d0` 生成 CID `0x2103` / MID `0x103`，长度 `0x30` | 普通画面到 `resource_video_enc_encode_picture_param_t`（事件 6）；READY 的原动作是 `0x24cda8` | 实际到该 typed wrapper 入口前停止，未执行完整状态迁移 |
| 同一逐帧消息的 final 标志为 1 | 原分支经诊断后调用最后画面的另一 helper | 实际停在该诊断前，后续调用仅作静态锚点 |

原逐帧 API 把原分配器返回的编号放入 payload `+0x14`；普通/最后画面标志放在 `+0x10`。本轮使用原分配器产生的 0、39、1 做消息对照，不再直接给生成器随意指定一个“MAIN 通道”。改变 UID 的消息在原接收函数中返回且没有分派。

packet UID 由源对象的一个 8 位字段生成，接收端按 32 位字段比较。本轮 UID `0x2a` 只是身份对照，不是用户相机信息，也不是此前另一命名空间中的源 ID `0x805700f9`。接收字节函数没有覆盖父路由、认证、完整消息对象或实际 USB/IPC 传输。

元数据只运行到 `0x136418` 的后续生产入口前，剩余 helper 尚未执行。未写部分保留 C3 输入，用来明确这还不是完整有效的 Start 参数；发送前缀复制这份字节不能当作硬件接受或真实未初始化缺陷。

## 原标志准备函数

原 `0x246274` 在明确的描述符/默认值/覆盖状态输入上运行：

- 覆盖功能关闭的条件下，完整正文返回 1，将 start-input 前五字节写成 `07 01 00 02 00`。
- 原缓存 `+0x36/+0x37` 控制对照还写入 start-input `+0x118=9`，完整返回；字段完整业务语义仍待绑定。
- 描述符 guard 非零或进入需要处理覆盖状态的条件，均到达原诊断，未提供日志/锁返回替身。

默认查询包装器 `0x22ba98`、真实共享锁和配置代次仍未接通。完整 helper 返回 1 的范围不等于真实输入已准备好，也不是实际 16 Mbps、完整 Start 或编码成功的证明。

正式结果共 **62 段原 A64 执行**，包括池初始化、41 次分配、元数据/消息片段、标志准备和原 guard/下一状态选择函数。重复清零写入保留严格范围检查及计数/摘要；原指令、寄存器返回和内存输出均由原代码产生，没有替换原函数输出。
