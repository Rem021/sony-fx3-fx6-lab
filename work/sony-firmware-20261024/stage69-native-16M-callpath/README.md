## 拒绝与恢复仍有实际缺口

原 `+0x21eeb8` 在通道准备返回后检查 W0：假分支先输出诊断，再与真分支汇合到 `+0x21eef0`，继续复制 COMMON 的输出字段。因此，简单让适配器返回0，不能当作“原厂已经清理并安全拒绝”的证明。本轮在自定义拒绝入口停止，没有执行 trap 或伪造 Sony 失败返回。该局部分支为静态核对，不是整个原 Open 失败流程或救砖验证。

下一步需追原 Open 的上层错误传播、已经借出的 ID／handler／map-node 归还，以及实际停止、所有消费者退出和有效原厂模式恢复；同时继续原 OSAL 的真实初始化依赖。不能把引用仍存活的模型指针复原当作可卸载或同机救援。
