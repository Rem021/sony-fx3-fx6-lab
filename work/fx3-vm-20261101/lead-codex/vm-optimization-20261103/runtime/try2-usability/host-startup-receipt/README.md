# 启动失败时保留原始错误与最终回执

2026-11-03。独立宿主候选 `run_trial_v15_startup_receipt.py` 修复 v14 在 HTTP 绑定失败、进程创建失败或 QEMU 早退时无法生成最终回执的问题。**未运行虚拟机、未替换用户默认入口、未改变 FX3 平台或固件。** 网页模块沿用 v5，仍需真实固件联动验收。

## 已复现的问题与修正

v14 的 `phaseA_capture`、`phase_exit_hit` 与省电观察计数在 QMP 建连和输入门创建后才初始化。更早的错误虽然进入收尾，却在健康判定时再次抛出 `UnboundLocalError`，遮住最初的错误，跳过最终回执及 HTTP 关闭。另一个缺口是串口文件尚未创建时，原始串口证据提取会直接读不存在的文件。

新候选将这些回执默认值放在启动动作之前；串口文件不存在时明确记作 `serial_log_not_created`，不补造空日志或通过证据。进程未创建时，最终提示明确说“模拟器未启动”。原有健康判定不放宽：启动失败仍返回 2，`health_pass=false`、`lifecycle_pass=false`，API16 恢复不伪造成功。

## 验证边界

[test-receipt.json](test-receipt.json) 记录六个案例：在旧版分别复现端口占用、创建进程失败、进程早退导致回执缺失；新版三种情况均保留最初错误、写出失败回执、释放两个真实文件锁，关闭已启动的 HTTP 线程。已有服务器的案例还通过真实 loopback HTTP 读取终态并认证确认收到结果。

测试提取生产 `main` 从 `journal` 初始化开始的完整启动及收尾语句，使用真实网页状态、日志监视器、健康判定和回执代码。仅进程接口是禁止启动真实程序的替身；不覆盖前置包校验、真实 QEMU、固件恢复或成功启动路径。测试对旧版泄漏的线程自行清理，未将测试清理算作生产通过。候选 `--help` 导入通过。
