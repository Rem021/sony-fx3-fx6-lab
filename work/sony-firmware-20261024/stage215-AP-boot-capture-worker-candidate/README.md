**已把第213／214轮的启动区合同实现成独立C工作器、ARM64入口、请求协议和本地组装器。新增11项测试与旧47项回归全部通过；交付0.5源码包。** 这补上了救砖准备中的一段采集代码，尚未取得同机备份，也没有真实上传、启动、退出、写回或独立救援通路。

## 实现了什么

- 独立目标`nflashaB0/B1`，设备号252:126/127。只接受分区记录报告的1至255个128KiB容量，两条记录必须唯一且等长；读取前后再以已有BLKGETSIZE合同核对。实际机身容量仍未知。
- 每块64KiB，每组最多128块，完整区域最多4组；首组可发现容量，后续请求必须绑定该容量。同一capture ID、目标、全局块号、环境指纹和请求SHA贯穿请求、块头、清单；不假定4MiB。
- 先拒绝更新环境标记，再以C内SHA-256逐文件核对公开7.02主系统的emmc、crypt-emmc、devno三个原模块。它只验证普通文件内容，不证明已加载驱动、机身身份或当前安装p1；不能拿主系统指纹放行更新环境。
- 源节点仅O_RDONLY打开，每块一次pread；短读、容量／元数据漂移、保护区破坏、超期返回及写出／关闭错误都拒绝完成。仅在核验的tmpfs内新建0700目录和0600文件，不覆盖、删除、重试或复位。
- 新增`boot-request`、`build-boot-worker`、`assemble-boot-worker`三个本地命令，没有上传、动态插件、认证、USB或执行命令。源码包不包含Sony模块、固件或生成的二进制。

## 仍不能当作真机备份或救砖

第214轮原驱动证据表明，启动区读取可以发MMC_SWITCH改变eMMC访问选择，特定失败分支会panic。O_RDONLY不代表整个设备协议状态不变。候选在请求和报告中明确记录这些影响，**没有实现或证明读取后恢复先前访问选择**，也不自动尝试归还、重置或重读。[原驱动证据](../stage214-AP-boot-read-transfer-and-capacity/README.md)

标准[Linux v4.9 BLKGETSIZE定义](https://github.com/torvalds/linux/blob/v4.9/include/uapi/linux/fs.h)支持512字节扇区单位；它不证明Sony当前内核或机身真实接受本候选。当前节点和数据流的绑定来自前两轮已封存的Sony原件分析。

实际读出视图、启动容器各组件编码、写回时所需视图、同机来源和已加载驱动身份仍未验证。模块文件哈希不能代替运行身份。分组读取不提供原子快照；工具要求的正常返回码由调用者提供，仍缺独立可信的跨进程执行／退出回执。清单存在不足以证明完成；最终关闭失败时正常返回条件不成立。

单块5秒、读取阶段60秒仅在调用前后检查，不能中断阻塞系统调用或kernel panic。候选不包含进程外状态看护、主机重启后判断或救砖后端。还需可信的临时执行通路、真实同机完整备份、独立AP入口，以及逆写、冷启动和故障恢复验证，才能讨论第一次修改固件写入。
