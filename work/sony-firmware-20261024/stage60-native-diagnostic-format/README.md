# FX3 7.02：原内部格式化与未执行的时间寄存器边界

本轮确认并执行了**原映像内部的有界文本格式化链**，使用原日志调用产生的格式字符串和实际 `va_list`，生成146字节诊断文本；两种旧值、32字节截断和零容量对照均通过。没有用宿主格式化结果补写客体输出，也没有为这条直接调用链接一个替代的内核 `printf`。

完整启用日志的原路径则在**首条时间读取指令执行前**停止，未映射或伪造计时寄存器。随后文本格式化是独立函数测试，**不是越过时间读取继续跑完整日志**。实际时钟、完整日志头／输出后端、同步／当前机身映射、主录硬件及同机恢复仍未验收。完整目标和16项要求保持不变。

## 已核对的原调用链

原日志格式化函数 `+0x27d7d0` 先通过 `+0x27d32c → +0x2a4588 → +0x29f6c8` 准备时间头。实际执行到 `+0x29f6d4` 前，寄存器计算出的客体有效地址为 `0xfffffffff3402108`，读操作尚未执行。相关原代码还包含其它时间／状态偏移读取，但本轮只实际到达第一个读取点。

该地址不在任何已映射客体区域中。本轮将其作为原寄存器访问边界，不转发宿主、不映射假寄存器、不编造读取结果；模型有效地址也不能直接当作相机物理地址或已确认MMU映射。

文本函数的直接调用链为：

`+0x126a8 → +0x125c0 → +0x17040`，随后进入映像内字符串长度、整数转换及字符串输出流helper。`+0x126e0` 的原字面量指向文件内运行库上下文 `0xffffffc001bf8478`，其首指针指向原只读数据 `0xffffffc00138f4f8`。这些值和数据原样取自已固定哈希的映像，不另造运行库或locale对象，不在本轮认定它属于某个具体第三方libc版本。

这将stage59“寻找格式化CAPI provider”的下一步假设收敛为上述**内部函数与时间访问**；不据此推断整份固件没有其它CAPI或内核格式化调用。旧报告与已封存证据保留。

## 原参数如何进入独立格式化测试

在声明“logger已初始化、类别启用、不静音”的客体状态上，原queued Open和包装函数进入原匹配诊断，原getter、名称helper、可变参数包装及真实输出区清零均已执行，再进入时间读取边界。全局构造与真实日志状态仍是未验证范围。

从该原路径保留实际格式字符串、32字节 `va_list` 及其原溢出参数槽，独立调用原 `+0x126a8`。这次调用使用另一块客体栈，防止覆盖仍暂停着的原诊断帧及参数。原source、临时匹配视图、`va_list` 和原参数槽均在函数返回后逐一保持。

原 `va_list` 的GP偏移为0、SIMD偏移为−128；这里的参数来自原栈参数区。GP保存区顶指针仍含A5／C3旧值，因为这一组输入不消费该区域，不能据此宣称指针错误或实机缺陷。字段布局及参数分区与 [Arm AAPCS64可变参数说明](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst#14-appendix-variable-argument-lists)核对；具体读取和输出以原代码运行结果为证。
