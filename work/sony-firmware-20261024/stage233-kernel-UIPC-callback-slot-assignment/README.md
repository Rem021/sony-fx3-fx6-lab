# FX3 内核 UIPC 回调接收槽分配

2026-10-30。**已补上232未核对的内核分支：已保存的FX3 7.02驱动使用共享待处理回调链表和最多四个、分别绑定任务的接收槽；此分支没有按队列号固定接收线程。** 若启用多个接收线程，相同服务队列的先后请求可由不同槽领取。因此231的“相同活创建线程”是有实际兼容条件的保护，不能靠“同队列”来宣称条件成立。

## 槽绑定与回调排队

接收端从32字节用户结构读取槽索引，要求0至3。每槽结构跨度32字节：`context+0x70+index*32`保存接收任务指针，第一次接收时设置为current；已有不同任务占用该槽则拒绝。这是**槽到任务**绑定，不是队列到线程绑定。

注册索引8的处理切片将同一handle上下文存入CB+0x30，将队列编号另存CB+0x1a，并用`.text+0x15f0`包装回调。入队切片`.text+0x1538`从该CB读取上下文，遍历`context+0x38`单链表至尾部追加回调，随后扫描四个睡眠槽，唤醒已登记的任务。接收切片在同一上下文锁内取`context+0x38`的头项，更新链表，保存本槽待完成回调，并将用户回调、参数和消息地址复制回接收线程。同步和非同步交接分支都进入这一入队逻辑。

结合232用户态的共享FD与回调循环，在多个活接收槽这一条件下，两个先后回调由不同槽领取是该分支允许的交接方式。这里没有模拟完整调度器，也没有推断实际请求一定换槽，或穷尽其他服务路线。
