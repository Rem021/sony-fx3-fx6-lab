# FX3：将客体预置副本移出原固件工作区（2026-10-26）

**原型曾使用的`COMMON+0xe010`起256字节有明确的原固件用途，不能把它称作我们独占的空闲区。** 本轮把客体预置副本移到单独声明的试验存储槽，限制为一个固定控制器，并保留stage74修正后的56字节查询容器。

目标两组输入继续读到16,000,000，原通道实参及原OSAL路径保持；原对象旧工作区、另一handler的整个common对象、试验槽两侧64字节边界都未改变。原固件工作区用途、非目标控制器拒绝及对照也完成独立执行和回读。共7例、40段有界执行。

**这只调整Mac客体模型中的存储。没有在相机上分配内存、装载模块或生成可刷固件。** 原选择指针的互斥、真实内存归属、所有消费者退出、实际主录和同机恢复仍未闭合。

## 原工作区的证据

固定7.02原文件中，`+0x226364`的type=2分支：

1. 清理`COMMON+0xdff8/+0xe000/+0xe008`三个选择指针。
2. 把原`+0x3d8798`起256字节复制到`COMMON+0xe010`。
3. 按原参数修改该区若干字段，将`COMMON+0xe000`指向这个工作区，并更新其它原字段。

原直接调用点为`+0x21ebb8`，原诊断中有`create_imola_enc_start_param()`名称。原构造函数没有清零某段字节，不能证明这段空间无用途。

两组明确的独立入口输入运行原构造和原函数，实际观察到旧工作区改写、原选择指针指向它；原FH描述、外置试验槽与控制区保持。调用使用声明的type=2输入，**没有证明当前目标自然进入此路径、实际发生并发冲突或正常机身存在缺陷**。它证明的是空间有原生用途，原型的独占假设缺少依据。

## 本轮原型改动

受限写者改用模型槽`0x113a1000`，位于本轮固定控制器`0x113a0000`之外，也与整个原factory／common对象范围分离。写入器和其临时视图入口增加控制器地址检查，拒绝其它控制器共享这一个槽。控制结构仍为296字节，字段位置不变。

这些数值是**harness声明的客体布局**，不是相机地址或真实分配器返回。没有解决多控制器、多会话、真实分配／释放、跨核同步或装载后的重定位；不能把固定试验地址写到机身上。

重新编译写入器与保留56字节返回容器的适配器，目标原请求实际调用新写者，副本仅相对原预置改变既有`+0xb0/+0xb1/+0xb2`三字节。原查询得到`trace/target/CPB = 25,999,360/16,000,000/26,000,000`，容器外整个适配器帧及保存槽保持。新适配器交给原通道的实参仍与入口一致，随后到原内核锁第一条指令前停止。

另有原UHD和关闭入口对照；提供另一未映射控制器地址的独立检查返回BAD_ABI，未解引用该地址，整个arena及试验缓冲区保持。这是模型契约验证，不是实际相机内存能力或权限证明。
