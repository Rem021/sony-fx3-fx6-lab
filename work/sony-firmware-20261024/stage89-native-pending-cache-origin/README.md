# FX3：待处理缓存的初始化与帧参数转存来源

本轮将上一轮声明的`manager+c90`记录追到原写者：**它是8字节待处理缓存，更新bit4可以由已有帧的参数更新标志转存而来，不是编码器成功确认。** 原记录初始化与“已有缓冲时的转存”已分别完成离线对照。真实元数据生产、缓冲所有权、任务调度、MAIN和硬件仍未证明。

仅Mac离线，没有Windows、UU、相机接口或刷写操作，没有生成可刷包。持续目标保持未完成；16项要求和既有授权均保持。

## 两项分开的验证

地址和偏移均为十六进制。使用固定哈希的FX3 7.02 VCD原映像，在Unicorn中执行限定原指令；没有指令替换、假返回、MMIO或逐次内存读写钩子。原映像、不可变输入、全部声明数据页及完整栈均核对。

**空记录实验与已有缓冲实验使用不同的声明状态。** 不能把初始化后句柄为空的记录当作已经取得参数缓冲。后者明确预置已有缓存句柄、元数据句柄和可用缓冲；没有证明其真实分配或所有权。

源元数据字节、48字节内容以及句柄均为明确声明的离线输入。源帧由原描述符解析指令绑定；源生产者中段没有执行，随后几个入口也不构成完整正常调用链。保留原生产者栈帧只证明本轮片段未破坏它，不证明完整函数能返回或调度合法。

## 这次细化的判断

- 缓存bit4可以在帧参数转存过程中产生，不能把上一轮的声明记录叫作硬件成功回复。上一轮局部发布/复制/清位结果保留，解释范围收窄到缓存参数事件。
- 缺缓存句柄时，原代码先设置缓存bit4，再进入尚未执行的分配流程。本轮没有执行分配失败处理，不能称作相机分配故障；也不能单看bit4判复制完成。
- 元数据句柄不同时，源帧标志同样可能已经写入，但本轮停在引用计数工作前，没有继续使用它发布或编码。
- 真实元数据`+50/+54`的生产者、第一次缓存缓冲获取、引用计数/锁、后端转交与确认，是下一步应核对的来源。不能用这些离线声明输入代替同机抓取或实际模块响应。
