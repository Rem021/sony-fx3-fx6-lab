# FX3 原 DMM 缓冲申请报文与提交前边界（2026-10-29）

尚未达到“FX5/VENICE 整套专业功能与色彩链替换固件可正常刷入 FX3”的停止条件。本轮把原 NRV 申请推进到 DMM 客户端的报文构造完成、提交入口之前。7 组有界验证通过；未发送请求、提供服务回复或取得真实图像缓冲，没有生成修改固件。

开始前校验 [上轮封存](../dynamic-id-20261029/README.md) 的全部 27 个文件，前一轮属于有新证据的 progress。原件与旧封存不变，本轮不操作机身、USB、手机或真实 IPC，不干扰另一 agent 的 HEVC/恢复工作。CP 原件 SHA-256 为 `c90d00d807874a5309dc1b65b203287e83608ceee513cc57b53409333fb6bcba`，VA = 文件偏移 + `0x108000`。

## 原池初始化与消息分配

本轮执行原 `0x49dbea..0x49dc1a` 片段，由它调用原 64 字节元数据池初始化，再建立 `0x147f9c0` 的变长软件池。变长池大小 `0x80000`（512 KiB）来自原指令常量。片段入口的 RAM 基址 `0x53000000` 与元数据区长度 1024 字节仍是明确夹具，未执行或证明正常机身启动的上游分配。

原 `0x49f80c → 0x49fc4c → 0x4a0980` 在该 RAM 条件下实际分配消息空间；没有钩子返回消息地址。216 字节负载对应 256 字节分配，原头部记录块数 4、引用计数 1、负载长度 216、前后保护字 `0x55555555/0x77777777`。

原 `0x57b7be` 构造容器，并通过原 `0xa878d2` 将之前原代码产生的回复 ID `0x9005601f` 写入负载前 `0xc` 字节的消息头。软件元数据池累计消耗 7 个 64 字节块；512 KiB 变长池消耗 256 字节。这些都是软件消息与上下文内存，不能当作图像缓存、传感器 RAW 或 DMA 缓冲。

## 原客户端身份与申请字段

原 `0x44d710` 的日志实参指向 `AllocNew:` 子串；同一完整字串带 `[DmmWrapper]` 前缀，附近源码路径包含 `InfraBB_DataFlowInfraWrapper.cpp`。因此将其分类为 **DmmWrapper 的 AllocNew 客户端路径**。这是原诊断字节与调用点的推断，不是恢复出了导出符号或公开 SDK 定义。

context 1/5/7 的三个原 kind3/NRV 前缀均停在 `0xa878ca` 第一条指令前。原提交参数为 R0=`0x61003c`、R1=分配出的消息负载地址；此时原客户端写入：

| 负载相对偏移 | 原写入宽度 | 值 |
| --- | ---: | --- |
| `+0x0` | 2 字节 | `0x20` |
| `+0x4` | 4 字节 | `0x4af` |
| `+0xc` | 4 字节 | `0` |
| `+0x14` | 2 字节 | `0x55` |
| `+0x16` | 2 字节 | `1` |

已按每个原写入指令的地址和宽度生成负载写入掩码：合计 **14/216 字节**。其余 202 字节保留 RAM 夹具的 `a7` 填充值。报文的原核心字段与消息头得到验证，不能把该快照称为完整可用协议规格，更不能直接发送到机身。

## 回复合同仅为静态证据

原调用者在提交返回后还会检查：提交返回为 0、回复 `u16+2` 为 0、`u16+0 == 0x8020`、`u16+6 == 0x55`、`u32+0xc != 0xffffffff`。本轮请求第二参数为 1，对应原分支还要求回复 `u16+8 != 0`、`u32+0x20 != 0`。

这些检查来自原 `0x44d854..0x44d8b2` 静态窗口，本轮没有执行或补入回复。特别是请求的 `+0x14` 与回复检查的 `+0x6` 不同，不能混用字段偏移；非零返回字也不能直接命名为有效物理像素地址。
