# FX3 7.02 物理端口关联诊断01固定包

本包用于首次实际Sony通信与退出诊断，沿用260已审查代码，绑定新的单次材料。它不上传程序、不写固件，不代表H.265功能包或可救砖方案。

## 固定机身与主机

经典ILME-FX3，用户确认7.02；源MSC必须为054C:0DA1、位置0x01100000、本次固定缓存节点和物理USB-C锚点。具体数值在`fixed-material.json`及`fixed-plan.json`。缓存节点或物理锚点变化时拒绝，不自动改目标。全部相机卷须已安全推出；推出后IOMedia节点为0允许，未知状态、挂载卷或无存储驱动拒绝。root入口会在接管前独立核对。

本次试验期间保持相机、数据线和Mac插口不动，不更换设备。SERVICE默认不发布USB串号，因此只在原MSC交换与旧对象释放后，对已确认的物理USB-C端口开启限定2秒/20次的采样关联窗口。SERVICE的实际串号字段保持全零，不复制MSC标签；若它提供串号，则必须匹配。退出后必须看到新MSC恢复原串号和原逻辑位置。

此关联依赖物理保管条件，不能排除采样间恶意替换，不是密码学身份或完整USB事件捕获。结果将单列为受控端口关联，原机身程序指纹及拍摄健康仍需后续验证。

## 最多执行一次的流程

1. 固定host工厂核对全部源码/构建/命令摘要和新范围授权，再查询缓存；目标、卷及物理端口均满足才创建本次私有作业。管理员程序尚未执行前不会发送USB请求。
2. 打开Terminal，由用户本人完成必要的sudo/Touch ID验证。固定helper与96B许可安装到root私有目录；原始帧、许可和单次标记存Mac内置盘私有目录。最多一个root helper，不采集密码，不修改隐私权限。
3. 父端通过内核UID/PID/出生时间/路径与helper自身映像摘要核对后，才允许接管。执行一次USB接管和MSC接口声明，然后MSC START与固定七次认证交换。
4. 释放旧对象，按上述有界物理端口窗口等待0336 SERVICE。获取并核对实际配置、接口和管道：仅单配置、单vendor接口alt0和已实现的64/512/1024B策略；不设置配置、alternate或USB速度。
5. 配置符合时进行SERVICE START和固定认证，仅发送一个固定read0，读取最多88B机内`.hasp`记录；只保存长度、HMAC和响应形状，原文立即擦除。没有任意文件路径、存储卡素材读取或上传。
6. 配置不符合时不发送SERVICE START、认证或读取，仅尝试一次独立控制STOP。该分支的实机退出效果未知。
7. 正常分支发送一次STOP并释放对象；在新的返回窗口中核对原MSC串号，再显式请求归还驱动。最终回执、helper退出、独立缓存和相机屏幕是分别核对的证据，USB返回不等于机内线程完成。

## 副作用与异常边界

认证可能更新机身认证历史、`.hasp`/`.etools`相关记录或工作模式。这不是零写入；即使没有固件写入，也可能停留在服务模式。目前未验证从所有异常恢复的方法，不能保证可救砖。

整体工作期限20秒，最终观察期限30秒；单个传输超时参数最多1秒，但原生调用不保证可强制中断。身份不明、超时、未返回或归还不明时保留UNKNOWN、原helper和连接；不强杀、不reset、不自动重试或重发认证，不自动断电/拔线。全局相机状态在Sony命令后仍保留UNKNOWN，不自动开放下一次试验。若系统另行显示权限或原生验证窗口，由用户本人处理，程序不自动改权限。

没有驱动安装、Fastboot/BootROM、任意内存操作、模块上传、固件/分区写回、功能解锁或跨机型刷写。完整同机备份、独立恢复、MAIN HEVC与首刷准入仍未完成，全部16项目标不变。
