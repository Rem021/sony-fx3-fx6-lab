## 两样本共同的长度关系

两份原件在偏移 `0x48` 分别有可读版本 `6.00`、`6.01`。读取字段并按实际文件长度核对：

| 观测 | V6.00 | V6.01 |
|---|---:|---:|
| 前部固定长度 | 76 | 76 |
| `0x34` 大端字段／候选头长度 | 1024 | 1024 |
| `0x44` 大端字段／候选主体长度 | 29,329,408 | 29,328,400 |
| 候选主体开始 | 1100 | 1100 |
| 剩余尾部 | 16 | 16 |

两版都满足 `76 + 1024 + 字段0x44 + 16 = 实际文件长度`，开头 4 字节也与 `0x40` 处 4 字节相同。**这是两份实际样本的结构关系，不是已恢复的厂商格式规范。** 尚未把这些重复字段、头部残留或尾部指定为校验和、密钥、IV 或签名。

## 有界线性模型的依据与限度

候选头内出现大量连续字节关系：`c[i+1] & 0x7f == c[i] >> 1`。各取六个长连续段，以每段前 64 位拟合二元线性递推，十二段都得到阶数 16、滞后项 `11/13/14/16`。各段其余共 **694 个留出位全部预测相符**。

使用每版最长段的训练位，在“该处为零填充”的假设下延展模型，仅对候选头的 1024 字节做 XOR 变换。两版结果各有 16 个非零字节，其余为零；非零字节位置不同。两个有界候选文件保留 SHA 和非零位置，未给这些字节赋予密钥／IV 等语义，也没有据此尝试主体密码、生成签名或导出完整解密候选。

该结果恢复了**一段可预测的数据模型**，还没有原始读取器证明它就是完整解包算法。没有用重复 XOR 往返作为成功解密证明；依据是不同连续段、两个版本及留出预测。详见 [模型、来源摘要与检查结果](structure-analysis.json)。

原始主体仍呈高熵，所查 ELF／XZ／SquashFS／UBI／CPIO／私有包装标记没有直接给出可读组件。V6.00 唯一 gzip 三字节候选在有界解码时因非法头标志失败；V6.01 无此候选。它们不是对全部格式的穷尽排除，更没有提取出菜单、色彩算法、传感器标定或系统加载器。
