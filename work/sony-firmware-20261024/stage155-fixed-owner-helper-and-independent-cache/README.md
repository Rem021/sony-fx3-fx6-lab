# FX3 固定原生入口、同机绑定与独立缓存观察

2026-10-28。**固定用途 C helper 已编译，13 项自写夹具可执行程序检查、37 项 C 核心回归及14 项缓存观察器检查通过；实际接管入口仍未完成或放行，没有可试刷包。** 原生 IOKit helper 和管理员脚本未执行，没有新增主动 USB、驱动、认证、相机文件、模块或固件操作。

本轮在已有授权内查询了一次 Mac 系统 USB 缓存：当时可见一台指定端口的 054C:0DA1 / ILME-FX3，接口0为 MSC，存储驱动链仍在。这仅是缓存关联，不能证明相机功能正常、备份可恢复或变砖可救。原16项主录与恢复验收要求保持。

[owner_entry_main.c](owner_entry_main.c) 不解释用户 Python、任意 DSO 或 Sony 命令。它在固定目录内打开私有共享文件，先持久化该文件的单次占用，再核对原生 PID/出生时间并执行共用 C 流程。期限在 helper 实际开始后采用 CLOCK_MONOTONIC；管理员确认耗时不消耗尚未开始的原生工作预算。停止是协作请求，不能取消阻塞中的系统调用。

新增 ABI3 的 `expected_body_tag` 将预选机身与原生第一次缓存观察对应起来，不匹配时不会继续 open/capture/claim。[派生记录](source-derivation.json) 保留154原件；[回归派生](regression-derivation.json) 固定此前测试源码与改动。

## 入口为何仍不能直接运行

[本地复核](local-source-and-lifetime-review.json) 和 [候选计划](candidate-plan.json) 列明尚未补齐的部分：

- 还没有实际调用端将管理员中继、真正 root helper、共享块及进程重接串起来。中继进程存在，不等于 helper 仍存活或已经退出。
- 单次 CAS 目前只防止**同一个共享文件**被重用，尚未把一份实机授权与固定构建、目标、跨新文件租约绑定。
- AppleScript 包装器接受 helper 路径参数，尚不能独立保证只运行指定二进制；未来调用端必须固定并验证路径和哈希。脚本只做过 `osacompile`，没有请求管理员认证。
- 构建及共享文件位于用户可写、关闭所有者检查的外置卷。root 执行前还需解决路径替换、文件身份及授权/二进制不可变绑定；没有安装加固后的提权组件。
- 缓存观察器尚未观察过真实接管前后驱动归还。C 的“拒绝已挂载或未知介质”并不替代完整的卸载前置检查、自动重挂载竞态与后置监管。

这些缺口关闭并完成具体审阅后，再请求一次明确的用户客户端、Seize/capture/release、驱动接管及管理员执行授权。此前描述符单次权限已经消耗，UU 的输入监控/Touch ID 授权也不覆盖这里。

## 首次刷入的时间条件

目前不能给出可靠日期，也不能保证最终一定能满足主力机的可恢复要求。下一次可准备的真机试验是 USB 接管与归还，仍不包含固件刷入。其后还需同机健康备份、实际恢复与回读、适用的独立救援入口，以及 FX3 7.02 专用临时补丁的目标原片验收，才具备讨论首次持久写入的依据。

主目标仍为 MAIN 1920×1080、30000/1001（29.97，区别于精确30.000）、HEVC420 10bit约16Mbps。已有 A7C II 作者演示、离线参数链及本轮主机夹具都不能替代 FX3 编码、音画、温度、长录、冷启动和对应恢复验收。未制作可刷固件，`persistent_write_release=false`，目标保持进行中。
