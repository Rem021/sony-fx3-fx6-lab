# FX3：主录参数生产者缺口与检查器的边界

**原应用这一处 MAIN 转换分支，在8个格式入口、两种选择值的32组旧内容对照中，没有生成候选所需的 VideoParamComb 6。质量6和帧率3可以生成，但它们不能补上视频类型缺口。** MPR 的通用检查函数对声明的候选参数能走到结束诊断；它也让一个超出已见类型表的合成类型值走到同处，因此不能把这项检查当作有效配置或硬件支持证明。

2026-10-27，仅 Mac 离线执行固定原代码；未操作 Windows、UU 或相机。地址及偏移为十六进制，下表选择值和类型值为十进制。完整目标、权限及16项验收保持。

## 参数来源

阶段104定位了普通录制调用 `mpr::RecStart`，并经 `SetRecStartInfo` 进入参数检查。本轮继续读到：

- 原内部函数 `cca10` 调用 `movieRecParam` 构造、`GetMovieRecParam`、`CheckMovieRecParam`，检查后以长度 `1bd` 复制至 `MovieRecInfo+58`。
- 原 `SetMovieRecParam`（`f0ff0`）和 `GetMovieRecParam`（`f1238`）的复制调用使用同一 ELF 全局地址 `38c810`；它们周围有原同步调用。上述复制、锁、当前全局值和运行时加载本轮没有执行。
- 原应用在 `2e6f7bc`、`2e6f9b0` 两个直接调用点调用 `mpr::SetMovieRecParam` 导入。两点都在原 `mpr_SetMovieRecParam`（`2e6e5d8`）内。直接 B/BL 扫描不覆盖间接调用。

因此需要继续追配置生产和快照来源，不能仅修改 RecStart 的介质启动请求。

## MAIN 三个字段的原生产

原应用诊断字符串及实际读取位置把局部参数的三个字明确命名为：

| 局部参数偏移 | 对应保存帧位置 | 原名称 |
| --- | --- | --- |
| `170` | `FP+480` | `mainVideoParamComb` |
| `174` | `FP+484` | `mainVQuality` |
| `178` | `FP+488` | `mainFrameRate` |

本轮先执行原函数序言至首个日志，再从 `2e6ea58` 独立进入转换正文。原序言产生的参数指针和保存帧保留。之前的清零、命名、接力/代理设置及日志均未执行；没有伪造它们的返回或把它们当作已经初始化。三字由原指令写出，停止在音频参数 helper 调用前。

固定声明的质量选择值2、帧率选择值15，原转换分别产生 MAIN 质量6、帧率3。改变格式选择 `input+14` 和选择字 `input+1c` 得到：

| 格式选择值 | 选择字0的原 MAIN 类型 | 选择字1的原 MAIN 类型 |
| --- | --- | --- |
| 5 | 4 | 4 |
| 6 | 5 | 7 |
| 7 | 0 | 2 |
| 8 | 1 | 3 |
| 9 | 9 | 9 |
| 10 | 10 | 10 |
| 11 | 12 | 12 |
| 12 | 1 | 1 |

每格以A5/C3两种保存帧旧值执行，输出三字一致。类型集合为 `{0,1,2,3,4,5,7,9,10,12}`，没有6。格式选择4/13、格式6下的选择字2、质量选择0和帧率选择12共10组负例，在原无效选择诊断入口前停止，未消费其部分输出。

这里的格式选择数字是原包装器输入枚举，不能直接当作相机菜单序号。也没有证明每个独立声明组合都能从真实菜单到达。结论只覆盖这一处转换正文，**不等于所有固件生产者都无法生成6，也不等于可以把某一项类型直接改成6后安全使用。**

既有候选要求的逻辑三元组为 `[6,6,3]`；此前元数据转换的范围内，它对应HD、30000/1001和16M字段。本轮没有把它冒充原应用的自然输出，没有再次验证实际编码、实际帧率或码率。新证据说明：候选除了底层资源/码率，还缺正常 MAIN 参数来源的绑定。

## MPR 检查通过分支为什么不足

原 `CheckMovieRecParam` 在 `cc580/cc5bc/cc5f8` 读取同一结构 `+170/+174/+178`。本轮的检查实验使用**除三个字外全零的声明结构**，没有执行应用完整构包或原结构构造。先执行原检查序言至日志，再独立进入日志后正文，止于下一个原诊断函数前。

| 声明的类型 / 质量 / 帧率 | 原分支生成的诊断 ID | 本轮观察 |
| --- | --- | --- |
| 候选 `6 / 6 / 3` | `40f` | 到达结束诊断 |
| 应用原输出核心 `5 / 6 / 3` | `40f` | 到达结束诊断 |
| 类型哨兵 `13 / 6 / 3` | `402` | 到达类型诊断 |
| 质量哨兵 `6 / 255 / 3` | `403` | 到达质量诊断 |
| 帧率哨兵 `6 / 6 / 12` | `404` | 到达帧率诊断 |
| 合成大类型值 `2147483646 / 6 / 3` | `40f` | 同样到达结束诊断 |

每项两种保存帧背景。原代码对这些字段进行特定哨兵比较，不能据此理解为完整类型表查验。结束诊断之后的原返回代码没有执行，没有补造日志返回或正常检查完成。合成大值没有交给后续类型表索引或编码器。

这只说明声明候选没有触发这些特定检查分支；不证明候选合法、音频/代理配置有效、资源匹配、媒体可写或硬件可编码。相应音频/代理开关在这份声明输入中为0，未覆盖其开启时的检查。

## 到编码 Open 的静态连接

原 `EnqueueExecEncOpen`（`d6698`）读取 `MovieRecInfo+1c8/+1cc/+1d0`；它们按前述复制偏移对应 MovieRecParam 的三字。函数还把主、代理参数分别传入 `GetCodecInfoForCodec(VideoParamComb, StreamType)`。原类型表 `g_videoParamComb` 的本库定义为312字节，每行24字节；本轮只核对其符号/重定位、调用指令和原表字节，没有执行查询、队列消费或实际 Open。

下一步应沿这个原类型表、编码 Open 参数来源和实际消费者核对候选类型6，以及 MAIN/代理选择、缓冲所有权、配置代次和同步。不能用通用检查的结束分支或相同编码器类别替代这些绑定。

Sony 当前经典FX3主录格式页列出 XAVC HS 4K、XAVC S 4K/HD、XAVC S-I 4K/HD/DCI 4K，没有列出 XAVC HS HD 主录。这是公开菜单规格，与本轮一个内部转换分支的结果分别保留，不能反推私有枚举数字或判硬件绝无能力。[Sony 原文](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000868279.html)（本轮从经典FX3菜单入口重新核对）。
