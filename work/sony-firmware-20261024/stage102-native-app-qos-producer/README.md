# FX3：原应用码率请求生产函数与SRT调用范围

**在官方appFw.so中找到原生`mc_enc_set_qos`生产路径：明确输入16000时，原指令生成目标16,000,000的完整80字节命令。该原生字节已继续通过独立av-cam客体的接收副本、状态分派和下层转发对照。现有可识别调用者属于SRT推流/推流启动，尚未绑定卡内MAIN。** 没有实际发送、编码成片、恢复或可安全刷入版本。

地址、命令号及字段偏移为十六进制；输入值、统计计数及比特率值为十进制。本阶段仍仅Mac离线，全部16项要求与相机授权保持。

## 从原应用输入到原命令

原外层包装器`2dd1d54`调用`2df20cc`，对应固件中的`infra_wrapper_bb::detail::mc_enc_set_qos`名称。该函数在原日志及OSAL初始化之后，从`2df213c`直接构建命令，没有经过stage101核对的`libInfraAvbbc`命令转换表。因此，那张表缺10a输出的结论保持；本轮找到的是另一条应用原生路径。

本轮先执行完整原序言至第一处日志入口，产生保存帧和输入指针，再独立执行原构包正文，未补日志/OSAL返回。正文用原`STP XZR`清理整个50字节消息，写入以下字段：

| 消息位置 | 原生成值 |
| --- | --- |
| +0 / +2 / +4 / +6的16位字 | CID2003 / MID10a / 长度50 / 原固定值1 |
| 载荷+4，即消息+0c | 目标更新字节1 |
| 载荷+8，即消息+10 | 32位输入字乘1000后的低32位 |
| 其它字节 | 原清理指令生成0 |

原诊断明确把目标字段标为bps；本轮验证的是具体转换：16000→16,000,000，20000→20,000,000。工程上输入按十进制kbit/s解释，与乘1000一致，但没有把这两组输入当作已测实际码率。

另有0和误把16,000,000直接作为输入的负对照。后者产生3,115,098,112，显示原32位乘法截断；前者仍构造目标更新字节。这些是宿主明确给出的单元输入，不是合法范围或下游接受证明，也未执行完整调用者的校验。

两种旧值背景A5/C3中，整个80字节输出逐字节一致；不是把预期封套或目标字段预先写进客体。输入和未使用的结果对象保持，原ELF映像只读，无补丁、原生返回或日志替代。

## 同一批原生字节继续向下传递

16000与20000两种输入产生的50字节原消息，原样交给独立av-cam客体，无宿主字段修改。原MID分派选择10a；原接收片段复制48字节至上下文`+358`并附加明确的回复标识；原状态3的ROM动作进入时序码率入口；最后在较低独立栈执行原下层转发，生成CID2103/MID10a、长度54的封套，目标仍分别16M/20M。

这是跨客体的**原字节交接**，不是实际进程间传输或同一实机实例。任务hook、日志、参数打印仍是明确间隙。状态3、回复标识及下层通道2属于接收模型输入，未由应用命令或实机证明。原暂停的接收/状态/时序栈逐字节保持，没有覆盖它们来完成独立下层调用。

## 当前调用者与未绑定的标识

完整`.text`中找到两处直达`2dd1d54`的立即分支候选：

- `2d9c204`：所在原函数名为`model::sequence_set_srt_streaming_target_bitrate::run()`，从对象`+1b8`取输入。
- `2db1bdc`：所在原函数名为`model::sequence_start_streaming_output::streaming_start()`，从对象`+61c`取输入。

这是这两处静态调用关系，不是所有间接调用或工作流的排除证明。相关成功日志也不能代替实际码率、成片或MAIN验收。

原`2de7070`以参数2初始化标识结构，并调用`osal_subsystem_id`、`osal_dynamic_id`。本轮仅执行到第一个OSAL调用之前，观察前8字节0/2，没有生成或假造有效ID。**不能因为这里出现2，就把它等同于下层模型中的通道2或MAIN号。**

原发送helper `2e109d0`引用`DataflowInfraMsg`和`DataflowInfraSender::SendASync`；原调用准备使用固定参数8057060a。发送/回复标识、实际目标实例、消息对象构造、SendASync、回复接收及正常外层包装器均未执行，没有打开进程、相机或网络流。

这些官方规格与本轮SRT调用者相符，但没有证明各编码格式组合、42010、16M实际输出、卡内文件沿用推流编码器或目标MAIN解锁。**推流和卡内MAIN继续分别验收，不把现成推流功能替代本任务。** 首轮检索出现的其他机型页面未用于FX3能力判断。
