# 第179轮：同进程 IOKit 有界收发适配

2026-10-29。**C 适配层与控制器的夹具连接已实现，55项当前本地检查、两条完整惰性流程通过。** 原生版本仅编译成对象文件；实际执行的是自写 SDK 形状的假 vtable，没有加载真实 USB 库，没有新增相机、管理员或隐私权限操作。

## 本轮实现

[C 接口](iokit_wire.h)／[实现](iokit_wire.c)借用拥有者同一进程内的 `IOUSBDeviceInterface650**` 与 `IOUSBInterfaceInterface650**`。仅提供固定8字节 START／STOP、固定516字节认证帧收发及本地代次检查；不提供枚举、打开、接管、关闭设备、清除 stall、重置、模式回退、文件或固件 API。它不会把 IOKit 对象强转为 libusb 句柄，也不复用已结束05进程的地址。

本轮对照本机固定 SDK 头文件及[Apple 官方公开头文件](https://github.com/apple-oss-distributions/IOUSBFamily/blob/main/IOUSBFamily/Headers/IOUSBLib.h)：管道引用是接口内索引，需要由拥有者实际枚举映射；不能把端点地址当作管道索引。`WritePipeTO` 没有实际传输长度输出，因此即使请求返回0，也记录 `actual_count_known=false`、`transferred=null`。读取只有在请求返回0、长度恰好516且边界和拥有者检查通过时才交付数据；错误返回附带的长度不会作为有效数据使用。

两个原生超时参数均为正值且不超过1000毫秒，并受单次操作及会话截止时间约束。保留原始 IOReturn，不套用 libusb 的错误编号。调用返回后再核对时间、缓冲区和拥有者代次。原生调用仍在途时保留 pending；不从另一线程强杀、重置、关闭接口或自动重发。设置超时不等于已证明真实驱动一定及时返回。

[Python 夹具桥](iokit_fixture_api.py)仅能创建并登记本进程的标记夹具上下文，持有动态库强引用并串行保护生命周期；拒绝整数指针、伪造对象、不同模式、不同进程标识及已释放对象。[控制器适配](iokit_wire.py)保留原147的目标／连接／观察新鲜度、报文序列、共享预算、一次 STOP 和非阻塞会话锁。实际 live 工厂在原授权门之后仍明确拒绝，因为原生拥有者 IPC 尚未实现。

## 仍未完成的边界

1. **真正的原生拥有者整合及 IPC。** C 代码尚未链接进负责接管的 root helper。身份、原端口、实际管道映射和句柄寿命仍须由拥有者证明；本地 `refresh` 只检查原子标志及代次，不枚举设备、不证明相机身份。Python注册的夹具地址不能用于其他进程。
2. **共享预算的原生落地。** 当前跨 MSC／SERVICE 的单会话预算和完整认证语法由 Python 策略执行。C 上下文只提供单上下文的形状、次数和在途保护；未来 IPC 必须固定上下文分配、全局次数、请求身份及回执归属，不能把任意新上下文当作绕过预算的入口。
3. **真实服务与退出。** 原生非夹具构建只允许已观察的 MSC 81／02／512B 形状；SERVICE 83／04仅为既有模拟数据，不是实测。START／STOP返回、合法认证应答和控制器模拟结束均不证明相机线程退出。控制 STALL 保留为独立状态，不充作相机成功。
4. **认证副作用及恢复。** 原7.02认证尾部的条件历史／日志／模式文件写入和原退出等待问题仍未在真机闭合；未发送任何 Sony 认证或 STOP。完整同机备份、恢复回读、独立救砖及目标 MAIN H.265 实录／长录均未验收。

因此本轮不是可刷固件或真机服务放行方案。下一步是在拥有者进程内落地带身份、代次、单次请求及全局预算的 IPC，再用不含 USB 的进程夹具验证在途与归还顺序。16项原要求、全部授权和用户限制保持原样，`goal_complete=false`、`persistent_write_release=false`。
