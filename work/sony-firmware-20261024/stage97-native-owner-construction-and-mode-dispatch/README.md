## 纠正此前初始化函数的解释

此前stage92及其沿用实验把`1352f0`称为“owner默认初始化”，这一称谓范围过宽。原调用者`1378fc`把栈上临时缓冲作为它的参数，`137920`调用后再把该缓冲用于参数结构；不能以此证明完整GOP owner的真实构造。该函数若从owner基址使用，会在`+4`形成`01010100`，不能作为这里动态表分派所需的正常初始索引证据。

与原GOP管理器直接相连的实际构造入口是`12f21c`：原`7a2ac`准备`f2c`字节申请，经原分配器返回；原`7a2c4`调用构造，原`7a2d0`保存owner指针。本轮从这段原调用者执行，owner地址来自原分配，不是预先写入CPU的成功返回。

旧实验的局部指令、声明输入和精确内存结果保留；其“正常owner默认状态”的解释收窄，不把此前带旧值的帧头/几何实验当作本轮真实构造后的正常模式结果。它们也从未构成实机编码或刷写证据。

## 实际构造建立了什么

地址为十六进制文件偏移，VA为`80000000+偏移`。本轮原分配返回owner `85000010`，原构造：

- 将两个声明配置ID分别存到`0/2`，将动态分派索引`4`原生设为0；两个ID不是动态表索引，也不是相机身份或MAIN通道验收。
- 调用原`1f3858`构造owner内嵌的`10..7f`参数结构，设置其中明确的初值与空引用。
- 建立owner内部链表、计数和历史记录初值。此前未追来源的`28/2a/31/32/35/36/37/84..90/98`等在这个**新构造状态**有原代码来源；这不是模式应用之后的最终值。
- `80`只按单字节置零，上面3字节仍保留池旧值；其他未写空隙也保留A5/C3。没有为通过检查清零填充。

原构造返回原管理器时，立即核对整个`f2c`字节及其哈希，再继续后续实验。

原管理器中`7a2d4..7a300`的回调对象分配/构造仍未执行，S3回调继续声明为0。随后从既有工厂后半段分别创建两种控制对象，原构造把owner指针保存到它们的`+4`。本轮堆中5次原申请依次为`f2c/18/c4/1c2c/524`；后四次是前轮已分类的两个对象和私有缓冲。正常启动及堆锁回调绑定仍有明确空缺，不能称完整有效的管理器工厂。

## 从原选择器连续进入模式处理

继续前轮第一选择器，消息长度字段为`70`，声明字段`payload+1b`为0或1，分别选择ringC4/ring524。选择存储之后，从同一条尚未执行的原JALR继续，保留寄存器、SP和所有RAM，没有另起模式入口或改写函数指针：

`7af58 → 原vtable slot8的143f38 → 134d40 → 原ROM表索引0的12f7dc`

ROM表位置来自原GP相对地址，第一对为`{8012f7dc, 0}`。原代码自己读取构造出的索引0、解析函数与调整量、设置实际owner参数，再执行间接调用。两种控制类共享这个模式包装入口，不能因为选择了其中一种就推断已选择HEVC或MAIN。

原`143f38`对控制对象`+10`的赋值也逐项核对：声明payload `+0e/+10`为`0/0、1/0、1/1`时，结果分别为`0、1、0`。字段含义尚未追到生产者，不给它们起具体拍摄模式名称。

原`12f7dc`从payload `28/2c/30`取得3个声明字，保存到owner `84/88/8c`，将`90/98`置零；`80`来自栈上临时标志。该标志只原写一个字节，随后整字复制，所以本轮保存`d7d7d701`，高3字节保留声明栈旧值。未把这些字称为已验证的时间戳、有效编码标志或实机缺陷。

2种池旧值 × 2种对象选择 × 3组分支输入，共12场景60阶段。消息及其3个字仍是离线输入，尚无真实生产者或跨处理器协议采样。最终停在`12f84c`第一个尚未建立的trace全局读取前；后续含硬件计时MMIO和原几何/模式工作。本轮没有修改日志使能、补造计时器、跳过日志后继续、声称模式已完成或启动编码。
