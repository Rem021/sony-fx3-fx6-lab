# CP 类别5配置的 escape 装载候选与 CPIR 全量边界（2026-10-30）

**找到上一轮普通转发以外的明确候选：公开 AP 参考的 `config_load_cetus_escape` 会选中类别5配置，计算 AP 暂存目的地址，再进入文件装载入口。** 用原 FX3 默认行和声明的默认地址作独立片段检查，`DmmCfg.bin` 走到文件装载前，`tomco.txt` 类别7则走跳过分支。没有执行实际文件读取／传输，没有证明这台 FX3 会正常经过该路径，仍无可刷修改固件。

开始及封存前核验目标外盘 UUID，独立回读[上一轮](../AP-CP-handoff-reference-20261030/README.md)12个封存文件。沿用[公开 A7 IV v2.00 AP SRAM 对照](https://github.com/DavidBuchanan314/ILCE-7M4-RE/blob/e85e137fc3b88b7cb26e69faa9f1304184678ff7/emmc_boot/README.md)，SHA `2e37d90bc8f489db13a0319a3e7f8f1e746921c380484147b922957af3e95d74`；它不是当前 FX3 的 AP boot0。另一任务的程序、原件、租约和设备未操作。

## 普通转发与 escape 装载的分类不同

上一轮已确认，所查普通参考转发分支不处理原 `DmmCfg.bin` 的 `0x05000000`。本轮在另一个原函数 `0xfe0520d4` 中找到：

- 查询 `0xfa019a`，保留一个暂存基址；表仍按 `0x90` 字节步长读取。
- 原选择段排除 bit31 置位的行及类别位全零的行。
- 原 `0xfe052258` 之后，完整类别位组 `0x07000000` 走跳过路径；类别5继续。
- 对继续的行，原 `0xfe05227c–0xfe052294` 计算 `AP暂存基址 + row.start - context.CP区间起点`，随后以路径和目的地址调用 `0xfe059e20`。

参考初始化代码由基键 `0xfa0006` 加偏移取得 `0xfa0080` 表、`0xfa01d0` 起点和 `0xfa01d3` 末端；末端减起点写入 context+`0x220`。这些字段来自原指令，不从日志名猜测。

## 原默认值支持一个有边界的参数投影

对已封存、校验通过的两份原 FX3 默认记录仅读取相关属性：

| 来源 | 属性 | 原默认值 |
| --- | --- | --- |
| 第一记录 AP 默认 | `0xfa019a` 暂存基址 | `0x412000000` |
| 第一记录 AP 默认 | `0xfa019b` 声明容量 | `0x2a00000` |
| 第二记录 CP 默认 | `0xfa01d0` 区间起点 | `0x808730000` |
| 第二记录 CP 默认 | `0xfa01d3` 区间末端 | `0x809a21e00` |

原 CP 表有9个类别5行；最小起点、最大行末地址加1恰与上述 CP 区间一致。按原减法，长度为 `0x12f1e00`，小于 AP 默认声明容量。这个边界符合是宿主对具体默认数据的检查，不表示原函数本身保证所有输入安全。

`DmmCfg.bin` 原行起点为 `0x809a08e00`，投影目的地址因此为 `0x4132d8e00`；`cpImg.dat` 原行对应 `0x412a49000`。

**这里明确组合了 AP 默认暂存参数与 CP 默认区间。** 没有证明当前机身选择了这两份记录，也没有证明参考相机运行时使用这些 FX3 数值。两个记录中相反角色的对应字段可为全1，不能任意互换或补零。

## 六个片段结果，而非一次完整装载

每个原行分别检查两个独立片段：选择／栈暂存前缀在原日志调用前停止；地址计算片段从该日志调用之后独立进入。没有为日志函数补成功返回，也没有把二者拼成一次完整启动。

| 原行 | 严格前缀 | 独立地址计算／分类片段 |
| --- | --- | --- |
| `DmmCfg.bin`，类别5 | 在 `0xfe055530` 日志入口前停止 | 得到 `0x4132d8e00`，停在原文件装载入口前 |
| `cpImg.dat`，类别5 | 同上 | 得到 `0x412a49000`，停在原文件装载入口前 |
| `tomco.txt`，类别7 | 同上 | 在原类别7跳过日志前停止 |

所有输入行逐字节取自原默认表。只声明路径指针、表索引／计数、原固定日志字符串地址、CP 区间和 AP 暂存基址；BSS／磁盘／硬件／查询成功回复均未提供。严格前缀只写一次 guest 栈，后续片段没有内存写入。

首版检查把栈也设成只读，原栈保存指令被拒，断言没有通过。原脚本和失败记录保留于 `attempts/`。修正为允许原栈保存、未知栈读取继续拒绝；完整前缀仍停在未执行的日志入口，后段仍明确是独立片段，没有通过伪造返回值越过边界。初版无效访问统一命名为 unmapped 的表述也已在新记录中改为记录实际访问类别。

## CPIR 不是已证明的整个 CP 内存映像

原 p8 FAT 中 `cpImg.dat` 为1,772,736字节，SHA `76af47a5f97470c396c9d0edc576e2bd31b808e8242d742f7722c6f9e90d91c9`。其魔数是 `CPIR`；原 CP 程序也含比较该魔数、取表偏移／数量、逐记录推进的代码。

本轮按原字段恢复500条、步长20字节的描述记录，载荷起点 `0x2740`；500条载荷长度总和加起点**恰好到达文件末尾**，没有未解释的尾部。474条记录满足“两个16位字段作尺寸候选、双字节平面且行距按16字节对齐”的长度关系；其余26条带有不同后续字段。未擅自给像素编码命名，也没有将这些记录当作 CMOS RAW 或完整 CP RAM 转储。

完整未修改的43,320字节 `DmmCfg.bin`，在该 CPIR 和原 `cpapp-b.bin` 中均没有明文整文件匹配。这只排除该精确字节形式，不排除压缩、编码或其他来源。

9个类别5默认行中，只有4个路径在本次已取得的 p8 FAT 目录存在。其余5个未在该目录出现，不等于整包或机身没有它们；其他分区的同名文件也不能自动当作目标 p8 的实际内容。当前不能用公开 p8 子集补零拼出一个“完整 escape 映像”。
