# FX3 运行时初始化与官方默认速率3

2026-10-29；经典 ILME-FX3 7.02；本轮仅普通本机文件与公开来源。

**FX3早期链路的离线参数候选现有官方默认值依据：速率字3、通道0、GPIO端口4／位2。** 新增速率属性为 `0x51002C`：11份经典官方模板的两记录共22项都为3；公开A7 IV启动块中同项也为3，原加载器确实把它读入用于SIO速率寄存器的字段。该结果缩小了209轮“19与3如何选择”的疑点，但不是当前机身实际设置或运行频率证明。

[候选参数文件](FX3-early-link-profile-candidate.json)只是数据说明，不含可执行载荷、机身接口或刷写后端。Linux官方刷写程序的固定请求19单独保留；没有把它认作早期加载器的默认值，也没有声称两种环境频率相同。

## 参考加载器怎样消费该属性

公开参考是固定提交的 [ILCE-7M4-RE](https://github.com/DavidBuchanan314/ILCE-7M4-RE/tree/e85e137fc3b88b7cb26e69faa9f1304184678ff7)，不是当前FX3同机备份。其原SRAM镜像中：

- 0xFE0535C4—0xFE0535D4构造属性ID0x51002C，将0xFE06A934作为输出地址交给属性读取函数；事务函数随后读取该字段，写SIO+0x14／+0x18。
- 该读取失败的选中分支返回2，**没有自动回退为速率3**。3的依据是实际属性数据，不是错误处理分支。
- 属性读取器的BKSB路径按12字节表项查询；指针帮助函数读取单元0xFE040110，公开镜像中该单元指向0xFE048800。
- 0xFE048800处BKSB有66项，逐项范围检查通过。速率项的数据位于0xFE048B48，4字节值为3；主通道／GPIO项也为0／4／2。读取器选择BKSB格式的运行条件仍是条件路径，未执行真实启动。

当前官方NOR内部归档包含 `LdrBkupList.txt`，共65个属性，明确列入0x51002C及上述SIO/GPIO相关ID。实际核对的归档4个文件为loader、属性列表、配置和md5；外层清单及该内层归档未见 `LdrBkup.bin`。**这个检查只说明所审查包的成员范围，不说明相机没有该启动数据。** 当前FX3同机BKSB仍未取得。

## 当前NOR中找到的第一个赋值阶段

当前加载器的初始化程序在0xFE04C6F0读取一项32字节区域表：目标0xFE061E00，长度7,480字节，处理函数0xFE04C750。该处理函数将w0设为0，按4字节写目标并递减长度，直到长度为0。

因此在**执行这条C初始化路径的条件下**，范围 `[0xFE061E00,0xFE063B38)` 会被清零，包含速率0xFE0625CC和相邻通道／GPIO字段。区域表结束后转入运行时入口，再可见主流程调用。这解释了为何不能从原文件末尾没有对应初始化数据就认定这些RAM字段不存在。

这个初始零写入不是最终所需的速率配置。当前NOR怎样在后续把官方默认属性或其他设置装入这些字段，仍未闭合；不能将“默认属性是3”写成“已证明这台机身启动后就是3”。还需当前配置消费路径、SIO父时钟／分频与实际入口验证。
