# FX3 DMM 模块、回复长度与配置适用范围

2026-10-27，仅 Mac 离线。**从同一官方固件提取并核验 dmm.ko / DmmCfg.bin，定位命令0x20分发表与0x61003c队列；原回复长度和 Unit Open 两个叶函数共36例通过。** 本轮未运行内核模块初始化、消息服务、真实分配器、锁或相机；硬件主录与恢复仍未验收。

## 新证据改变了什么

1. 原模块的普通/同步命令表均把0x20指向 `.text+0x5488`，其路径调用原单位分配，再按标志调用 Open。模块接收及同步队列注册原指令使用0x61003c，与此前MPR发送目标一致。这建立静态对应，不代表真实驱动已注册或端到端传输已完成。
2. 原长度选择函数对0x8020等类型、数量1至12计算 `0x18 + 16×N`；0或大于12时回到0x28。**这个函数没有提供8块上限，也不能把返回0x28理解成已拒绝异常数量。** 阶段127的1至8限制仍只保护MPR调用者的0xa8输出与附加字段布局，不予放宽。
3. 普通 Unit Open 在声明的有效状态/句柄下增加打开计数、更新状态，再填写块数和地址/大小；这是有副作用的函数。0x1001标志在所测叶函数条件下不改变该计数，也不能因此批准真实协议查询，外层消息/日志/调用者仍未验。
4. 无效代次或保留索引返回错误时，原叶函数可以保留旧数量存储；另外一些拒绝路径会写零。因此必须联合验证状态、来源、数量、长度和所有权，不能把零值、残留数量或局部返回当成安全/资源有效证据。

## 配置文件不能直接套用

提取来源为已验证官方大小/CRC的分区镜像，逐个重新核对SHA256及CRC；只读文件系统解析，不挂载、不执行。`dmm.ko` 为118336字节，SHA256 `1e28a4921b36cd8866330a6670d72627d347c556dbea8568cd5b3ab60853e65a`。

`nflasha8:/DmmCfg.bin` 为43320字节，尾部版本串为 `for ilc8g8g-ipsxcp       2025/02/10 10:35:08`。按原初始化函数所读80字节组头、20字节记录、终止标记、单位表及44字节版本布局，宿主有界解析恰好消费完整文件：1组根记录、164组规则、348个单位；这些单位各引用1个extent。

但阶段126四种DMM模式涉及的 **20个目标单位号在这348个单位中均不存在**。这个配置的身份和运行时适用关系没有建立，不能用“其单位都只有一块”推断目标录制链不会超过8块。

原模块元数据和 `__param` 重定位将 `DmmConfig:charp` 绑定到 `.bss+0x18`。原配置读取器从该字段取得文件路径；原初始化回调申请0x25800字节并调用它。**本轮没有取得实际启动参数、没有读取机身文件，也没有执行这些内核/文件服务。** 下一步应定位官方启动链实际传入的DmmConfig路径或加载来源，再解析与目标单位匹配的配置。

## 验证边界

- 21例原长度计算：类型0x8020/0x8028/0x802a，数量0/1/8/9/10/12/13。9、10、12块分别得到168、184、216字节；13块回退40字节，而非返回错误。
- 15例原 Unit Open：覆盖1/8/9/12块、普通/独占/0x1001标志、代次错误、保留索引、饱和计数、状态和标志拒绝、零块对照。原代码只在客体中对声明的单位/extent记录做标量读取与复制，地址没有映射到设备。
- 仅为两个叶函数所需的两处本地ABS64字面量绑定客体rodata/bss；其它原指令字节保持。**不是完整模块重定位、装载或Linux启动。** 每例核对SP、保存寄存器以及允许输出区之外的栈、scratch、原text/rodata/bss保持不变；描述项的未写填充及尾部也逐字节核对。
- 5个截断配置输入均拒绝。配置布局为原指令支持的宿主解析推断，未执行完整原配置解析器或验证运行时采用该文件。
- 两次本地工具失败保留：测试最初将0x802a误列为固定长度，依据原跳表修正；随后修正Unicorn Python接口要求bytes而不接受bytearray。正式源/结果另存，原固件未改。

目标仍为经典FX3 7.02的1920×1080、30000/1001、HEVC42010约16Mbps MAIN，精确30.000另列。实际编码/文件/音画/长录/冷启动、同机备份/受限恢复回读和独立救援均未通过；16项要求状态、Mac-only限制、相机授权以及旧前后端保持。
