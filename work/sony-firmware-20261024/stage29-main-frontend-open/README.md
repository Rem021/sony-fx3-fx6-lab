# FX3 主录前端的排队、参数保留与 SET_REC_FORMAT

本阶段在明确的数值状态前提下运行了主录前端Open分支。**它并非在所有已查分支里都强制重建视频参数：状态2的复制片段保留了目标0x98字节参数；状态0/1则可能只把Open排队，返回1。** 另一路 `SET_REC_FORMAT` 消息确实有参数重建逻辑，实际调用顺序、参数合并和最终硬件接受仍未闭合。

14个场景通过，均为原指令与明确客体前提。没有执行完整前端配置事件、任务钩子、资源/VCD、硬件编码或恢复。1920×1080、30000/1001、HEVC420 10-bit约16Mbps MAIN尚未达到可用或安全刷入标准。

## 返回1可以只是排队

本轮沿上一阶段已绑定的索引0构造收尾，进入原编码入口和ext-ISP前端。内部Open表位于0x35ce58。数值状态0/1的guard为常量真，next保持自身，动作调用0x13bc4c。

动作会比较事件中的源标识参数与配置中保存的MC标识：

| 明示前提 | 原局部行为 |
|---|---|
| state0/1，源标识参数不同于MC标识 | 把0x38字节事件复制到前端+0x18，登记到前端待处理槽，内部处理返回0，外层零值比较返回1 |
| state0，源参数与MC标识相同 | 立即转交状态包装器；本轮在任务钩子入口停止 |

目标MAIN和非法codec/frame两个对照都可以走排队路径。源头部与0x98视频参数不变；排队事件中的参数指针仍指向原参数区。状态机内部的busy标志在局部正常返回前清除，但前端的待处理槽仍持有请求，因此不能将这个busy清除或返回1解释为硬件已经打开。

不同标识对照使用0x810b0768作为明确fixture，同标识使用0x805700f9。**这不是实际发送者读数或实机状态；OSAL注册、来源和共享/物理地址传输仍未执行。** 运行从“消息指针已可用”的前提出发。前端待处理槽的后续出队、配置事件与完成通知还需追踪。

## 状态2保留原视频参数，状态8另有原始flag写入

数值状态2的动作0x13bb98把原0x98字节参数分别复制到前端+0x120、+0x1b8，并复制一份作为后续事件参数。目标HD、原UHD控制和非法codec/frame三个场景都确认逐字节一致，然后在子事件处理器0x13dd50入口停止。

当前片段没有将1920×1080改成3840×2160，也没有改变目标codec、帧率、质量等字节。这只证明原复制分支，后续子事件及其副作用未执行，不能外推整个前端始终保留参数。

数值状态8的另一个动作0x13bd24，在子事件调用之后含有packet+0x88=1的写入。一个独立的后调用片段核对了该写入及转交包装器，其他参数字节不变。它没有执行先行子事件，也没有假定其成功或无副作用。后续包装器会如何结合这个flag选择状态、以及真实调用顺序，仍须继续核对。

## SET_REC_FORMAT是另一条消息路径

原入口对CID0x8003作独立分派；其MID1的诊断文字为 `[EXT ISP IF][RcvBB]SET_REC_FORMAT`，随后调用0x13a248构造另一份0xd8字节参数块。不能把这条消息仅称为输入描述，更不能未经顺序证据认定每次用户Open都必经此重建。

本轮核对了其中两类帮助片段：

- 宽高直接从该消息+0xc/+0x10写到输出+0x90/+0x92，即内联视频包+0x68/+0x6a。HD和UHD两个独立场景分别得到1920×1080与3840×2160；这处没有硬编码4K。
- FileFormat帮助函数0x13ab1c搜索原0x39325c的16行三选择值表。其结果随后存入前端+0x340，重建尾部写入输出头部+0x1c。这一张表的输出集合没有15/18，但它不是完整编码能力表，也不能据此断言真实MAIN HEVC会被拒绝：尚未确认有效消息的来源、值、顺序，以及它与原Open参数的组合关系。

完整重建、合法的HEVC SET_REC_FORMAT输入及其生产者尚未执行或绑定。后续实现必须核对原MAIN参数与SET_REC_FORMAT、管线和前端状态的一致性，不能只让其中一份参数看起来符合目标。

## 29.97与精确30.000仍须分开

SET_REC_FORMAT的0x13ad70帮助函数先做整数除法，再按商值映射枚举。原指令对照如下：

| 输入有理数，原progressive输入为1 | 该帮助函数输出 |
|---|---:|
| 30000/1001 | 3 |
| 30/1 | 5（默认路径） |
| 60000/1001 | 5 |
| 25/1 | 2 |

精确30/1得到的5只是此函数的默认枚举结果；不能解释成相机会实际录成60fps，也不能解释成整机已经拒绝精确30。当前完整目标继续以30000/1001为主，精确30.000fps单列，不能用“名义30”掩盖差异。
