## 固定评审的候选

[probe-plan.json](probe-plan.json)只定义下列顺序，没有发送器或可执行上机入口：

| 顺序 | 操作 | 固定边界 |
|---|---|---|
| 1 | Senser START | 0字节控制传输，setup为4301ff37aad70000 |
| 2 | 请求一次挑战 | 516字节OUT，命令1，载荷全零 |
| 3 | 接收一次挑战 | 516字节IN，2或8仅作为公开参考响应码 |
| 4 | Senser STOP | 0字节控制传输，setup为430100c855280000 |

不提交命令3的摘要或命令5的认证完成请求，不进入文件命令、DMM、上传或固件操作。候选总预算10秒、单次原生调用最多1秒；这些是调用前后检查，不能中断已经阻塞的系统调用。没有重试、重置、强杀或自动切模式的替代路线。USB报错/超时和状态不明不能被当作“没有生效”或“退出成功”。这些边界仍不足以放行，不能直接照表操作。

## 为何在第一步就不满足当前范围

固定[PMCA维护者源码](https://github.com/ma1co/Sony-PMCA-RE/blob/a82f5baaa8e9c3d9f28f94699e860fb2e48cc8e0/pmca/usb/sony.py)中START/STOP的参数，与FX3 7.02原libInfraUsbCmn.so的1d460处16字节完全对应。原创建函数装入这一对配置。原usbg_sen.ko回调对匹配的两个控制头共用后续路径：先调用usb_gadgetcore_stop_other_driver；返回0时尝试usb_event_add_queue，然后仍返回常数2，不检查投递结果。

因此，**省掉认证摘要和后续写命令，仍不能去掉START本身的驱动/事件影响。** 同样，STOP请求也不能被当作已证的无副作用查询或实际退出证书。这里没有证明机身必定重新枚举、一定切到某PID或实际产生持久写入；确定的是“不改变驱动状态”的保证缺乏依据。

上述原件事实在138/145/146阶段已经保存。本批的新增成果是将它们重新绑定到这份明确的4操作方案并作出否决，不把复用旧事实计作新的运行发现。[原字与来源绑定](source-binding.json) · [核对代码](audit_minimal_plan.py) · [机器可读结论](decision.json)。只解析字节和AST，没有执行Sony、Linux、glibc或下载的相机代码。

## 下一次实际验证需要什么

已有的[195号仅主机对照固定方案](../stage195-root-host-validation-plan/README.md)准备了root与普通用户之间的实际身份、自读程序及受保护回执核对。它无需相机，没有IOKit/USB/Sony后端，当前仍未执行、未重新申请或批准。固定批准包SHA为00f983286fea58a429ff829887a1a65230cff817b51a4b5447c1a63b1a47f1d0。该主机验证即使通过，也不授权或证明相机操作。

实际相机试验必须另有固定程序，明确可能影响USB驱动/会话的范围，并具备原生主机控制端、单次权限、当前身份、在途调用处理、实际退出与驱动归还证据。现有主机原生入口仍未放行，当前MSC初始认证/挑战处理及真实返回也未闭合。

对这条“不切状态的Senser最小诊断”到此结束离线推进。没有新的主机/机身证据或不同接口时，不再为同一候选追加模型、包装器或重复核对。重新做普通描述符查询也不能替代上述前置。后续应报告具体等待条件，而不是继续增长阶段编号。
