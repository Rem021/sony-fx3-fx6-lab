# FX3 直接加载构造函数入口适配依据

2026-10-30。**FX3 7.02有一条与脚本插件线程不同的直接加载分支：固定库文件写入后dlopen，成功则dlclose，中间没有dlsym。** 这为下一版的构造函数启动器提供了具体原厂调用点，尚未证明实机上传、加载、退出或恢复可用。

## 对上一轮结论的补充

第229轮分析的Create/Load/Run/DestroyScriptI对象及停止条件，对独立的jit_thread路线仍成立；**完整脚本接口不是所有加载路线的必要条件**。不能将该线程的合同当作直接文件写入分支的唯一前提。旧记录原样保留，以本轮的路线区分限定其适用范围。

第227轮候选仍不能直接使用：其构造函数只写内存标记，实际任务靠显式step推进。直接分支不会调用step/status，也没有为该候选提供主线程、反复调度或可靠退出观察。要适配，应调整启动与完成架构，不能简单改名上传。

## FX3 原件中的两条直接分支

[原始指令核对](direct-entry-audit.json)重新读取同一官方包保存的libJiritsu.so，完整解析三个函数、独立核对16个调用。原件SHA256为`bdef58b24a3b67b4d14d4f0214b89aae0fcad19f114b4188c328f9d2c092f1d9`，没有运行这些函数。

| 原函数 | 固定路径匹配后加载 | 成功后的卸载 | 中间dlsym |
|---|---|---|---|
| adj_cmd_set_file | `0x8f1c` | `0x8f60` | 无 |
| adj_cmd_set_file2 | `0x9908` | `0x9928` | 无 |

两处都使用`/tmp/jiritsu/libJit.so`和flags=1。普通路径先open/write/fsync/close，完整写入长度比较和路径相等分支之后才尝试加载。因而加载失败并不意味着文件未写入。第189轮所证父目录flash挂载及非只读标志仍保留；这不是纯RAM投放路线。

[glibc 2.25原文](https://github.com/bminor/glibc/blob/glibc-2.25/elf/dl-init.c)的初始化处理先调用DT_INIT，再遍历DT_INIT_ARRAY；无须先有脚本接口导出。该源码支持加载语义的解释，不能代替Sony加载器对我们ELF的实际接受测试。候选构造函数若长时间工作，会延迟此同步加载调用返回；若直接exit，会伤及调用它的服务进程。

## 公开实例的可借鉴部分

固定[chocotan/a7c2-re提交2f66a0c](https://github.com/chocotan/a7c2-re/tree/2f66a0cd9732dd7900582e0213b5adb7761c4d1e)，取得libJit报告、C载荷、构建与请求文本；另固定[FireHydrant提交f4e3284](https://github.com/Himpq/FireHydrant/blob/f4e328425386bb1578cc5651f44dea0fa9685cf5/DEVICE_CHANNEL.md)的A6700通道说明。它们属于相关机型经验，不是FX3复现。

公开C构造函数以裸系统调用创建不共享地址空间的子进程，父端迅速返回，子端exec动态shell。这个结构解释了如何避免把长任务留在同步加载函数内；源码没有等待子进程。我们没有编译、导入或运行该载荷。

FX3适配不能直接采用其通用shell、自删／清理同名文件或脚本末行状态作为结束证明。固定任务、完整镜像绑定、同机健康备份、私有完成通道和独立退出观察仍需实现；原厂回收器可能取走普通子进程退出状态的问题没有消失。父端dlclose也不代表子进程已停止。

## 容量与页大小不能跨机型照抄

A7CII请求源码的MAX_UPLOAD为5MiB、工具自身MAX_PAYLOAD为256KiB；A6700文档则写单次上传65536字节。FX3的5MiB比较位于action=0xff缓存分支，不能拿它证明普通文件写入的通用上限。现有227模块262936字节比上述A7CII工具的载荷护栏多792字节，但这不是已测得的FX3拒绝结果。

已保存FX3参考GPL配置声明PAGE_SHIFT=12及4KiB页，适合作为后续缩小ELF对齐填充的依据；它不是这台机身当前内核的读取结果。实际传输分帧、分配、长度、加载和页大小兼容性仍需独立验证，不随意扩大主机上限。

## 下一版的具体方向

优先实现直接加载用的受限构造函数启动器：初始化只做有界身份／任务检查，拒绝缺失或不匹配的任务；把固定工作交给不共享地址空间的自写子程序后尽快返回。还需解决父端已卸载时的私有完成观察及独立退出证明，保留全局防重复、镜像／请求绑定和失败UNKNOWN，不复制公开通用命令执行器。

先安排无源读取的入口诊断，再考虑同机健康备份采集；这是完整目标中的入口验证，不取代MAIN1080p29.97 HEVC420 10bit约16Mbps、exact30单列、实际文件音画长录、访问归还、独立AP恢复及逆写冷启动要求。目前没有准备完可获批的上机实现，也不执行相机试验。

16项要求、全部授权、正式0.4/0.5与23源码保持。195仅主机root01仍未批准／启动；本轮无USB／缓存、管理员、认证、上传、Sony或Linux代码执行、固件写入。目标active，首次刷写未放行。
