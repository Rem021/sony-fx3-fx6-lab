# FX3：原固定消息区、指针域及容量前提

**本轮原指令核对纠正了早期消息指针标注：PayloadMpr `+8` 来自物理/设备域，`+28` 来自映射后的虚拟域；原 Open 的 memcpy 参数使用 `+28`。原 GetFixedArea 类型2读取的是长度 `200`（512字节）的固定区，CreateMessage 不会重新分配它。** 这替换早期阶段23对这两个域的解释，旧封存文件保留，不能再按其旧域标签构造实际请求。

2026-10-27，仅 Mac 离线执行固定官方样本。地址和偏移为十六进制；数量为十进制。相机、Windows、UU未操作，未读取实机 Backup、执行Mmap或发送消息。目标、权限、stage75不可部署原型及16项验收保持。

## 固定区实际从哪里来

原启动调用点 `b7018..b703c` 读取 Backup 项 `fa0028` 与 `fa005d`，将返回值作为 `memory::init` 的基址和长度。它们不是已知实机值；本轮没有执行这些读取。

原 `memory::init`（`2c0be4`）先调用 `memory::Mmap`。Mmap 包装器最终把输入基址放入设备映射的offset参数，返回映射地址；init随后把该返回值和原输入基址分别写入固定记录。这与Linux mmap返回进程虚拟映射地址的接口含义相符，实际驱动和相机地址仍未验收。[Linux man-pages](https://man7.org/linux/man-pages/man2/mmap.2.html)

本轮执行原init序言至Mmap调用前停止，再把虚拟基址作为**独立日志/调用间隙后的声明输入**进入原 `2c0c04` 描述符生成正文。没有制造Mmap返回或执行完整init。物理/设备基址和虚拟基址刻意不同，便于发现互换；它们仅是客体数字。

在声明总范围 `8e00` 下，原指令生成五条32字节记录。原GetFixedArea的跳表顺序与记录存储顺序不同：

| GetFixedArea类型 | 记录位置 | 相对基址偏移 | 原长度 |
| --- | --- | --- | --- |
| 0 | 记录0 | `200` | `8000` |
| 1 | 记录2 | `8200` | `400` |
| 2 | 记录1 | `0` | `200` |
| 3 | 记录3 | `8600` | `400` |
| 4 | 记录4 | `8a00` | `400` |

类型5作为越界控制由原getter返回三个零。原getter的第一个地址输出取记录中的原输入基址，第二个取Mmap返回的映射地址，第三个取长度。不能按记录物理排布猜类型，也不能把第一个返回地址当作虚拟地址。

## 完整原消息构造与域更正

原 Codec Open 序言保留格式、数量和ViewId后，在独立的消息准备入口中，原代码生成单项消息ID `210`；数量大于1时生成 `1610`，长度为数量乘 `98`。随后实际调用完整原 `CreateMessage`（`27deac`）和完整原 `GetFixedArea(2)`，由原指令返回到调用者。

| PayloadMpr位置 | 本轮原来源 |
| --- | --- |
| `+8` | getter第一个地址，原输入物理/设备域基址 |
| `+10` | 数量×98，32位长度 |
| `+18` | CodecType调用参数 |
| `+1a` | 第九个原调用参数 ViewId，从调用者栈读取 |
| `+1c` | 外层FileFormat调用参数 |
| `+24` | 原消息ID |
| `+28` | getter第二个地址，Mmap返回的虚拟域基址 |

getter返回的长度写在CreateMessage的临时局部槽，构造函数未用它作容量准入；它也不是 `+1a`，后者在ViewId0/1对照中由原指令核对。

随后执行原 `282d6c..282d78` 参数准备，停在未执行的memcpy导入前。实际观察到：目标X0等于 `PayloadMpr+28` 的虚拟地址，源X1等于原Open参数指针，长度X2等于数量×98。没有执行这次实际数据复制。

阶段23的消息偏移/外层格式观察保留，但其独立post-GetFixedArea输入把虚拟/物理域名称反了。本轮以原初始化、跳表、完整getter/构造器及实际复制参数替代这些域标签。若沿用其 `GetMsg(out+8,30)` 复制前提，两个域也应随之加8；本轮没有重新证明该外部GetMsg或完整传输。

## 所有权和容量的具体限制

同一客体中连续构造格式15与18的消息，原构造器返回相同固定区指针。原48字节头复制确实保留各自的格式字段，但不产生独立参数区。外层锁和回复流程可能负责串行化，本轮未执行，不能把这个观察定性为实机竞争或复用错误。

原发送序言运行到OSAL分配前停止；原头复制正文另以显式捕获地址运行，未把地址写成分配器返回。暂停中的Codec保存帧保持不变。原数据区复制、OSAL分配、发送/等待/回复均未执行。

三类声明环境都以A5/C3背景核对：

- 完整声明范围 `8e00`：类型2长度 `200`。数量1/2的声明长度分别为152/304字节，落在该记录长度内；数量4的长度608字节超过它，但元数据仍能构造。没有执行超长复制，不能据此指控真实调用者会提交该数量。
- 原ELF的零记录、没有init：完整原getter/构造器仍可返回零指针。未初始化客体不是实际开机状态，只说明构造器本身不建立有效映射。
- 声明总范围 `100`：原片段仍先写出类型2的 `200` 长度；其记录范围超过本轮声明范围。没有执行Mmap，也未核对真实页舍入或外层调用约束，不能当作实机越界缺陷。

这支持后续诊断必须同时核对：真实启动基址/长度、映射、固定记录、请求长度、指针域、所有权及串行化。离线容量比较是研究观察，不是新增的固件校验或已部署保护。
