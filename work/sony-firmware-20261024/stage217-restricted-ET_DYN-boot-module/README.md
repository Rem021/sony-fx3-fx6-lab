# FX3 最小动态启动区模块候选

2026-10-29；经典ILME-FX3 7.02；仅Mac离线构建与自建ARM64装载夹具。持续目标保持active，尚未达到首刷条件。

**已将0.5启动区读取源码编译为PIC，并构建真正包含动态元数据和初始化重定位的ET_DYN候选。最终8项本地检查通过。** 这解决了“静态ET_EXEC不能直接充作动态模块”的格式缺口，没有接通Sony装载器、专用子进程身份、上传、preload安装或真实恢复。

## 构建物与初始化边界

[boot_module.c](boot_module.c)包含既有0.5固定启动区工作器。新增的初始化函数只写模块自己的一个64位内存标记，不调用读取器、系统调用或进程退出；`fx3_module_status`只返回该标记。启动区读取函数保留显式调用，原请求、文件指纹、容量、读取和失败处理规则不变。

[dynmodule.py](dynmodule.py)是隔离在本轮work目录内的限定构建器，不修改已交付0.5的解析器或链接器。输入限固定源码，拒绝外部导入、未知重定位、额外初始化入口、析构器、RWX和不符的节权限。它不是通用链接器，也不是相机启动器。

| 项目 | 当前候选 |
|---|---|
| 格式 | ELF64 little-endian、EM_AARCH64、ET_DYN；没有程序执行入口或PT_INTERP |
| 大小／SHA-256 | 262,936字节；`dcc741e2346fd58ed8f08955244b8c74b10216043c78c4d53d2734f85ccf43eb` |
| 程序头／节 | 8／11；五个LOAD分别R、RX、R、RW、RW；栈不可执行 |
| 重定位 | 100处代码字段链接处理；1处运行时R_AARCH64_RELATIVE，只对应初始化数组指针 |
| 动态导出 | `fx3_boot_read_window`、`fx3_module_status`；无DT_NEEDED或未解析符号 |
| 初始化 | 单个28字节函数，返回调用者；已检查无SVC、BL/BLR或间接跳转 |
| 只读保护 | 初始化指针及动态表位于独立RELRO区，测试装载器在重定位后设为只读 |
| 文件权限 | 0700新目录、0600构建物，不覆盖、安装或自动执行 |

构建物在[最终构建目录](runs-final/built/build.json)留档，另一次独立交叉构建字节完全相同。先前探索构建和首次7项测试均保留，最终结论只绑定当前源码和[最终8项回执](runs-final/receipt/results.json)。0.4／0.5源码包及0.5全部23个源文件保持原字节，本轮未发行新正式版本。

## 实际跑了什么

[test_dynmodule.py](test_dynmodule.py)用自建装载器解释候选的LOAD／动态表，只施加这1处相对重定位，再设置内存权限，以Unicorn运行我们自己的ARM64机器码。它不运行Sony动态加载器、真实glibc、Linux内核或Sony驱动。

- 两个装载地址`0x10000000`和`0x100000000`下，初始化前标记为0，初始化后为固定值。初始化与状态查询均没有系统调用或源节点访问。
- 之后显式调用实际PIC启动区读取函数，各完整读取合成boot0的128KiB，两块输出通过既有独立解码器，返回0。调用前后的栈及callee-saved寄存器均保持。
- 同一实例再入返回10，且没有新增syscall；再次调用初始化也不会清除读取器的一次性状态。
- 文件指纹错误、更新环境标记、迟到返回、清单关闭失败均返回非0，不调用进程exit，不补读或重试。清单存在不覆盖失败返回。
- 用独立测试指令尝试写RELRO区，CPU实际报WRITE_PROT。未知动态标签、外部符号、RWX、重定位越界和额外初始化指针被拒绝。
- pyelftools独立解析动态符号、初始化数组和重定位；Capstone逐条检查初始化代码。

设备、root身份、文件元数据、容量、时钟、tmpfs和syscall均为显式夹具；公开模块仅作为普通本地数据参与原有指纹核验。合成来源和输出为本地文件，不能据此证明真机备份或故障后恢复。

另有一项反例检查：把初始化指针改成另一个合法代码地址，格式检查仍可能通过。因此**inspect只证明格式，不能认证初始化行为**。其相关行为和硬件标志明确为false；本轮行为结论绑定固定源码、构建物SHA及实际测试，不能从任意文件的“格式合法”推导安全。

## 与标准、原加载器的关系

[Arm ELF ABI 2025Q1](https://github.com/ARM-software/abi-aa/blob/2025Q1/aaelf64/aaelf64.rst)用于核对ABS64与相对调整的编码和语义。采用已发布的稳定版本，未把当前main中较晚日期的规范作为本机运行证据。[glibc2.25 dl-init](https://github.com/bminor/glibc/blob/glibc-2.25/elf/dl-init.c)说明初始化数组经装载基址定位，再调用其中的函数；[AArch64装载代码](https://github.com/bminor/glibc/blob/glibc-2.25/sysdeps/aarch64/dl-machine.h)提供相对重定位参考。三份上游文件只读为文本，未编译或执行。

FX3原加载器的版本和局部preload错误处理沿用[190轮原件核查](../stage190-AP-process-launch-and-loader/README.md)。**版本对应和标准格式不能替代该Sony装载器实际接受本候选的证据。** 本轮也未执行原加载器代码。

## 尚未接通的关键部分

专用debug子进程匹配、同机来源、已加载驱动身份、可信启动与退出回执仍未实现或实测。构造函数当前有意不分派工作；在匹配身份未完成前，不能改成自动读取，更不能在主im或无关进程调用exit。原日期触发失败仍可能改变机身时钟，固定libJit路径也涉及持久挂载；本轮没有采用这些路径。

模块继承0.5的范围：启动区读取可能改变硬件访问选择，特定内核失败可能panic；实际数据视图、结束后归还和逆写仍未证。显式导出函数不是操作授权。本轮没有USB缓存／接口查询、Sony认证、模块上传、相机文件读取、管理员程序、权限变更或刷写，也没有新建或删除相机preload文件。

下一步先把FX3原固定子进程参数、真实程序身份与受限分派接起来；在未匹配主进程／其它子进程时保持无源分区访问及无退出行为，并继续核对原启动/返回条件。195仅主机root01仍待具体批准，未启动、未重问。全部16项要求、同机健康备份、独立AP救援、真实目标HEVC主录与长录验收不变。
