# FX3 7.02：原音频/代理参数生成与前端准入补强

2026-10-27。**原应用音频与代理helper现在有完整的局部执行证据；代理帧率直接复制MAIN帧率，但helper不会独自验证格式/码率整组搭配。** 据此更新了自编译guest-only前端：保留已识别的正常声明组合，拒绝未列出的代理组合、音频通道和帧率不一致，原门控/内存边界拒绝保持。

本轮共**151个有界阶段**：原音频/代理和调用者及新前端127阶段、门控回归22阶段、借用外部数据控制2阶段。后两轮复用已经保存的原参数输入，没有重跑或重复计数原矩阵。全部只在Mac文件与Unicorn内存中执行，没有Windows、UU、相机接口、真实配置写入或刷机。

## 原字段及输入范围

原音频helper `APP+0x2e5349c` 写 `MovieRecParam+0x184/+0x188`；原日志名称分别为 `mainAudioParamComb` 与 `mainAudioChannel`。声明输入覆盖默认、两个特殊分支及范围外选择，共40例。局部正常返回产生的二元组为 `(0,1)`、`(1,1)`、`(1,2)`；部分输入进入原诊断前停点。这里没有把数字直接改名为采样率、位深或实际声道数，也没有实机采音。

原代理helper `APP+0x2e50bf0` 写使能字节、VPC、质量、帧率、音频组合与音频通道。32例覆盖类型/质量范围、关闭分支和帧率对照。

| 原选择输入与声明条件 | 原输出 |
| --- | --- |
| 代理选择1或2 | 使能0；VPC13、质量255、帧率12、音频组合5、通道255等哨兵 |
| 代理选择0、格式0 | 使能1，VPC6；质量选择0→6、1/2→26、3→28 |
| 代理选择0、格式1 | 使能1，VPC11；相同质量映射 |
| 代理启用、MAIN帧率3 | 代理帧率3，由原调用者/原helper传递 |

纯原MPR名义码率函数对质量6/26/28分别返回16000/9000/6000；这不是当前编码器或文件码率回读。原类型表的VPC6尺寸为1920×1080，VPC11为1280×720。

这些输入数字不是用户菜单序号。尤其是helper还会把声明帧率12复制出去，并可局部生成VPC6/质量28、VPC11/质量6。**局部返回不等于有效的整组参数。** 官方代理设置仅列HEVC HD 16M/9M及AVC 720p 6M，本轮前端只保留与这些已列组合一致的声明配对；不能据此判定固件全部路径都接受或拒绝某组合。[Sony代理设置](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000882045.html)

## 原调用者到前端的数据

12组调用者实验先执行原MAIN序言，止于首个日志；再独立执行其原448字节memset（绑定同固件原libc）；最后从明确的独立MAIN正文入口继续，**在原调用点实际调用音频与代理helper**，止于后续模型诊断前。

MAIN核心仍是原应用生成的 `[5,6,3]`。原helper生成的音频/代理字节随448字节参数跨guest交给新前端。成功时原通用MPR函数产生类型6，最终仅主视频类型变化；质量6/帧率3及原音频/代理字节保持。

此前其它初始化、命名/元数据、模型、同步、保存及录制步骤仍未执行。虽然零背景由原memset产生，**未执行的后续写入不能当成正常配置的零值**。这不是完整健康参数快照或实际可录制配置。

## 新增的guest-only准入条件

[新C候选](scoped_frontend.c)沿用阶段116门控和内存边界，并检查原helper已识别的音频二元组。对于本轮目标29.97声明配置：

- 关闭代理时要求相应的原哨兵字段一致。
- 启用时要求代理帧率3、对应音频组合/通道，VPC6仅配质量6/26，VPC11仅配质量28。
- 原生成的禁用代理、HEVC16/9、AVC6声明组合通过；两个未列出的格式/码率配对，以及人工音频通道/帧率不一致对照拒绝。

后续22例在原生成的正常字段上复核magic/控制地址、关闭、代次、调用点、源越界、目标与源/控制区重叠、外部数据三类边界；拒绝不写副本。另两例加入明确声明的48字节外部数据，准备仍通过并保留借用指针，未宣称拥有其数据或已完成保存。

这是我们客体代码的附加检查，**不是Sony菜单校验、可信epoch/空闲状态、物理音频可用性或硬件资源准入**。目标MAIN与代理虽可出现相同VPC6，流角色及后端资源仍须分别验证；不能把代理表等同于目标MAIN支持，也不能全局改变代理质量来配合MAIN的FF临时匹配视图。

旧阶段116仅以不透明字段证明字节保留，其音频/代理数据并非有效完整配置；旧证明保留，新条件不把它提升为可上机来源。阶段75后端与阶段116已封存文件未修改。

## 复核及当前限制

原APP、MPR、libc和Sony指令保持。自编译对象只有自身CALL26/地址跳板链接；原memset、helper和复制函数执行原指令，不伪造日志或成功返回。逐阶段核对栈、scratch与整个APP/libc映像边界；三份运行结果按各自源码及对象哈希封存。本轮没有失败重跑。复核由同一代理完成，不是独立引擎或实机验收。

[Sony主录设置](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000868278.html)本轮同时复查；公开XAVC HS 4K设置不能作为新增HD29.97 HEVC MAIN能力证明。

全部16项状态及当前授权保持。仍缺完整源参数、真实目标选择/同步/代次、16M模型与编码的一致性，以及实际成片、音画同步、长录温控冷启动、同机健康备份、受限恢复回读和独立救援。当前没有可安全刷入版本。
