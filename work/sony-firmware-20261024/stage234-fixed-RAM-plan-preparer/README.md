## 固定功能和配置

[prepare.c](prepare.c)只支持生成231格式、purpose=1空操作计划。构建器内嵌固定工作程序SHA256 `c711f6ab…24c47ec`、长度131864、测试nonce和关联字段，期限60秒。当前配置都是人工值，**没有把关联字段当成真实机身身份或用户授权**。构造函数不启动工作程序，不访问boot设备、卡片、素材、USB或固件。

准备程序先核对参考im完整SHA、root身份、当前库文件完整性及加载的只读字节。自身完整性使用完整文件的规范化SHA，仅把固定32字节校验字段清零；文件的完整SHA另写入暂存回执供未来主机比较。规范化自校验只能证明自洽，不能认证任意改写后的程序；未来投放仍须核对固定完整二进制、真实身份和传输绑定。实际Sony加载器是否接受ELF仍未知。

## 创建与发布顺序

1. 核验`/tmp_wbshd`是可写tmpfs、属主root、目录权限合适且有足够空间；以mkdir创建不可复用的0700准备目录，失败不接管旧目录。
2. 从目标CLOCK_MONOTONIC生成起止时间。在准备目录以EXCL/NOFOLLOW和明确的O_RDWR、0600创建`plan.pending`，写256字节、fsync、复读、核对权限/稳定性/长度/内容并关闭。权限被umask等改变时拒绝，不调用chmod或改全局umask。
3. 写入并复读`prepare.staged`。它包含完整程序SHA、计划SHA、预期工作SHA、nonce、时间、进程关联和计划inode。阶段固定为STAGED，**不证明已发布、工作完成、资源归还或USB恢复**。
4. 再检查期限，仅调用`renameat2(..., RENAME_NOREPLACE)`发布到固定计划名；遇到已有文件、竞争插入、ENOSYS等均失败，不退回普通rename，不覆盖。
5. 复读已发布计划，要求与原暂存对象dev/inode相同，权限、内容、CRC及稳定性正确。关闭全部本次目录FD后，再读一次时钟，才允许本地状态标记为已准备。

Linux v4.9参考源码固定了AArch64通用系统调用号276、VFS在重命名锁内拒绝NOREPLACE的既有目标，以及tmpfs的标志支持，见[kernel-contract-review.json](kernel-contract-review.json)。[Linux rename手册](https://man7.org/linux/man-pages/man2/rename.2.html)也说明不覆盖语义和文件系统支持条件。没有据此断言当前Sony内核调用可用；不支持时必须停止。
