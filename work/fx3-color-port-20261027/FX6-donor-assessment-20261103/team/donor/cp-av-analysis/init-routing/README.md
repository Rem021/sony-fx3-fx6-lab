# FX6 MLUT 初始化至 DMA 描述构造：限定 CPU 回执

2026-11-03。**已闭合 FX6 6.01 AV 内部的一条具体路由**：原始初始化器以原始 `memcpy` 把 `MLUT_MTX_A_REG_SG3TOAP1_0` 的 152 B 描述符从文件偏移 `0xb83218` 复制到 ACES Rec.709 look 的第 63 项 `0xaa5208`；原始 DMA 列表构造器随后在该项读取数据指针、寄存器偏移与字数，并生成第 63 条 16 B 链表记录。全部工作为静态分析与隔离 CPU guest，**没有硬件 DMA 提交、传感器像素处理、VM 或相机结果**。

## 固定输入与映射

- FX6 `fat-files/nflasha3/av-cam.bin` SHA256 `56684d830eab1e304868548746d8275188a925f9e4ab9354560180c31b4a93cf`，12,939,512 B；每个脚本启动时复核。VA 基址 `0xffffffc001000000` 由该镜像自身 ORIL 头的首指针 `base+0x58` 推导，见上层 `mapping.json`，没有借用 FX3 基址。
- FX3 7.02 对照仅只读此前固定的 `initializer-guest-results.json`（SHA256 `29c76396ae58e8caca2bd96e0eb0408854c163e60556b5d27b4da9d6bd76ab95`）与 `look-consumer-guest-results.json`（SHA256 `6443be58aaa2a547aa7488a7551452ab4ce995bc108e8cb9244f7892b7b84a4f`）；它们原有的 CPU guest 证据不等于真机视频路由。
- 本阶段所有新文件只在 `init-routing/`。既有固件、上层回执、VM、USB、相机与 SD 均未改动。

## 原始初始化器与写域

在零外部参数、固定客体初态下，Unicorn 从 FX6 原字节入口 `0x29f508` 执行，允许 PC 仅落在 `0x29f508–0x2a5964` 和原始 `memcpy` `0xd80–0x1060`；没有替代 `memcpy` 的 stub。500,000 条预算内执行 55,395 条指令，原 `memcpy` 调用 1,166 次，正常返回哨兵 PC `0x60000000`。该**实测路径**的 30,316 次镜像写事件合并成唯一连续区间 `[0xa88bd0, 0xab4020)`，共 177,232 个唯一字节、13 个写入指令地址；客体栈写入另行计数。精确合并区间、写入指令地址和全部 1,166 次调用的源、目标、长度在 `init-trace.json`。这不是所有可能运行状态的全 CFG 写集。

其中唯一一次向 `0xaa5208` 的复制发生在调用点 `0x2a35e0`，`src=0xb83218`、`n=152`。目标 152 B 与未修改官方镜像的源描述符逐字节一致，源区未被写，SP 与 x19–x29 保持。第二轮将写域收紧到实测区间，在整个写域前后各放 16 B `c7` 客体内存哨兵（`0xa88bc0`、`0xab4020`），两端均保持；细节见 `controls.json`。

负例一仅把**客体 RAM** 源描述符 `0xb83218+20` 的 ASCII `M` 改为 `N`，原 `memcpy` 正常把改变传播到目标，目标与官方原字节 SHA 不再相同。负例二把预算降至 1,000 条，执行未返回哨兵且尚未复制该 slot，因此拒绝把它记成通过。两负例都没有修改磁盘固件；所有客体补丁在 `controls.json` 列出。

## 目标 slot 被 DMA 构造器读取

在同一隔离 guest 先运行上述初始化器，再以 look 22 的表项给原始构造器 `0x2a7978` 输入 `ip=0`、`count=70`、首描述符 `0xffffffc001aa2ca0`。该函数执行 6,389 条原始指令，返回哨兵；`dma-trace.json` 逐项核对 70 条 `<I 源物理低32, I 寄存器目标低32, I 下一节点物理低32, I 控制字>`。第 63 项在 `0x2a79d8` 读 `0xaa5210` 的寄存器偏移，在 `0x2a79ec` 读 `0xaa5208` 的数据指针，在 `0x2a7b00` 读 `0xaa5218` 的字数：指针 `0xffffffc001bb1dec`、偏移 `0x200`、字数 13，生成记录 `[0x01bb1dec, 0xf3019200, 0x01c62400, 0x0e48900d]`。70 条记录按原描述符字段全部复核通过，输出前后 16 B `5a` 哨兵保持。

DMA 测试的外部依赖均为**显式客体桩与输入补丁**：将镜像 `+0x20` 的 provider 指针暂改到客体 RAM 表；表 `+0x610` 指向仅记录参数的 cache-flush 桩，`+0x630` 指向按声明公式 `0x400000000 + (VA - 0xffffffc000000000)` 返回地址的映射桩；另写入 70 项输入与输出哨兵。客体只调用 209 次映射桩和 70 次 cache-flush 桩，没有实际 OS 地址转换、缓存操作或 DMA 提交，函数返回后即截断。原字节 `+0x20`、补丁地址、回调输入和桩语义全列于 `dma-trace.json`。

## FX3 / FX6 有效 CPU 路由差异

下表仅对**明确给定的 look 22 CPU fixture**成立；未观察相机当前 MAIN 选项或传感器 RAW 输入。

| 环节 | FX3 7.02 已有 CPU 回执 | FX6 6.01 本轮 CPU 回执 | 可得结论 |
|---|---|---|---|
| look 选择 | 索引 22，`SL3SG3_TO_ACESREC709`，70 项 | 同索引、同名称、70 项 | 查表选择结构一致，真实菜单选择未知 |
| 矩阵前处理表 | `SG3TOAP1_0` 数据指针低 32 位 `0x01c15aa8` | `SG3TOAP1_0` 数据指针低 32 位 `0x01bb1dec` | 13 个矩阵原字与 VENICE 命名表、两机 SHA 相同；指针只是布局差异 |
| 描述符初始化 | 原复制目标 `0xb07ba0`，原 `memcpy` 152 B | 原复制目标 `0xaa5208`，原 `memcpy` 152 B | 同类表被装入不同镜像偏移；FX6 本轮已执行验证 |
| DMA 描述构造 | 入口 `0x2c4794`，第 63 项目标 `0xf3019200`、控制 `0x0e48900d` | 入口 `0x2a7978`，第 63 项目标与控制相同 | 源指针因镜像布局不同；下一节点指针因测试输出缓冲区不同；均未提交硬件 |
| 上游像素域 | 黑电平/去马赛克/降噪与 MAIN 生效路径未闭合 | 同样未闭合 | 相同 MLUT 数据与此 CPU 路由不能推成最终视频色彩相同 |

逐字段原始数值、依据层级和不同缓冲区解释见 `route-diff.json`。既有 29 组 Vintage 描述符差异只属于那些 look 的数据，**不能外推成 FX6 视频色彩全部差异**。`libmpr.so` 的 `RawInfo`/`stillrecord` 仍只归类为静态照片支线候选。

## 复现与下一步

在本目录运行 `sh prepare.sh`，再依序运行 `PYTHONPATH=.vendor python3 trace_init.py`、`PYTHONPATH=.vendor python3 replay_controls.py`、`PYTHONPATH=.vendor python3 trace_dma.py`、`python3 compare_route.py`、`python3 verify.py`。`prepare.sh` 只在本子目录暂装 Capstone 5.0.6、Unicorn 2.1.4；临时依赖在本轮结束前移除，需重现时重装。`run-receipt.json` 对固定原件及四份运行回执重新校核并记录各脚本 SHA。

下一最小阶段应沿该 70 项链表的**实际调用者与 MAIN/monitor 选择条件**追踪，同时以真实固定 RAW 输入/像素输出建立像素域证据；当前不能从 MLUT 描述符或地址转换桩推断传感器校准、ISP 算法和实机结果。
