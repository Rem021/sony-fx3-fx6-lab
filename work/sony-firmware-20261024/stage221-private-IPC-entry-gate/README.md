# FX3 自写ARM64读取入口：私有GRANT／READY／GO门

2026-10-30；经典ILME-FX3 7.02；仅Mac离线源码、编译与自建ARM64／假Linux测试，无相机操作。

**新候选入口默认拒绝缺少私有通道或匹配许可的调用。最终10项检查、44组案例通过；同一源码两次构建一致，完整四窗口合成采集仍能完成。** 这是把第220轮存活监管原则接到工作器入口的第一步，不等于机内全局监管已经完成。

## 入口现在要求什么

[ipc_gate.inc](ipc_gate.inc)只接受继承的198号描述符：root属主socket、未命名AF_UNIX、SOCK_DGRAM，SO_PEERCRED中的root PID／GID须匹配当前父进程。验证这些条件前，不修改socket选项、不关闭可能属于其它用途的描述符；通过后启用SO_PASSCRED并接管这条私有通道。

随后每个进入读取的调用必须完成：

1. 从该通道取得320字节GRANT，核对实际附带的SCM_CREDENTIALS、消息边界、保留字段、CRC、当前PID／父PID、整个handoff与目标单调时钟期限。
2. 通过进程过滤，再读取RAM请求与handoff，逐字节比较通道携带的完整256字节handoff；保留原同nonce／同窗口不可复用占用。
3. 发送READY，再收到同一个handoff的GO。缺少、迟到或不匹配GO均不打开源分区。
4. 调用私有读取组件。调用实际返回后才发送DONE，包括返回码；通道发送或关闭失败不能报告正常返回0。控制通道阻塞或源读取阻塞时，不提前发送完成，不关闭原在途上下文，不强杀、复位或自动重试。

控制消息使用一次定长收发；接收前最多请求一次1秒ppoll，并在返回后核对实际单调时间。超时不补收或重新开始；MSG_DONTWAIT／MSG_NOSIGNAL分别控制当次收发与信号行为。这些系统调用在真实内核仍可能异常阻塞，1秒参数不是真机硬截止保证。

收到额外SCM_RIGHTS即拒绝，并关闭已实际带回的描述符，包括截断标志或接收报错的清理分支。未知／重复／缺少凭据、异常控制头和消息截断均拒绝。不会把收到的描述符当成源设备或许可文件。

## 新的空操作子进程合同

新候选只匹配13字节的`/bin/sh\0-c\0:\0`；旧40字节日期命令在本候选中被拒绝。**13字节是本轮新设计的启动合同，不是对原厂argv的重新描述。** 第218轮原厂日期串的原始证据保留；本轮没有执行shell、日期命令、fork／exec、修改原固件字符串或安装preload。

BusyBox自身与父im参考文件SHA过滤仍在。真实父im身份未观察；候选未来需要由父im内的受控扩展创建通道和调用入口。如果改用独立keeper进程，必须同时重新设计父进程过滤，不能直接拿当前im参考哈希套用。构造函数仍只写内存标记，不自动读取或退出，新的受控启动与显式分派尚未接好。

[模块与handoff派生记录](source-derivation.json)逐处记录对第219轮的修改，其余字节保持；内层读取组件与0.5正式源码未改。动态导出仍只有受保护入口和状态查询，无内层读取旁路导出。

## 仍未闭合的全局排他与授权

[Unix接口说明](https://man7.org/linux/man-pages/man7/unix.7.html)区分创建时的SO_PEERCRED与每条消息的SCM_CREDENTIALS，也允许具备相应能力的特权进程指定不同凭据。因此这些检查用于严格关联参考父进程与消息，**不证明发送方持有全局占用、不证明完整加载代码，也不代表用户批准。** PID／nonce／CRC／SHA均不提升为授权。

第220轮Mac存活监管器尚未与本轮二进制协议连接；机内监管端、原子固定资源域、实际fork／exec及退出观察均未实现。第219轮旧模块保留，其直接并发反例没有被抹除。新模块拒绝无私有许可的入口，但合格root父进程可向多个子进程发许可；没有全局keeper就仍不能保证跨任务排他。下一步必须补真正的共享监管状态和双端协议，明确原子占用／异常保持UNKNOWN／实际子进程退出条件，不能仅凭测试给出GRANT就声称全局问题已解决。

真实受保护路径、root跨UID／同机来源、装载与受控退出、完整备份、启动区数据视图／访问归还、独立AP救砖和逆写／冷启动仍未验证。全部16项要求、MAIN1080p29.97 HEVC／长录与exact30区分保持；195仅主机root01仍未具体批准、未启动。本轮无USB／缓存设备查询、管理员或相机操作，0.4／0.5正式包及23源码不变。目标active，未放行持久刷写。
