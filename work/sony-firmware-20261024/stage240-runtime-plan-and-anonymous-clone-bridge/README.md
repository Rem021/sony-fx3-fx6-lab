# FX3 运行时计划与匿名副本启动桥

2026-10-30。**第239轮分开的父端接收器和隔离监管者，已接成同一段自写 C 启动路径：捕获计划、校验镜像、创建匿名副本和通道、创建两个子进程，再观察原对象的退出。** 8项检查、27个模型场景通过；两次构建完全一致。它仍是空操作研究程序，不能投放相机或作为可刷写固件。

执行只发生在 Mac 上的 Unicorn 中。Linux 的进程、文件、IPC、信号、时钟、内存系统调用和原厂回收者均为明确的自建模型；没有运行 Sony、glibc、Linux 或公开相机载荷原代码，没有创建实际 Linux 子进程。没有新增 USB、相机缓存、管理员、认证、上传、读卡或固件操作。

## 这一版解决的具体衔接

[bridge.c](bridge.c)不再依赖固定的321/5001/53或固定期限。调用者PID/TID来自自己的系统调用，通道FD来自socketpair，外层子PID来自clone；期限、nonce、profile和controller关联来自复制到私有栈的完整256字节计划。协议3的四种消息都绑定完整计划SHA256和当前镜像SHA256。收到并验证HELLO和原进程目录FD后才发ACK；监管者收到ACK后才创建内部空操作工作器。

匿名映射使用内核分配的地址，按64KiB对齐，不使用MAP_FIXED。代码复制并核对摘要之后，分别设置R/RX/R/RW四段权限，没有RWX。外层clone在匿名副本内执行；模型在子进程首条指令前移除原文件镜像和调用者计划映射，子进程仍可依靠匿名副本和写时复制的栈继续运行。子端不返回已卸载的原文件代码。

完整文件为262144字节，SHA256为`0bf01a5c42ea6a7591d30954fea8448d65c45dae28ec2c20b6769e12f188b1b4`。[128处链接地址引用](relocation-audit.json)在5个统一、页对齐的移动量下均保持指令字不变，共640次算术核对；这是本文件的地址审查，不是任意ELF加载器验证。CPU缓存维护、真实栈与映射生命周期仍未实测。

镜像摘要覆盖前三页不可变内容，并将最后一页BSS规范化为零；本次固定文件的第四页恰好全零，所以与完整构建文件SHA相同。**这不校验运行中BSS，更不证明请求获授权或镜像来自可信控制端。** 全部摘要都属于关联与完整性检查，不能作为签名。

## 回收顺序的实际修正

外层使用`clone(SIGCHLD)`，内部工作器保留`clone(0)`。前者才能被已研究的普通WNOHANG回收者处理；后者由独立监管者在其私有子进程域内等待。

父端在创建前屏蔽调用线程的可屏蔽信号，观察到原目录对象的`Z/10752`（正常exit42）后，才恢复原掩码，允许模型中的普通回收者完成回收。随后原目录FD相对查找返回对象已消失，局部状态才可为11。父端不用可复用的数字PID重新等待。早被其它线程回收、未回收、原掩码已屏蔽SIGCHLD，都保持HELD。

恢复掩码失败被记录为失败，**该故障场景会留下改变后的线程掩码**，没有自动重试或恢复成功证明。11还要求关闭本程序已知持有的FD、撤去父端匿名映射成功；它只表示这条空操作路径的局部结果，不能充当全部任务资源或USB归还证明。第239轮接收头复制失败导致未识别FD的UNKNOWN边界继续有效。

## 核验范围和未完成项

[27个场景](runs-bridge-verified/receipt.json)包括四组PID/TID/地址/时钟、捕获后改写调用者计划、完整计划错误、只读页内容改动、准备/保护/clone失败、工作器失败、异常HELLO、早回收/未回收、原掩码屏蔽SIGCHLD、掩码恢复失败和同一已加载副本重放。[重复构建](reproducible-build-summary.json)与当前测试源码快照均已绑定。模型时间由系统调用推进，不是实际CPU耗时或内核硬实时保证。

尚未完成的接入有明确边界：

- `_start`仍是提供模拟计划地址的测试载体，没有Sony动态构造函数。第235轮准备程序绑定的是235的镜像；不能将它产生的计划不经适配就交给240。
- 每个已加载副本的`entered`只防本副本重复进入；新加载会有新BSS，**跨加载全局排他尚未接入**。人工nonce/profile/controller值也没有取得真实控制端或这台机身的认证关联。
- 同一Sony进程内其它线程可能继承端点、回收或改变父域的条件仍未测定。239的两个来源/子域反例保留，不能单凭新模型没有注入它们就宣称全部排除。
- 本版没有boot源读取、结果回传、健康机身备份、独立AP恢复、逆写/冷启动或H.265主录修改。不能用空操作退出成功代替这些验收。
