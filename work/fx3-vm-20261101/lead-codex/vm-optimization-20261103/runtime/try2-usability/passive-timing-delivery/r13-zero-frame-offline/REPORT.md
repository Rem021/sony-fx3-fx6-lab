## 2. 生产/消费路径与启动分叉

实际成员仅seek读取5个：init、gate、timer、preset、capid；四个ELF分别匹配 **v11 gate、v3 timer、preset timing、v49-touch100 capid**。前三个helper源码/编译回执SHA匹配，preset复用r9绑定并重新匹配实际装入ELF；r13的21份宿主observer-source也逐份核回执。CPIO仍为原A/r3，未重新读取整个镜像。r13 preinput hook只位于取到下一输入后的分支，本轮0键且无相关QMP日志，未执行；不能归因新增暂停。

原链已缩到具体位置：注册函数 `0x16f16bc` 将callback注册到消息队列，按原请求值 **20000、mode2** 启动；`0x16f1358` 处理来自0x910040的自然消息并调用payload callback，条件成立时以mode3续期；callback `0x16f1c18` 最后跳到 `0x16f1a48`。后者只增加a18一次，然后分配28B、构造150000/source830128并发送到5503e0。**v3 timer helper包装的是另一个widget回调，没有自产150000循环。** 未闭合原服务端完整计时单位/注册实例数，不能只用20000推出确定频率或重复定时器。

id9计的是原增量store前命中，不等于send成功；id10仅在原source830128/type150000匹配后减量store前命中。id11统计所有取包，`timer_dequeue=5741`是对同批150000的另一观察，**不能再加到id10当第二批消费**。count11−count10=27，既有其他发送路径有25条`0x2eacd4c`及2条`0x16f10b4`尝试，与不同消息路径相容，不是证明少减27。

所有已打印id9/id10/id5样本同一root `0x7ef355cd60`；生产在uipc_proxy_0/1/2/3（tid240/241/242/245），消费只在AppFw tid377。四proxy是callback工作线程，不能据此称四个定时器。全局count没有按object分桶，未打印事件不能逐条证明同对象；现有单次UI初始化、同root样本及原callback参数支持单root解释。8831−5741=3090接近last3091；probe在store前、镜像非事务，差1不是损坏证明。

原task stat（例如r13 LF10309/10310/10313/10320、10493）显示proxy policy2/rtprio6，AppFw377 policy2/rtprio1；成功运行也如此。UI线程累计utime/stime持续增加，不能称整线程死锁；也不能仅凭优先级确认它被饿死，没有ready等待时间或helper耗时归因。

最具体且可逆的辅助层问题是 **未采样的持续镜像成本**：`fx3-ui-gate-v11.c:12` 的mirror每次atomic读取96Q、写768B、执行两次dmb；`:78–89` 每个id<12都调用，`boot_event():63/70` 即使id40已不打印也仍调用。r13实际count40=5768，不能漏算。

| r13镜像核算 | 数值 |

| 生产id9的mirror调用机会 | 8831 |

## 4. 最小可执行候选设计：精确计数与发布分离

**首要两假设**：H1为gate全镜像使单UI消费者吞吐不足；H2为原定时服务/代理积压释放及调度导致生产节奏超过处理，mirror不是主要限制。无CPU耗时分解，现阶段不能选定其中一个；不再扩大反汇编或增加大日志。

下一步仅需独立制作以下**未实施**的观察候选，目标文件是 `fx3-ui-gate-v11.c` 的 `struct statistics st`、`mirror()`、`fx3_gate_event()`及`boot_event()`，与宿主 `optional_paused_snapshots.capture()` / 独立读取解析器：

1. **唯一权威统计源**改放既有64KiB预留区未使用的 `+0x3000` 新布局中（例如64B身份头，`+0x3040`起原96Q statistics，结束+0x3340；独立实现须再审地址不碰两bank/boot等记录）。保留每次原probe的精确atomic计数、原hist/TLS decision、字段及原Sony指令/寄存器/返回/errno；不是另写一份易失配的影子计数。新头明确magic/version、pid、root、布局长度和绑定状态；记录object不匹配计数，补足当前全局count身份缺口。
2. **仅降低镜像发布频率**：候选两种模式N=1/N=64，来自相同权威统计源，用全局访问序号决定发布。原bank保持有序双bank复制及dmb，声明它是采样视图；不删原消息、修改timer/阈值、改线程优先级/亲和性，也不同时调整capid/preset日志。N64理论上大幅减少完整复制，但成本改善须实测。
3. **暂停态新鲜度不依赖N**：QMP stop ACK且query-status paused/running=false后，宿主独立读新权威区，核magic/version/pid/root/bound，再读第二遍确认字节一致；它是每个probe直接更新的源，**无需新周期线程或guest flush协议**。可能暂停在probe中段，仍按逐字段非事务状态解释；旧bank的publication再新也不能替代权威区。缺失/布局未知/不一致必须报unknown，尤其全零OSD ring时不得把旧bank当实时末态。
4. **先离线验语义，再决定运行**：同一固定原程序、硬件/型号/配置及5000ms合同，N1/N64只差发布频率；先用受控probe序列核两模式所有权威计数/branch输入一致。必要反例含N−1次后立即暂停、暂停在probe中段、生产者在最后发布后继续、0/2/3及signed负值比较输入、多proxy交错、object不匹配和OSD全零；最终权威值不能退回陈旧bank，且原调用参数/返回/errno/GPR/SIMD/NZCV不变。当前没有执行这些测试。

如另获运行授权，仅用固定、短的零键启动窗口比较权威Δid9/10、a18低水位与id7/8机会，不为等画面延长长跑。若降低镜像后消费明显追上、低水位恢复且生产节奏无对应下降，支持H1；若镜像已减少但原流量/消费差与零机会仍相近，削弱“mirror单独是主因”，优先H2。一次A/B仍不是因果证明，阴性结果也不排除其他日志开销。此候选修的是观察辅助层的持续开销，**不是已验证的零帧/菜单修复**。
