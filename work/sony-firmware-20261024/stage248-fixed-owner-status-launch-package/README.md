# FX3 单次USB接管与归还诊断方案

本方案只验证Mac端能够受控接管FX3的MSC接口并归还驱动，不修改相机固件。构建、单次随机标记、设备节点及许可文件固定在本目录；须有新的具体授权才可执行。**当前未获批准、未启动，不可据此刷入固件。** 代码与离线检查以本目录verification-receipt.json为准。

## 本次拟执行的范围

标识为fx3-702-owner-status-20261030-11，范围MSC_OWNER_STATUS_ONLY，最多一个root helper、一次尝试。固定目标是Mac缓存中的054C:0DA1、ILME-FX3、端口0x01100000和节点4294982508；位置或节点改变即拒绝，不自动改端口或重试。

执行时会打开Terminal，必要时由用户本人完成一次sudo或Touch ID。只在Mac内置盘/private/tmp/fx3-702-owner-status-20261030-11及/private/var/root/fx3-owner-trials中创建固定程序、许可、数据页、Unix连接和记录。安装程序0500、许可0400、root目录0700；已有目录身份或权限不符时拒绝，不自动修改旧目录权限。旧的195号HOST_ONLY授权已经消耗，本方案不接受它或旧05号授权。

程序先核对实际root进程、用户501的图形/TTY归属、程序自读摘要、固定父进程和单次nonce。通用native标志仍为0；仅本固定状态诊断可通过root私有许可入口进入。许可绑定本次nonce、目标端口/节点及一次调用上限，root entry.once和新作业记录共同阻止重放。

## 相机相关操作

1. 执行前由用户在Finder手动推出相机所有卷，保持相机开机、MSC及当前端口/数据线；程序不替用户卸载卷。
2. 获准后的启动器先读Mac USB缓存核对固定节点。root helper再次核对缓存节点和挂载状态，在任何USB插件/接口打开前拒绝节点不符、仍挂载或状态不明。
3. 为前后机身一致性，helper只在内存中用本次固定密钥对USB缓存序列号做HMAC。原序列号不写记录；该标签不证明相机固件身份或相机认证。
4. 明确执行一次USB设备接管，可能暂时断开存储驱动；尝试打开接口0，核对81/02端点与管道编号。没有驱动安装、自动复位、配置切换或Sony模式命令。
5. 父进程只发送本机OBSERVE、STATUS、END三条消息。入口拒绝START/AUTH/STOP；程序不发送Sony控制或批量数据命令，不读取卡内文件、素材或相机固件。
6. 关闭接口，使用限定的ReleaseDeviceMask归还设备，关闭设备并核对原机身标签与驱动缓存基线，再通过原本已核验的连接返回私有结果，独立观察原helper是否退出。预算是20秒工作、30秒最终观察，不强制中断已阻塞调用。

若出现阻塞、超时、身份变化、回执不完整或归还不明，保留UNKNOWN和同一实例，不强杀、不重置、不自动重试。接管不改固件，但设备/驱动调用仍可能挂起。若出现系统隐私提示，由用户自行选择；程序不自动申请或修改权限。实际相机屏幕状态须另由用户观察。

## 交付文件与边界

- [fixed-plan.json](fixed-plan.json)固定构建、nonce、路径、目标和操作范围；[approval-bundle.json](approval-bundle.json)列出批准对象与摘要。该包生成后不改写。
- [native_factory.py](native_factory.py)在任何缓存查询、作业创建、Terminal或sudo之前检查新授权及完整包摘要；[run_approved_status.py](run_approved_status.py)是获准后的唯一启动入口，当前不运行。
- [status_permit.c](status_permit.c)核对root私有许可；[owner_iokit.c](owner_iokit.c)在打开设备前落实节点准入并建立私有一致性标签；原有状态消息白名单保留。
- 246阶段已实测的HOST_ONLY身份与回执组件提供复用依据。本新构建尚未在root或真机执行；普通用户夹具、许可文件检查和CPU帧检查不代替真实USB验收。

通过本诊断只表示限定主机接管/归还链取得证据。Sony认证、相机内程序加载、同机健康备份、独立救砖和1080p H.265实际主录仍分别待验，原G01至G16保持。它不构成可刷固件、交叉刷入或修改包批准。
