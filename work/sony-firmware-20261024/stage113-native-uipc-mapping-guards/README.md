# FX3 7.02：原 UIPC 分发守卫与用户指针映射

2026-10-27。**原分发器先检查用户记录范围、操作号、映射状态和进程归属，再从原 ELF 表选择处理函数；分配与回调通知使用同一套“用户基址＋池内偏移”转换，释放入口反向转换并限制单个指针偏移。** 本轮补的是原代码规则，未建立真实用户映射、分配队列或生命周期，不能放行刷写。

正式结果：[mapping-guard-results.json](run-inclusive-address-limit-20261027/mapping-guard-results.json)。在两种内存种子下，共 30 组分发、10 组分配入口、4 组独立转换片段、10 组释放范围、6 组映射长度及 4 组独立映射状态，合计 112 个有界阶段。全部在 Mac 的 Unicorn guest 内存中执行；没有 Windows、UU、相机接口、主机 ioctl、模块装载、真正 remap、驱动改变或设备写入。

## 分发及前置检查

沿用阶段 47 的官方样本 `osal_uipc.ko`，SHA-256 `6aa0f5c8c72f5f6cf9aa9c905fc3f3f75b8bea0dfebaf13deb632b0de088eb38`。原 `.text+0x4d8` 分发器先为 16 字节参数记录检查地址范围，再停在用户复制调用之前。另一个独立阶段获得明确声明的记录和先前原栈帧，从 `0x538` 开始检查后续条件：

- 去掉操作号最高位后，仅允许 0 至 16。
- 用户映射基址非零才允许普通操作；尚未映射时只允许操作 16。
- 声明的任务 `mm` 标识必须匹配打开上下文的归属字段。
- `.rodata+0x340` 原表中，分配 10 对应 `.text+0xc70`、注册 8 对应 `0xe90`、释放 11 对应 `0x778`、回调通知 13 对应 `0x890`，初始化 16 对应 `0xb50`。执行停在分发 `BLR` 前，没有调用处理函数以伪装完整分发成功。

范围实验核对的是**最后一个字节**：16 字节记录的 `pointer+15` 等于声明上限仍能进入复制前停点，超过上限则拒绝。补有加法进位和越过 64 位末端的对照。范围通过本身不表示该地址已映射、可读或复制成功。原分配入口另检查 16 字节嵌套参数和非空输出单元；有效片段仅生成原分配函数参数，然后停止。

`SP_EL0`、任务结构片段、地址上限、mm 标识和上下文都是明确声明的 guest 输入，不是读取 Mac 或相机内核的任务。失败复制的独立状态输入走原拒绝返回；未知用户复制没有被替换成成功函数。

## 分配、回调和释放的地址关系

三个独立入口共享相同的声明基址和偏移，用原指令分别计算：

| 原片段 | 原关系 | 本轮停止位置 |
| --- | --- | --- |
| 分配 ioctl 后段 `0xce0` | 用户数据指针 = 用户映射基址 + 内核数据指针 − 内核池基址 | `0xd48`，复制输出指针到用户之前 |
| 回调通知片段 `0x9f0` | 用户数据指针 = 用户映射基址 + 内核消息头指针 + 24 − 内核池基址 | `0xa24`，解锁之前 |
| 释放入口 `0x778` | 内核数据指针 = 内核池基址 + 用户数据指针 − 用户映射基址 | `0x7a0`，真正释放之前 |

两种用户基址、数据偏移 64 和 `0x2040`、worker 索引 0 和 3 都保持正反转换一致。通知记录的回调和上下文来自声明输入，原指令写出其记录与用户数据指针。分配输出的 8 字节用户复制、真实回调排队、解锁和释放都未执行。

释放入口的无符号偏移检查允许 `0..0x1fffff`，拒绝低于基址和到达 `0x200000` 的指针。**这是单个指针的位置检查，不是整个消息长度、分配身份、引用计数、代次或是否已释放的证明。** 边界位置到达释放前停点，不能理解成这些位置上存在有效对象。

阶段 112 的 128 字节声明块与尾标记解释继续保留。本轮为原驱动的指针转换补了规则来源，仍未证明该块在实机用户态确实映射、回调期间仍存活、或 48 字节复制实际安全。

## 映射长度与条件发布

原 mmap 入口 `0xd70` 要求 VMA 结束地址减起点恰为 `0x200000`，即 2 MiB。本轮通过等长、少一页、多一页对照，等长停在 PFN 计算前，另外两种停在错误日志之前。

另以原入口形成的保存帧为基础，独立给定 remap 状态后从 `0xe00` 执行：状态 0 才把 VMA 起点写入上下文 `+0x30`；非零则保留旧基址并返回原错误。**这是条件发布的实验，不是真正 remap 的成功或失败结果。** [Linux 内核内存管理接口说明](https://docs.kernel.org/core-api/mm-api.html#c.remap_pfn_range)将 remap 描述为把内核物理页映射到用户空间的操作；原 Sony 样本的实际页帧、锁和映射权仍需另证。

## 原样本、重定位与实验修正

21 个局部 `R_AARCH64_ABS64` 重定位仅在 guest 副本中按原 ELF 记录填入数据指针：4 个文本内字面量及 17 个原分发表项。消息池根的原重定位目标是 **`.bss+0x50`**；没有凭临时反汇编笔记把它当成 `.data`。未应用或执行未知外部调用，没有进行真实 Linux 模块加载。原指令字节不变，映射副本在每阶段运行前后保持不变。

首次测试错误地把原 `RET` 观察记录也视为禁止调用，触发脚本断言；第二次把范围上限误当成不含末字节的界限，再次触发断言。两次失败和各自源码保留。修正观察断言与边界预期后，正式 112 阶段通过，未改 Sony 原指令，也未伪造外部函数的返回或输出。复核由同一代理完成，不属于另一独立执行引擎的复验。
