# FX3：原帧分配接入原构造，及公开恢复案例边界

**在同一离线 RAM 实例中，原类型5分配器返回句柄，原调用者从句柄取得物理地址，随后连续进入原帧构造、几何与帧头处理。** 这减少了上一轮“帧地址由实验输入声明”的缺口。源参数缓冲也由本实例中的原类型4分配器建立，但其48字节内容和RAW对它的引用仍是声明输入。

5组场景、203个有界阶段通过；包括原128块帧池耗尽后的第129次申请，原代码返回空句柄并转入错误分支，未进入帧构造。不是完整相机启动、完整调用或实际录制验收。

仅Mac离线；没有操作Windows、UU、相机、存储卡、驱动或权限，没有可刷包。16项要求、授权和实机验收条件全部保留，目标未完成。

## 原分配与调用者

以下为十六进制文件偏移，代码VA为`80000000+偏移`。ROM池描述、类型分派、构造、分配和调用者指令均来自已校验的原VCD文件；原文件不修改。环境中的RAM布局、GP、输入RAW和部分owner字段仍为实验声明，不是正常启动的机身抓取。

| 项目 | 原ROM/请求 | 本轮结果与限制 |
| --- | --- | --- |
| 类型4源参数池 | ROM `2132c0`，128块，每块512字节；申请`11c`字节 | 原分配返回`84100040`，指向物理`00c2c140`，引用字节1；`ec..11b`预置48字节参数，不是原消息生产者输出 |
| 类型5帧池 | ROM `2132d0`，128块，每块1264字节；原调用者申请`4f0`字节 | 原分配返回`84100e80`，指向物理`00c3c140`，引用字节1；原调用者转成`80c3c140`传给构造函数 |
| 原帧构造 | 原caller `14411c`调用`1f8550` | 构造及嵌套初始化完整返回`144124`；即时检查新帧参数句柄与更新位均为0，保留的对齐空隙来自池旧值 |
| 原帧头 | 从`1440c8`经构造、几何、包装及帧头，不再在`131888`切开 | 更新关闭时返回原caller并停`1441e4`外部虚表读取前；更新开启时原赋源句柄，停`131c20`引用增加前 |
| 耗尽控制 | 原生连续申请类型5共128次，再由原parent申请 | 第129次返回0，原状态为`b1020001`，转入`144334`诊断前；没有构造新帧，物理帧池保持旧值 |

正常分配的A5/C3旧值及更新位0/10共4组；耗尽1组。正常组类型4/5剩余块数均127，耗尽组为127/0。源参数的引用字节在开启更新的终点仍为1：原代码已赋帧指针，但尚未增加引用，不能称作参数共享或更新完成。

实验host没有设置CPU的分配返回值、新帧地址、原parent描述符或实际空闲计数。它只在**独立的期望状态**中计算这些值，再逐字节比较原代码产生的结果。RAW的`54`字段预先声明为预期类型4句柄，运行后与真实分配结果核对；它仍不是原生RAW消息生产路径。旧的声明帧页`81500000`改为只读并保持73，未用于本轮构造。

## 明确保留的断点与缺口

同一RAM实例不代表无间断完整启动。以下部分没有执行，续接使用明确列出的原指令边界，未补写IRQ返回或模拟成功：

- 注册校验、factory之前的IRQ，以及factory中的CACHE维护；只执行已分类的原构造及原注册存储。
- 原parent的`143fc0` GP锁ID读取、`143ff8..14402c`锁ID保存/IRQ获取、`144090..1440c4`IRQ释放。
- 开启更新后的新参数引用增加；或关闭更新后的外部虚表分派。

这些缺口使当前结果不足以证明真实同步、引用生命周期、调度队列或MAIN绑定。owner的历史记录和若干输入字段仍未取得真实生产来源。没有MMIO、逐次内存读写钩子、指令替换或假返回；每阶段核对完整栈、全部数据区及整个加载映像，映像仅允许原代码写入运行时注册表指针的4字节，磁盘原文件不变。CODE观察可能包含被annul的延迟槽，因此不把单个PC出现当作指令副作用证据。

上一轮的`1920×1088`帧字段与裁剪值4、单位2的`1088−4×2=1080`仍仅为参数数值对应。本轮没有生成或解析HEVC码流，没有调用实际硬件编码器。原MAIN Open/Start、29.97与精确30的实际帧时序、声音、长录、温度及冷启动均未验收。
