# FX3 编码参数的文件初值与旧值保留

2026-10-25（本地日期）。离线研究，原件与相机未改动。

**本轮闭合了受控“从文件建立对象”条件下 52 字节的零值来源，尚未闭合真实运行时复用和完整请求有效性。** 原通用编码器对象构造函数不写其 448 字节编码块；这些字节在官方文件的六个静态槽中原本就是零。人为设置的旧值也会被构造函数和本轮 HEVC 参数片段保留。这个对照不能证明实机存在缺陷，也不能把保留区直接判为无用。

合计 32 段原指令执行，包含 14 次完整通用编码器对象构造正文。工厂本身只运行前段，停在六个对象构造完成后，后续注册没有执行；不能称为完整工厂、固件启动或真实 MAIN 实例验收。

四组中，原 HEVC 参数片段均写入编码块 396 字节，另 52 字节保留原值。A5/C3 两组输出差异恰好是这 52 字节；文件初值下，原 FF 和私有 16M 对照只相差 `+0x2d/+0x2e/+0x2f` 三字节。trace/CPB 解码保持 25,999,360/26,000,000。数值是请求字段的离线解码，不是实拍码率。

## 原代码与初值来源

- 固定存储调用链：`0x22a724 → 0x22a680 → 0x22e95c → 0x226d2c`。静态地址计算得到工厂文件偏移 `0x562930`，六个 handler 槽从 `+0x40` 开始，步长 `0xe518`。这里只核对原调用点与计算，不声明完整链已连续运行。
- 通用对象构造正文 `0x21d9e0..0x21dc64`、基类构造 `0x22c450`、15 个内置池的原构造/初始化，均通过上一轮绑定的原 `memset` 执行。A5/C3 对照原栈返回，虚表地址点为 `V+0x37bda8`，对应原 RTTI `imola_common_api_enc_handler`。
- 六个原文件编码块偏移分别为 `0x570b48/0x57f060/0x58d578/0x59ba90/0x5a9fa8/0x5b84c0`，各 448 字节全零。哈希与原指令列在结果中。客体将这段静态存储搬到声明的私有 RAM；不是实机地址绑定。
- 原 prepare 入口现在实际完成描述符复制及栈上 136 字节清零。原 builder 从 `0x221b50` 正常入口运行，实际完成 COMMON 64 字节清零，再保持寄存器/栈从同一 PC 继续到强制诊断调用前。
- 强制诊断 `0x221eec` 仍未实现。后半段在**另一个客体**从 `0x221f50` 开始，使用明确复制的内存/栈和保存寄存器输入，停在正文成功标记。没有伪造日志返回或把两段拼成“完整 builder 成功”。

原 LIRO `.init.text+0x240/+0x244` 检查 `load` 字段，另有文件名条件可以绕过文件读取。所以文件零初值不能推出每次重载、WBI、热切换或旧对象复用时都会重新清零。真实槽位分配、其它初始化/清理与下游对这 52 字节的读取范围，仍需追踪。

## 目标与安全边界

目标仍为经典 FX3 7.02 的 1080p、30000/1001 fps（用户所称 30p）、HEVC 4:2:0 10bit 约 16 Mbps 主录；精确 30.000 单独验收。本轮沿用人工 quality24/FF 行 386 描述符。原 quality22/FH 目标未命中资源表的问题仍存在。私有 16M 副本及指针本轮是明确的主机数据输入，不能称为新实现的 Sony 原生写者或安全上机模块。

本轮重查 [Sony 主录文件格式说明](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000868279.html)及 [Sony 代理设置说明](https://helpguide.sony.net/ilc/2210/v1/en/contents/TP1000882045.html)：官方列出的 HS 主录为 4K；HD HEVC 16 Mbps 4:2:0 10bit 列在代理选项。代理文档与原参数片段都不能代替新增主录模式的硬件接受证明。
