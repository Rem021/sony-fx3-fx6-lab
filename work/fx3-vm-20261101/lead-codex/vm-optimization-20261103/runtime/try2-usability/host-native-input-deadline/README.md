# 缺少原生按键接收证据时的有界退出

2026-11-03。独立宿主候选 `run_trial_v16_input_deadline.py` 补齐按键等待的一个缺口：**发送方抬键回执已出现，但原程序的按下／抬起接收记录不完整时，也要在原有 12 秒期限后停止并收尾。** 不重发按键、不伪造接收，不改变固件、FX3 平台或省电设置，默认入口未替换。

v15 的按键完成要求发送方抬键及原程序 down/up 三项证据齐全，但其超时条件只检查发送方抬键。因此当发送方抬键存在、原程序接收证据缺失时，完成和超时两个分支均不满足，网页 busy 可持续至整轮时间上限。候选在发送方证据存在时也检查原程序两项接收记录，失败进入已有异常收尾路径。证据全部齐全时，不压缩现有 MENU 等画面等待窗口，也不把像素变化当作输入接收证明。

[test_deadline.py](test_deadline.py) 从生产源提取旧超时判断与新函数，验证六种状态：空闲、期限内、缺发送方、缺原程序接收、错步号以及回执齐全但 MENU 仍在绘制。缺接收案例复现旧版不超时、新版明确失败。[test-receipt.json](test-receipt.json) 同时核对用户历史 `try2-70588c4c` 第 10 键三个标记均存在，**因此该历史卡住事件不能归因于此缺口**。

```sh
python3 -B build.py
python3 -B test_deadline.py
```

[build.py](build.py) 从固定 SHA 的启动失败回执 v15 构建独立 v16，保留前版及[完整差分](runner.diff)。只做宿主离线验证，没有 QEMU、固件键输入或浏览器联动；真实异常收尾仍需运行验收。该候选不用于正在排队的 FX6 零键实验。
