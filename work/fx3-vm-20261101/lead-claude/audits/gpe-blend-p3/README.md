## FillRect：颜色与三个 selector

令 `s=u8@0x24`，`K=u8@0x25`，`c[0..3]=u8@0x20..23`。日志的 `flags=(s<<8)|K` 是 v13 adapter 合成字段，**不是原厂一个 flags 字节**；AP81 现有 serial 的唯一 FillRect marker 是 `fmt=0 flags=0xff`，即 `s=0,K=255`，命中 `0xc50c` 关闭混合。现有 AP81 日志只另含一条 Flush，没有 BitBlit；本审计没有把“预计大量 alpha blit”当作已观测事实。原分支证据 `0xc458–0xc51c`；日志路径与 SHA、两个完整 marker 见 proof.runtime_observation；打包方式另见 [v13 marker 合同](../../impl/gpe-adapter-v13/README.md)。

颜色寄存器 `B07` 的精确数值（A1；`0xc384–0xc454`）：

```text
fmt0: B07 = (c0>>4)<<12 | (c1>>4)<<8 | (c2>>4)<<4 | (c3>>4)
fmt1: B07 = c0<<24 | c1<<16 | c2<<8 | c3
```

fmt0 为高 nibble 截断，不是除 17 四舍五入；fmt1 不做颜色乘法。上述是寄存器值，既有 CPU 后端按 LE16/LE32 存放；以 `12 34 56 78` 输入时分别为数值 `0x1357 / 0x12345678`，内存字节为 `57 13 / 78 56 34 12`。不能把数值顺序与小端内存顺序混为一谈（`0xc390 rev`；`0xc400–0xc428`）。

下表列出**实际写入**；“—”表示该分支不写，硬件旧值仍可能存在，不表示置零。所有寄存器均为十六进制编号，值也以十六进制显示（K 除外）。

| s / K | B01 | B02 | B03 | B04 | B05 | B06 | A1 证据 |
|---|---:|---:|---:|---:|---:|---:|---|
| 0 / 255 | 0 | — | — | — | — | — | `0xc50c–0xc51c` |
| 0 / 0..254 | 1 | `09080901` | 0 | K | K | — | `0xc464–0xc4b4` |
| 1 / 255 | 1 | `05040501` | 0 | — | — | — | `0xc580–0xc58c→0xc54c–0xc578`；B01 的 1 来自 `0xc3ac` 前已读的 s |
| 1 / 0..254 | 3 | `05040501` | 0 | — | — | K | `0xc520–0xc578` |
| 2 / 任意 K | 1 | `0c000100` | 0 | — | `K*01010100` | — | `0xc590–0xc5dc` |

selector2 的 `B05=K<<24|K<<16|K<<8`，低字节恒零；不是四字节 `KKKKKKKK`，K=255 也没有关闭混合的特殊分支（`0xc5c4–0xc5d8`）。

| s | fmt | B10 | 原行为 / A1 证据 |
|---|---|---|---|
| 0 | 0/1/2/3 | `e1/e0/e2/e1` | 表 `0x15210`；`0xc5e4–0xc608`；fmt2/3 在 `0xc430–0xc450` 警告并写 B07=0 |

## BitBlit：精确分派与两组混合寄存器

令 `s=u8@70`、`K=u8@72`、`f73..f78=u8@73..78`。s=2 原厂直接返回 1（`0xcf48–0xcf88`）；3/255 等其他非零 s **原代码按非零路径处理**，不是已确认的新 blend 模式（`0xb2c8`、`0xbe04`）。软件准入可保守限制 0/1，不能把未知 selector 发送硬件试错。

以下分派限定 rotation@68=0、目标 w/h@10/14 与源 w/h@48/4c 全等。rotation 非零或不满足几何条件可能进入 StretchRotateBlit，本 P3 不扩展（`0xcf8c–0xcfb0`、`0xd0b4–0xd144`）。

| 条件 | 入口 | A1 证据 |
|---|---|---|
| 任一 f73..f78 非零 | `0xbbcc` 通用图元 | `0xcfb4–0xcfcc→0xd040`；f73..76 作为 raw 非零判断，高 nibble 也会改变分派 |
| 全 flags=0，且 s=0,K=255，dst=src | `0xb578` 转换/复制 | `0xcfd0–0xcfe4→0xd028–0xd094`；并非所有相同格式都在此合法 |
| 同上，src≤1,dst≤2 或 src=3,dst=1 | `0xb578` | `0xd030–0xd03c`、`0xd070`、`0xd0a8` |
| 不满足上述纯转换条件，src=dst≤1 | `0xb234` 快混合 | `0xcfe8–0xd010` |
| 其余 | `0xbbcc` | `0xd040–0xd05c` |

快路径的实际寄存器写入：

| s / K | B01..B06 | B10 | A1 证据 |
|---|---|---|---|
| 0 / 任意 K（自然分派仅 K<255 命中快路径） | `B01=1,B02=09080901,B03=0,B04=K,B05=K` | fmt0→3；fmt1→1 | `0xb4dc–0xb534`、`0xb330–0xb350`、`0xb570` |
| 非零 / 255 | `B01=1,B02=05040501,B03=0` | 同上 | `0xb4c8–0xb4d8→0xb300–0xb32c` |
| 非零 / K<255 | `B01=3,B06=K,B02=05040501,B03=0` | 同上 | `0xb2d0–0xb32c` |

**快路径完全不读颜色 @6c..6f；通用路径才将其 rev32 写入 `741`**（`0xb234–0xb574` 对照 `0xbdd8–0xbdec`）。不应给无 flags 的快混合额外乘上这四字节“滤镜色”。

通用图元不用 B01..B06/B10 执行混合，而用以下对应组；`710` 是程序实际写的使能/同步状态，未据名称猜测它的全部硬件含义。

| s / K | 实际写入 | A1 证据 |
|---|---|---|
| 0 / 255 | `760=0`；该处不额外写 710 | `0xc004–0xc00c→0xc08c–0xc09c` |
| 0 / K<255 | `710=1,760=1,770=09080901,771=0,772=K,773=K` | `0xc010–0xc088` |
| 非零 / 255 | `710=1,760=1,770=05040501,771=0` | `0xbe10–0xbe1c`、`0xbff0–0xc000→0xbe54–0xbe84` |
| 非零 / K<255 | `710=1,760=3,774=K,770=05040501,771=0` | `0xbe20–0xbe84` |

通用目标格式写 `20=dst_low32`、`21=stride_bits|hw_format`（`0xbc24–0xbc84`），源写 `462=src_low32+offset`、`463=src_stride`、`464=hw_format`（`0xbcf0–0xbd54`）；不能误以为它还受上条命令 B10 配置支配。通用路径在 `0xbf84–0xbf90` 另写 `710=1`；本报告不假定任何遗漏寄存器已 reset。

| `0x160224`，循环`0x1602c4–0x1602f4` | RGBA8→数值ARGB4444 | **说明同一库还存在另一4444通道顺序**，不能只凭“4444”合并两者 |
| `0x160134`，循环`0x1601d4–0x1601f8` | RGB8→数值RGB565，高bit截断 | 不能因此把 GPE fmt3命名成RGB565；没有绑定证据 |

回调由 `0x160928–0x16092c` 配置，相关 GOT `0x262718/838/e88/1a0` 是 RELATIVE 重定位，分别指向 `0x160134/0x16031c/0x160224/0x160414`。PNG默认RGB(A)顺序、BGR交换与alpha添加规则参考 [libpng 官方说明](https://www.libpng.org/pub/png/libpng-manual.txt)；库中 `0x160914–0x160918` 还存在单独的 BGR 分支，因此这里的输入约定不能横推到其他分支。

`stella::Color` 的 ZERO常量本身全零，无通道辨识力；`0x133774–0x133810` 的颜色乘法虽有确定软件式 `(a*b+a+b)>>8`，它处理Color乘法，不是GPE blend参考实现。**不能把这一除256软件式借给B02对应硬件**。

`color.uxb` 仅52B；`image.uxb` 为uxb头；`image_00_32.uxc/43.uxc` 实际为uxd头（头/大小/哈希见proof.resources）。本审计没有闭合资源解压、像素格式或调色板表到 `GRM_gpermRectblit` 的绑定，资源文件存在不能补齐通道、straight/premultiplied或CLUT结论（像素进入GPE的原上层范围 `libObj 0x101970–0x101d1c`）。因此后端打包规格保留 c0..c3，**fmt0/fmt1的位序是A1，RGBA名字为B级交叉支持**。

## 可直接实现的 P3 准入/拒绝规格

这里“拒绝”指本软件后端返回可识别 unsupported、保留原Main失败完成路径，**不是宣称原厂该组合非法**。已知extent/逐行span/clip/重叠/回调限制沿用现有 P0–P2；不得借扩展混合取消它们（地址源`0xb354–0xb3c8`、完成账本`0xaf08`、错误由 Main `0x9c34–0x9c4c`，已有审计可复核）。

| 组合（覆盖全部 selector/flags 分类） | 可实现像素规则 / 动作 | 依据与剩余门禁 |
|---|---|---|
| Fill fmt0/1,s0,K255 | `D=pack(c)`，按上文精确高bit打包 | 延续P1；`0xc50c`关闭混合，`0xc390/0xc400`颜色 |
| Fill s0,K<255 | **拒绝P3像素执行**；可实现寄存器编程等价的命令描述 | `B01=1, B02=09080901`；像素因子/舍入U，`0xc464–0xc4b4` |
| Fill s1,任意K | 同上 | `05040501`与可选B06；s1,K255仍开启混合，`0xc520–0xc58c` |
| Fill s2,任意K | 同上 | `0c000100`及非对称B05，`0xc590–0xc5dc`；不能擅自解释为clear/multiply/destination-over |
| Fill fmt2/3或未知selector/format | 拒绝；不扩展P1 | color=0警告/非零s限制/原assert，`0xc330–0xc454`、`0xc5e4` |
| BitBlit fmt0/1相同、s0,K255、f73..78全0、无几何变换 | `Dpacked=Spacked`，沿既有P2按行复制 | `0xcfb4–0xd094`、B01=0；仅既有支持子集 |
| BitBlit s0,K<255 或 s1任意K，flags任意 | 拒绝P3像素执行 | 快组/通用组已恢复，因子编码U，`0xb2c8–0xb534`、`0xbe04–0xc09c` |
| BitBlit s2 | 原错误返回；不可成功完成 | `0xcf48–0xcf88` 原返回1；adapter按自己的既定返回映射 |
| BitBlit其他s | 保守unsupported | 原代码非零别名不等于已定义ABI，`0xb2c8/0xbe04` |
| 任意跨fmt转换，包括0↔1 | 拒绝正式P3；可提供显式实验候选 | B10表已知，硬件4→8扩展/舍入U，`0xb5c4–0xb644`、`0xb794–0xb7d0` |
| fmt2/3/4任意路径 | 拒绝正式像素执行 | 通道与采样未绑定；源3还必须mode1..4，`0xb708/0xbd84→0xaf98` |
| s0,K255且任意flags非零 | 拒绝通用像素执行；可先做描述符级实现 | f73仅分派、f74采样、f75/76运算码、f77/78翻转已分清；`0xbd94–0xc0e8`，仍缺通用图元等价性 |
| rotation/缩放、部分clip、重叠 | 保持既有unsupported/边界拒绝 | 不借本P3审计扩展P5；`0xcf8c–0xd144` |

4bit**输入打包**有精确式；4bit**混合运算**与0↔1**硬件转换**没有。可实验的 `8888→4444=各byte>>4`、`4444→8888=nibble*17` 或 `nibble<<4` 不可标“原厂等价”：第一种只有软件打包同形证据，后两种在已审计 GPE生成器里都没有执行（`0xb578`仅写寄存器）。

## 为什么不能给出精确 alpha 像素公式

已知 B02/770 的 raw字节分别是 `[01,09,08,09]`、`[01,05,04,05]`，selector2是`[00,01,00,0c]`；这些值来自常量装载而非可识别的像素运算（`0xc478/0xc550/0xc5a4`、`0xb304/0xb4f4`、`0xbe60/0xc03c`）。没有寄存器字段定义就无法把每半字/字节可靠分配为源因子、目标因子或反相操作。B01/760从1变3且额外写B06/774，只证明控制与K通路改变（`0xc52c–0xc548`、`0xbe34–0xbe54`），不能证明额外bit在乘源alpha、乘RGB还是选择其他阶段。

以下只能作为待排除的**假设族**，不能直接写进默认后端：

| 假设族 | 候选式（用归一化通道） | 未知项与证据边界 |
|---|---|---|
| 常量插值 | `O=Q((K*S+(L-K)*D)/L)` | L=255还是256、是否全四通道、因子方向、Q阶段未知；`09080901`没有字段注释 |
| straight输入的常见混合 | `a=Q(As*K/L)`；`Co=Q(Cs*a+Cd*(1-a))` | 只由上层未预乘色提供B级支持；源/目标alpha语义与结果是否归一化未知；`libObj 0x15294c–0x152958` |
| premultiplied输入的常见混合 | `a=Q(As*K/L)`；`Co=Q(Cs*K/L+Cd*(1-a))` | 是否某些资源已预乘未知；`741/740`颜色处理也可能改变输入，`0xbdd8–0xbe00` |
| 输出alpha | `Ao=As*K/L+Ad*(1-a)`、`lerp(As,Ad)`或独立系数 | B02/B03原值不足以择一；不能默认 source-over alpha |

即使确认了前三个颜色通道的近似source-over，仍须分别验证：alpha8/4bit分母与满值特殊分支、4→8复制bit或左移、乘法逐级截断或最终一次舍入、饱和/环绕、输出alpha、颜色运算/转换/量化的先后。它们均由 `0xaf30` 之后的硬件处理，本审计的软件重放在该提交点停止。

## 后续运行验证方法（本次未执行）

1. **先取得输入与原厂输出的同一绘制凭据。** 在已有授权的运行链中记录原始56/144B参数、源/目标绘制前后原始面、stride/format/extent代次和最终显示面；异步用原完成边界读取，不以Flush或截图猜测写入顺序（同步/回调原路径`0xaf08`、`0xa110/0xa158`，前序审计已定位）。QEMU新后端的输出只能验证它自己的实现；要证明芯片公式，需原厂硬件原始面或适用的官方寄存器文档。
2. **区分候选算术。** 分别测试s0/s1/s2；K取0/1/15/16/127/128/254/255，As/Ad覆盖0、部分、满值，RGB用互不相同且可大于alpha的值。`S=253,D=0,K=127`时 `/255 floor=126`、`/256 floor=125`；`S=1,D=0,K=128`时 `/255 floor=0`、nearest=1，可区分常量插值候选。该向量只用于选假设，不能先假定s0确为该式（分支锚点`0xc458/0xc520/0xc590`）。
3. **把格式与算术分开测。** 无混合先测试fmt0/1每个通道独立nibble/byte ramp及0↔1，尤其nibble1/7/8/15；随后比较“先量化再混合”和“混合后量化”。fmt2/3/4先绑定已知资源的pixel stride/采样/颜色定义，再测试mode1..4；不能用猜解的UX图像当真值（转换入口`0xb578`、表生成`0xaf98`）。
4. **flags单变量与状态依赖。** 单独改变73..78，75/76比较1/15/16，77/78比较1/2，检查上一条命令留下的未写寄存器是否影响结果；颜色6c..6f用单通道/透明值，排除滤镜/逻辑运算混淆（`0xbd94–0xbe00`、`0x13e34`）。
5. **实机照片/原厂截图用于语义交叉验证。** 匹配同一UI资源、尺寸、背景、panel控制和alpha，检查透明边缘、色道置换与预乘黑边；照片的曝光/显示转换不适合证明±1 LSB或精确舍入。应先比较原始面，再比较最终显示，不能把显示链差异补偿进GPE（GPE生成到提交边界`0xbbcc–0xc150`、`0xaf30`）。

本目录交付闭合了**命令→寄存器**，只闭合了独立PNG回调的**CPU像素打包**，没有闭合**混合寄存器→硬件像素**。P3正式混合与转换仍需上述像素oracle；先前AP81的 fmt0覆写成功不填补这一缺口（`0xc50c`与`0xc52c/0xc590`是不同分支）。
