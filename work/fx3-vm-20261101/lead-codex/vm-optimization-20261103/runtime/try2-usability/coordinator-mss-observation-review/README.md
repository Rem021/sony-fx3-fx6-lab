2026-11-03。现有 v7 观察器在公共发送构造器 `appFw+0x2eaf294` 仅保留队列 `0x80924220` 且命令 `0x00920204` 的调用。这是本轮对已固定源码的直接复核，见 [evidence.json](evidence.json)。它不能代表同队列所有计时相关活动。

原 app 字节再次核对：`0x2eaf2fc` 写消息前两字、`0x2eaf300` 写后两字，`0x2eaf304` 调用发送函数，`0x2eaf308` 检查返回值，`0x2eaf334..33c` 另取缓冲并释放。现有 `0x2eaf308` 探针曾得到 unreadable，原因未闭合；不能称已拿到真实 16B 线包，也不能简单归因为已被本函数释放。不得为取包未经验证新增 BL 探针。

下一轮最小修改是复用已验证的普通指令挂点，只取消命令号单项过滤，记录每次命令/参数、guest monotonic、TID、入口/返回关联和丢失计数。记录不能改返回码、发人工重置消息、改变省电时间或丢弃失败。本轮只定位观测缺口，没有更改观察器或启动 QEMU。
