# 旧HELD主机进程的单次清理方案

**只清理Mac上的两个旧实验进程；不访问相机。尚未批准或启动。** 用户已明确确认FX3机身侧USB-C完全拔下，电池供电下的拍摄界面及菜单正常。相机先保持独立，不重连USB。此前只是单次服务通信中断后的手动恢复，录制与固件救砖仍未通过。

## 为什么需要这次例外

261的HELD分支无限暂停；INT/TERM/HUP处理器只写停止标志，循环不会检查它，不能正常退出。这是本机工具缺陷。原固定方案承诺“不强杀、不重置、不自动重试”，因此不能将整体继续研究同意直接当成这次强制终止的许可；实际执行前须单独批准此处的具体范围。

## 固定操作

1. 必须保持用户确认的相机侧USB-C断开，且相机电池界面/菜单正常。本程序不自行探测、打开或控制USB，也不把任何其他Sony节点当成这台FX3。
2. 最多运行一个新管理员程序，必要时由用户本人完成Terminal中的sudo/Touch ID原生验证。不索取或记录密码，不调整隐私权限。新程序和不可重用记录只存Mac内置盘私有目录：`/private/tmp/fx3-host-cleanup-20261101-01`及`/private/var/root/fx3-host-cleanup-20261101-01`。
3. 核对旧helper PID85066的UID0、出生时间1793515458.389961、私有路径及实际映像SHA；核对原观察器PID82324的UID501、出生时间1793515061.924886、Python路径/映像。两者都通过才继续。
4. 只用task-name端口读取内核审计token，核对token所绑定的PID版本和路径。不给task控制端口，不读写进程内存，不注入代码，不修改审计身份。不降级为仅按PID发送信号。
5. 只对已核对的旧helper发送一次明确的SIGKILL(9)。这会强制结束该主机实验进程，不能标为协作退出。最多观察约2秒；若未确认原实例消失，停止，不再发信号、不动观察器。
6. 只有旧helper确已消失，才对同一个已核对的普通用户观察器发送一次SIGTERM(15)，最多观察约2秒。它的已保存HELD回执和56帧保留，不把这一步称为原通信成功。
7. 全局journal只读，核对终止前后字节及文件身份不变，保持原OWNED/UNKNOWN阻止复用。新root目录记录单次标记和结果。它不清锁记录、不写CLEAN、不重发认证，也不开放下一轮相机试验。

旧helper与观察器之外的进程、Terminal其他窗口、驱动和用户资料均不在操作范围。任何身份、文件、token或结果不明确时都停止；不自动重试。本方案不批准固件写入、相机操作或264离线候选上机。

## 已完成与未完成的检查

[固定计划及程序SHA](fixed-plan.json) · [构建与主机检查](build-and-check.json) · [普通用户子进程检查](own-child-check-attempt03.json)。最终程序和子进程测试编译通过；测试启用ASan/UBSan。用自建普通用户子进程验证了出生时间/UID/路径不符时拒绝，错误audit版本不能终止它，正确token只终止该测试子进程；当前两个旧实验进程未收到信号。正式程序在普通UID运行时立即拒绝，未读取目标或发信号。两个程序均不链接IOKit。

root路径、私有journal及对UID0旧helper的实际清理尚未执行，不能用上述测试宣称成功。首两次测试包装有SDK类型名和API返回值处理问题，原失败记录保留；最终使用本机SDK的audit_token_t，并按API非零返回识别失败。

参考：[Apple公开实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c)提供按audit token发送信号的路径；本机SDK有相应声明，自建子进程测试核对了实际系统的错误版本拒绝行为。它不证明相机状态或恢复能力。
