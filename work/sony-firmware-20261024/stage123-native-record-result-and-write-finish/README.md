## 原释放与事件的顺序

通知函数原序言在日志前停止；独立 post-log 帧进入原汇总器，经过独立锁间隙后返回调用者，原指令保存结果并进入记录释放包装器。原 free 的实参是记录指针。free 本体没有执行；独立 post-free/post-unlock 帧运行原返回和事件参数准备，在 SetIssueEvent 前停止。

因此本轮确认的是原调用顺序和数据来源，**没有释放实际记录，也没有发出真实事件**。事件的8字节载荷没有整份384字节记录快照，不能代替释放前的实例绑定和必要信息保存。捕获方案必须验证实际分配寿命，并在原 free 前生成独立拥有的必要数据；不能在收到完成事件后追读旧指针。

FileQueueStreamWriteCmp 的静态分支另显示：在相关条件下先排队 EncClose，再排队 AllMovieWriteFinished，随后清除 MovieRecInfo `+0xa48`。Enqueue 函数把旧记录指针放在任务请求 `+0x50`。本轮没有执行该完整生产者分支，也没有证明 Close 已完成、全部异步消费者退出或指针已安全回收；记录字段清空与排队完成也要分开验证。
