# 本次 SERVICE 停留与恢复审查

本次已有真实通信，但未完成正常归还。状态为 **OWNER_RETAINED / HELD**，不是通信成功，也不是已证明固件损坏。现在的优先项是恢复并验证普通使用；继续等待已结束的诊断窗口不会自动完成退出。

## 已取得的证据

管理员验证由用户完成后，原观察器核对了 root helper 的内核身份和自身映像。MSC START 返回已完成的 STALL；随后七次 OUT 和七次 IN 都返回，每次 IN 为516字节，固定响应形状通过。旧 MSC 接口和设备对象释放调用已返回。

原程序仅等待2秒/20次采样：前两次仍见旧MSC，随后18次未见目标；没有在该窗口接受 SERVICE。故没有打开 SERVICE、没有执行 SERVICE START/认证、88字节 read0 或 STOP。56份逐调用原始帧和1024字节 HELD 回执已保存。回执表示无在途主机调用，但不证明机身内部回调或历史记录写入已结束。

稍后的独立普通用户缓存探针见到同一物理USB-C锚点上的054C:0336、Sony USB Device。它属于窗口结束后的证据，不追认为窗口内身份已通过。没有固件、分区、备份属性、机身文件写入命令或模块上传；MSC认证仍可能产生认证历史/工作模式副作用，不能称零写入。

## 本机实现需要修正的两点

1. 等待窗口过短。固定上游PMCA使用10次、每次先等待0.5秒，约5秒；本包只用2秒。已证实我们的窗口内未见SERVICE、窗口外能见；枚举的精确耗时以及是否只有这一原因尚未测得。不能仅把常量改大就直接重试。
2. HELD分支缺少协作退出。原生helper进入无限暂停循环，没有fixture里的退出门。所有已记录调用已返回、旧MSC对象已释放，但软件全局锁仍占有，原观察器也保持运行。不能把“保留软件实例”等同于“有阻塞的USB调用”，也不能通过强杀或改锁掩盖未归还事实。

不修改正在运行的helper、封存261包或已消耗许可，不在另一路径绕过锁启动新USB程序。下一版本应分别记录设备状态、对象所有权、在途调用和程序终态；无在途I/O且对象已安全处置时，支持保留持久UNKNOWN标记的协作退出。只有完整边界审查后才形成新构建，本说明不是新上机包。

## 当前恢复决策顺序

| 观察结果/路线 | 处理边界 | 怎样才算通过 |
|---|---|---|
| 先由用户观察屏幕和存储卡访问灯 | 保持原连接；先不切模式、拔线或重复管理员验证 | 记录显示内容、有无错误/黑屏、访问灯是否亮或闪烁；尚待用户反馈 |
| 屏幕已回到普通USB/MSC | 先核对新缓存是否同机MSC及存储驱动；屏幕与缓存不一致时继续保留UNKNOWN | 普通模式、驱动和后续正常开关机分别取得证据；原试验仍保留历史HELD |
| 仍为SERVICE或黑屏，但没有更新/保存/访问活动 | 根据屏幕反馈再给出一次明确的手动正常关机/断开外部供电/重启流程 | 正常开机、菜单及原拍摄模式恢复；不能提前称为已经救砖 |
| 更新/保存提示、访问灯活动或状态不明 | 不建议断电，先澄清状态；不自动发STOP、重认证、reset或文件命令 | 明确可恢复操作的前置；仍不具备时停止设备动作 |
| 另做控制端STOP | 上游提供STOP，但正常调用位于SERVICE START/认证之后；本次未到该状态。未认证直接STOP的实机效果未知，且原锁尚未交接 | 需要独立、可审查的排他和恢复方案；当前不执行 |
| 写mode6或运行up.sh等社区做法 | 排除。本次没有执行这些脚本，也没有已证的mode文件故障 | 不能为了套用其他机型案例主动改变启动选择文件 |

上表是条件决策，不是要求用户立即拔线/断电。正常关机后仍须核对所有外部电源；只抽电池而USB仍供电不能证明完整断电。主机程序退出、普通USB恢复、相机能拍摄与固件救砖是不同验收。
