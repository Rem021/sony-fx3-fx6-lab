## 新增的实际代码

[front.c](front.c)在完整计划准备成功、运行核心返回之后，生成256字节`FX3LOCALRESULT1`记录。它携带nonce、完整文件SHA、规范化镜像ID、完整计划SHA、profile/controller关联、目标单调时钟窗口和PID/TID。固定文件位于已核验RAM目录下的`fx3-plan-preparation-v1/entry.local-result-v1.bin`；按0600排他创建并复读，不覆盖旧结果。

[result_protocol.py](result_protocol.py)要求调用者先给出外部预期的文件SHA、nonce、profile和controller，并与整个构建文件及配置匹配。解码时严格要求4字节原厂状态加256字节记录，核对CRC、保留字、所有关联和时间字段，再独立重建完整计划v2并比较其SHA。改变文件可写填充虽不改变运行时ID，也会因完整文件摘要不符被拒绝。

当前共享库为262144字节，完整SHA256为`e009b374283a8f8d0f1c1101f95c5b5d2ec0bd46530440d57f9c94b32ae30232`。构造入口、计划v2/IPC4、匿名监管和保留式跨加载占位沿用242；没有动态导出、shell、源分区读写或在线发送入口。[重复构建](reproducible-build/build.json)和231处地址引用/1155次算术核对均一致。

## 为什么记录不能表示全任务完成

记录只声称**运行核心已经返回的局部观察**。写入记录之后，还有它自身的同步、复读、关闭目录和最终时钟检查。模型明确保留了六种反例：这些后续步骤失败，构造器最终为HELD，但磁盘模型中仍可能存在有效的“核心11”记录。

因此解码器始终返回`LOCAL_OBSERVATION_ONLY`和`may_release_owner_or_flash=False`；它不证明记录关闭、setter返回、USB归还或全部资源清理。核心HELD、短记录、旧记录、原厂错误状态、错误身份/计划/时钟及损坏CRC都不能被转换成全任务成功。没有加入自动重试、删除占位或刷写放行。

测试中的“原厂回复体”是由模型将原厂状态字与自写C生成的记录拼接而来，**没有运行Sony GET处理器或实测USB回包**。外部给定的profile/controller也还不是经过认证的当前机身身份。

## 原厂读取路线的新核对

[静态原件合同](native-result-contract.json)固定经典FX3 7.02的`libJiritsu.so`，SHA为`bdef58b24a3b67b4d14d4f0214b89aae0fcad19f114b4188c328f9d2c092f1d9`。完整函数及原始字另存，不执行其指令。

- 高容量包装器的分派表将命令15送到选路径、16送到SET_FILE2、17送到GET_FILE2；包装器本身另有DMM会话阶段。当前代码只生成内层候选字节，没有实现或调用这些阶段。
- GET_FILE2的三个内部字节采用操作0、selector FF、模式0时，走文件读取；这与第一个字节为FF的缓存读取分支不同。正常模式的数据布局为状态字加文件内容。
- 操作0仍先调用`sys_mount`，目标为`/tmp/jiritsu`。它不会因此成为纯RAM或零副作用命令；认证历史写入、其它日志、挂载处理仍需独立审查。
- 模式0跳过额外数据变换，selector FF使路径解析器读取选定路径。固定候选使用`/tmp/jiritsu/../../tmp_wbshd/...`以指向自有RAM记录；原字符检查不拒绝这些点组件，但实际命名空间、挂载边界和安全解析均未实测，不据此发请求。
- 选路径保存在全局单元`0x467c8`，选择与读取是分开的请求，GET结束会释放它。若另一个命令改动该状态，固定请求字节本身不能证明实际读取的仍是自有记录；当前独占条件尚未建立。
- 设备端按stat得到的整文件大小分配DMM，而不是按主机接收上限分块。主机严格限制260字节回复不能反向限制机内分配。
- GET对fsync/close的返回值、SET对dlclose的返回值没有相应业务状态检查。SET状态0也不等于我们的构造器状态11。读到了有效记录仍不能补全这些原厂返回语义。

候选内层帧格式同时参考已固定的[A7CII请求源码](https://github.com/chocotan/a7c2-re/blob/2f66a0cd9732dd7900582e0213b5adb7761c4d1e/report/2026-10-18-libjit-exec/scripts/libjit_requests.py)，仅AST读取，未导入或执行。实际FX3认证级别、类别登记、DMM会话、全局路径独占和USB回复仍未验证；不能将两条候选帧当作可发送工具。
