# FX3：扩展IMOLA参数与原生缓冲复制、登记

本轮沿原HEVC码率封装继续执行参数生成片段，并验证了**原代码把448字节参数复制到池缓冲，再将缓冲地址/容量登记到索引**的路径。16M候选与原FF对照的整块448字节仍只差目标码率的3个字节，trace和CPB保持原值。

37段原代码片段、14次上一轮编译原型调用和5类负例通过。新的实际代码证据表明：重新选择原预置后，已登记的池缓冲仍保留16M，原预置指针复位不能证明这些数据已经退出。

**尚未运行完整构造器或硬件请求。** 原运行时清零和必经诊断未执行；前缀与后续是有明确输入假设的独立片段。全部相机访问、主录、恢复和救援仍未验证。

## 原参数生成推进到了哪里

原调用者0x21f7f4在0x21f85c把公共参数定位到owner+0xe198、编码参数定位到owner+0xe1d8，调用0x221b50的`create_imola_enc_start_param`相关实现。原日志路径名称为`common/imola2/imola_common_api_enc_handler.cpp`。

本轮没有伪造清零或诊断的返回值：

1. 用显式fixture初始化公共输出、输入对象与编码缓冲。输入包含1920×1080、stream14及用于通过此分支的其他人工字段；这些字段不是当前机身真实输入。
2. 从0x221b8c运行清零之后的独立前缀，执行原格式/对齐判断与原VUI帮助函数，在必经诊断0x221eec之前停止。
3. 将该前缀留下的寄存器、VUI栈值和已准备缓冲明确作为另一片段的输入，从0x221f50运行HEVC后续，执行原预置读取、各扩展字段、默认表复制和色彩帮助函数，在0x2227b0的函数体成功标记处停止，未执行函数尾声。

因此，这些结果不能证明“完整函数正常返回”。真实清零、诊断的作用、实际输入初始化和完整调用顺序仍未闭合。

扩展片段把原FF预置的参数继续写入编码区，并从原表复制0x118字节至编码区+0x88。目标16M、trace25,999,360、CPB26,000,000保持。对照原FF的24,498,176目标，整块448字节的差异仅位于+0x2d、+0x2e、+0x2f。

## 52个字节仍依赖进入前的内容

对编码缓冲分别填入0xa5和0xc3后，两个独立客体最终仍有52字节不同；这些位置恰好是本轮参数片段没有写过的字节，包括+0x1a0至+0x1bf的整个32字节尾部，以及20个内部字节。

这说明本轮片段不足以确定整个448字节对象。它**不证明原固件存在未初始化数据故障**：这些位置可能由更早的构造、初始化或其他分支负责，也可能是保留区。必须追到真实初始化与接口布局，不能自行补零后宣称请求有效。

## 原代码如何复制并登记

原调用者在0x21f8f0指定编码区复制长度0x1c0，通过0x21a3b8调用：

- 0x22c7d4从owner+0x1038指向的池队列取得缓冲，检查块容量，并调用原memcpy复制请求长度。
- 它返回缓冲地址及**池块容量**，随后推进池队列索引、减少可用计数。
- 0x21d4f8/0x21d58c从另一池取得索引节点，保存键及上述地址/容量对，并把节点接入索引。

本轮以人工填好的池与索引执行这些完整局部函数，没有替换任何分配、复制或登记返回值。容量512、请求448的正例中，实际仅复制448字节，缓冲后64字节保持；返回对和索引记录的是512容量。另一个容量恰448的对照也通过。容量字段不能直接解释为最终HAL发送长度。

成功之后，原池可用计数与索引节点池计数均为0，索引根仍指向保存缓冲地址的节点，缓冲中仍有16M参数。随后调用原预置选择器使owner+0xe000重新指向原FF，复制缓冲及索引记录保持不变。这是人工排列的原片段对照，不是实机竞态或全局退出测试。

## 在途登记必须跟随副本

使用上一阶段原型，测试者分别为准备源和原代码生成的缓冲副本提供登记。归还生产者和源登记后，副本登记仍阻止数据复原；原选择器复选后仍阻止复原。

**这些登记由fixture在原复制/索引发布之后提供，尚未接在真实发布前的钩子上。** 本轮只证明需要覆盖的依赖和原型的拒绝行为，不证明准入、登记与发布已经原子衔接。副本仍在索引中，未模拟归还副本登记，也没有宣称消费者完成、节点删除、缓冲归还或代码回收。

## 负例边界

| 条件 | 原执行观察 |
|---|---|
| 池为空 | 在原诊断入口停止，未复制缓冲 |
| 池块447字节，小于请求448 | 在原诊断入口停止，缓冲与可用计数未变 |
| 复制成功但索引节点池为空 | 缓冲已复制、原池已消耗，索引根仍空，然后到达诊断入口 |
| RcMethod人工输入2 | 到达对应原错误诊断，未完成后续参数构造 |
| 人工输入宽1921 | 原对齐检查到达错误诊断 |

所有错误路径都在诊断前停止，不能由此推断完整错误返回或清理结果。尤其索引节点不足的情况，需要继续追复制缓冲的归还和错误收尾，不能因为索引为空就认定没有在途数据。

原调用者0x21f87c调用参数构造后，至下一次缓冲准备调用前未显式按构造返回值分支；这只是该局部控制流的观察，不推断原固件缺陷或实际硬件接受。
