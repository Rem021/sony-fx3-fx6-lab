## 新增实现

`capture.py`固定读取配置为25,100,288字节、383×65,536字节，按128／128／127块分三组。`RegularFileSource`通过O_RDONLY固定一个普通文件描述符，核对外部保存的完整SHA、长度、单链接和元数据；不接受设备节点、符号链接或短载荷，不自动补尾。该长度是已有静态配置，不是本次实测7.02机身分区长度。

每次块读取前保存带本次capture ID及随机nonce的请求日志；精确核对回复、范围、长度、状态和来源，保存块SHA／CRC。三组清单通过前一组SHA串联。结束后再次计算来源全SHA、确认关闭来源，再读取已落盘的383块、生成镜像并完整回读，最后写完成回执。来源哈希会额外读取完整文件两次，不能将383个主块请求误写成全部系统读取调用数。

总预算600秒、块调用5秒均为调用前／返回后检查，**不能抢断正在阻塞的调用**。真实进程夹具证明阻塞期间不会发起第二次读取、提前关闭或生成完成回执。调用未正常返回时记录UNKNOWN_IN_FLIGHT并在同进程保留提供者；关闭失败为UNKNOWN_CLOSE，不重试。此机制尚不处理主机进程退出后的真实设备状态，也不是硬件看护或断电恢复证据。

新增命令`capture-local`与`verify-capture`均只处理本地文件，没有设备节点访问、动态插件加载、USB、Sony认证、工作器上传或运行Sony代码。内部提供者接口只接受local-regular-file类型；后续实际机身后端仍需另外实现与核验。当前命令的SHA用于复核已保存本地文件，不能给首次真实机身采集增加“事先知道机身SHA”的循环前提。

当前源码的[14项读取测试](runs/capture-tests-final/test-receipt/results.json)和[13项原有适配测试](runs/adapter-tests-final/test-receipt/results.json)全部通过，共27项。回执逐文件绑定当前Python源码SHA及各自测试源码SHA。

- 真实普通文件完成383块读取、三组留档、完整回读、重新验证，再生成限定候选并精确还原。
- 短读、超长、错偏移、错capture／nonce、错误／布尔状态、来源变化、错误数据、未明调用、KeyboardInterrupt和关闭失败均拒绝完成。
- 真实子进程在读取中等待，主进程观察其日志及未关闭状态，再协作解除等待；超时返回拒绝，无强杀／重置／第二次调用。
- 注入证据写入失败后保留先前块，不继续采集；篡改完成标志、重复JSON键、尾块、窗口链和外部SHA均拒绝；链接、重复输出和原件路径保护通过。
