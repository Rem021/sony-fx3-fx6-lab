# FX3 7.02 Darwin复位映射与自身更新回跳

2026-10-29。**已用当前FX3原字节补齐Darwin核心的`0x4200`布局映射，并定位一条“内部初始化通信 → 条件事件 → Seton更新分支 → Upd主函数 → 地址0/4向量”的局部链。** 这是Darwin自身更新方向的证据，尚不是AP的p1救砖入口。它改变了下一步应追的具体对象，仍不能发布真机刷写。

仅读取已保存原件并运行宿主解析/静态校验。没有执行Sony/guest代码，没有相机、USB、管理员、驱动、Windows、UU或GUI操作。195 root01仍待此前具体回答，固定作业未创建，不重复询问；16项目标、全部授权和原候选保持。

## 先修正映射，再读函数

原件沿用[198从完整7.02 FDAT提取的darwin_core.bin](../stage198-AP-CP-loaders-and-partition-selection/originals/darwin_core.bin)，243000字节，SHA256 `ac3fe4cb9d7122b196d33ca3514d0eb4e2d3abbed882926d4e08d5b26b76afe0`。

本轮联网看到[A6000研究状态页](https://github.com/nicolvus/a6000-fw-decomp/blob/main/docs/STATE.md)明确更正其Darwin基址为`0x4200`。仅把它当假设，在FX3自己字节上独立核对：

- 首部word为初始SP `0x200026D0`，复位指针为`0x45F9`；该映射把复位入口定位到文件`+0x3F8`。
- 原始Thumb BL位域解码与Capstone一致，复位桩调用`0x4674`。随后的LDR从`0x4670`读到`0x43FD`并BX过去，落入运行时初始化桩。
- 其余异常向量也对应到MSP/PSP异常处理入口及故障循环。此前0和0x4000仅为未成立的候选，198原记录保留；本轮不继续使用它们解释更新函数。

[向量原始编码与四份切片](vector-source-proof.json)。这是自洽的来源布局映射，不声称机身实测PC、MCU具体料号、唯一可能的运行时布局或所有路径都能执行。原件的绝对字符串指针未匹配不构成反证：本轮用ADR相对引用定位了实际日志；[283个ADR候选](ADR-reference-candidates.json)仍可能包含数据或宽指令后半字，不整体当作可达代码。

## 当前原件的条件更新链

以下地址采用该来源布局，仅记录条件成立后的局部行为，不给出发送/切模式操作。

| 阶段 | 原字节证据 | 范围限制 |
| --- | --- | --- |
| InitCom `0x4E5C` | 内部收发正常返回0、CRC比较相等后，命令`0x11`分支把下一字节写给输出指针；子值4的选中路径保留状态0返回 | 未完成外部发送者、整条SIO驱动和全部错误路径证明 |
| 本地生产者 `0x18004` | 以选择参数3调用SVC#0xC，返回且首halfword为0xA时调用InitCom；返回0且输出4，会构造halfword对`[0,4]`，再以选择参数0调用SVC#0xB，传`0x00040000` | 只确认调用参数/局部数据流；SVC队列实现、实际交付及物理可达未验 |
| Seton main `0x86C8` | 接收调用之后，若两个halfword为`[0,4]`，保存结果2；正常ABI模型下经清理返回2 | 清理子调用必须正常返回并保持r4；没有执行它们 |
| Seton next `0x883E` | 给定结果2，原表`[2,3,5]`选择状态5 | 退出回调/异步代码不能在下轮取值前覆盖状态，仍是显式假设 |
| 分派循环 `0x4B06` | 状态表base `0x38B60`，记录长度16；第5项先指向`0x99CD`，随后`0x99D1` | 第5项后两个指针为0，不能假设异常返回时仍有完整退出合同 |
| Upd main `0x99D0` | 日志文字可核对；准备中写`[0x20000706]=4`及下一byte0，再以r0=0调用`0x45DC` | 是MCU内部状态，不能混成AP的loader/up.sh模式号 |
| 转移叶函数 `0x45DC` | 从`[r0]`设置MSP/PSP，最后从`[r0+4]`取PC；给定r0=0，目标来自地址0/4 | 这两个目标word的同机原件与实际行为尚未取得 |

## 这不等于AP救砖

目前必须区分三个对象：Darwin地址0/4的向量目标、AP的eMMC boot0早期程序、以及198已追清的CP固定交接。它们不是同一个bootloader，也没有因某个编号相同而建立连接。

这轮说明当前Darwin核心含自身更新回跳逻辑；没有证明核心损坏后还能由按键、USB或电脑独立触发，也没有证明跳转后会暴露Fastboot或能重写AP的p1/p3。[当前包的Darwin更新清单](darwin-package-coverage.json)只列`darwin_core.bin`；本轮未取得独立Darwin启动程序、FX3同机eMMC boot0或当前p1。没有将历史2.05 p1代作当前备份。
