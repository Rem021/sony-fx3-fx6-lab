# FX3：类型4分配器与首次缓存缓冲

本轮将“空缓存记录没有缓冲句柄”的断点推进到**原分配器实际生成句柄、原缓存调用者保存句柄并复制48字节参数**。原池耗尽时返回空句柄并进入原错误分支；原引用减到零、归还和重借也在单实例RAM中完成一次。

这仍是有明确跳过区间的离线实验：**注册前检查/IRQ、缓存维护、缓存调用者的IRQ获取和释放均未执行。** 没有据此证明实机同步、全局所有权、正常调度、MAIN、硬件或恢复。仅Mac，未操作Windows/UU/相机，无可刷包，16项要求和授权保持。

所有地址/偏移为十六进制，数量和容量另有标注。7.02 VCD原映像固定哈希保持；未修改磁盘上的固件字节。

| 缓存首次请求 | 原`140d40`在已有句柄为空时自然准备类型4/大小`11c`（284字节），调用原`5ef3c`分派器 |
| 原虚调用 | 原注册槽和原ROM vtable把类型4分配绑定到`606d0`，归还绑定到`60068`；仅放行这两个已核对的原JALR目标，没有替代函数或假返回 |

原工厂和固定池构造完整执行到`5d304`缓存维护指令前，再从原`5d318`独立续接：保留原栈/寄存器，执行原读取、尾声、返回及原注册槽保存。**没有执行或替换缓存指令，不声称缓存一致性已经建立。** 缓存调用者从原`140d04`的IRQ前停点，另续原`140d40`；分配结果存入后停`140da0`，再从IRQ释放后的原`140dd8`续接。所有跳过区间在结果中登记。

## 观察器与失败尝试保留

原构造函数`60570`附近存在DIVU/BEQL/BREAK。对同一原指令组以声明除数128、1和0校准：前两组分别得到512、65536，无中断；0组确实产生中断18。CODE观察会包含被取消的BREAK延迟槽地址，不能把观察到地址等同于执行了BREAK。正式场景均无实际中断，没有指令替换。

两次准备错误及执行源码均保留，未计为通过：

1. 初始工厂入口`5d97c`少包含原`5d978`设置arena参数的指令，构造未获得正确参数；完整栈/数据核对拦截。修正为从`5d978`执行原参数设置。
2. 虚调用后，callee保存的是分派器已更新的提供者/请求长度；初始离线栈预期误用了外层调用者的值。实际数据匹配而完整栈核对失败，按原指令修正预期，检查范围没有放宽。

正式结果采用`run-corrected-call-frame-20261027/`。所有数据区域、完整栈、原映像（仅已声明运行时全局允许原写）逐字节核对；未安装逐次内存读写钩子。
