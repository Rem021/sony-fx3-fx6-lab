## 恢复的矩阵参数规则

原 `Matrix_Process::Mtx_one2one`（`0x46994`）先按 `2^fraction_bits` 缩放，再执行上限／下限处理、符号相关四舍五入。模式 1 在取整行和非零时做归一化；非零模式随后通过对角元素修正，使行和回到缩放单位。源代码的正上限分支是严格 `>`，不能擅自改成 `>=`。原 `SET_MTX_data` 的相关调用使用 fraction_bits 16、limit_exponent 19；这个限制指数不能直接解释为整个硬件的 signed19 饱和范围。

在隔离 Unicorn 中执行原量化函数及原 `vector<vector<double>>` 构造，宿主只替代 `new/delete/memcpy/ldexp`。138 组有限数值样本与独立翻译完全一致，包含单位矩阵、FX3 已有 VENICE 矩阵、半单位取整、零行、正负边界和 64 组确定性矩阵，分别覆盖模式 0／1。这不是任意 NaN、无穷值、所有枚举或全部数值域的证明。[量化及寄存器字符串回执](art-matrix-guest-results.json)

FX3 现有矩阵经上述转换后，模式 0 和 1 都保持：

```text
 75487  -7714  -2237
 -2656  79077 -10885
  -807    475  65868
```

另执行原 `LMX_data2byte`（`0x46dd0`）的循环、子串位置和目标存储，用具名短字符串子串构造 shim。三组样本确认 8 位十六进制字符串按低字节在前拆为四字节。既有 VENICE 矩阵的九个系数共 36 字节，与原 FX3 AV 镜像中实际表载荷的系数部分逐字节相同；原表另有四个控制字 `[1,0,0,0]`。负数先加 `2^19` 的准备来自 `Basic_Info::dec2hexa_keta` 的静态指令，该格式化函数本身没有在此执行。[原表与字节比较](matrix-serialization-comparison.json)

这个结果支持复用部分数值及序列化规则，不能把“已有的同一矩阵相同”称为新的全套 VENICE 色彩移植，也不能证明其他矩阵、LUT、传感器标定或原厂自动白平衡已兼容。

## 参数分派与寄存器标签

原 `ArtModeController::setParamData`（`0x1b228`）的 72 组 descriptor 分派检查通过：38 组调用相应 setter，34 组没有调用。执行了原 caller 的分支与目标字段偏移；三个 setter 和 descriptor 插入为记录 shim，不冒充实际处理或动态容器执行。仅按观测的 controller/type/stage/selector 数值记录，没有给未知枚举强加公开相机模式名称。[分派回执](art-dispatch-guest-results.json)

另执行十个原寄存器标签赋值函数，字符串赋值为宿主 shim，无真实寄存器或 MMIO：

| 原函数标签 | 恢复的十六进制字符串标签 |
|---|---|
| Lmx0 | `0200`…`0224` |
| Lmx1 | `0240`…`0264` |
| Lmx2 | `0280`…`02A4` |
| Lmx3 | `02C0`…`02E4` |
| Lmx4 | `0700`…`0724` |
| MTX | `00CA`…`00DB` |
| DEMTX | 依次赋值 `0086`…`0097`，同一对字符串会被反复覆盖 |
| Lut1D0 RAM | `0103/0109/010F` 及反向配对 |
| Lut1D1 RAM | `0183/0189/018F` 及反向配对 |
| Lut1D2 RAM | `0803/0809/080F` 及反向配对 |

例如 ART 的 Lmx0 使用 36 个系数字节标签及额外控制标签；FX3 的原描述符在 register offset `0x200` 处提交 13 个 32-bit 字。数值碰巧同为 `0200`，仍没有建立两种接口的等价关系，不能按标签直接跨机型复制寄存器块。

## type4 内层的新结构线索

三份已下载官方原 `BERLIN/DATA23213` 再次核对原摘要，尾部最后 16 字节均为一个 little-endian u64 和八个空格：

| 版本 | 实际长度 N | 尾部 u64 L | N−L |
|---|---:|---:|---:|
| 3.92 | 287,442,920 | 287,442,620 | 300 |
| 4.10 | 286,877,016 | 286,876,716 | 300 |
| 5.00 | 287,401,488 | 287,401,186 | 302 |

三版都精确满足 `N = ceil(L / 8) × 8 + 296`。这是可复核的长度关系；L 的语义、296 字节的分布，以及头部、签名、IV、摘要或加密区位置仍未知。没有检查解密后的补齐字节，因此不能据此指定 3DES、Blowfish 或其他密码算法。

在每版 12 个明确的头／尾候选位置，以两种字节序测试 FX3 官方 FDAT 公钥，共 72 例，未得到有效 PKCS#1 v1.5 格式。这个负结果仅针对该公钥、位置及签名格式，不能排除其他密钥、位置或签名方案。[尾部回执](donor-footer-results.json)

对已提取 FX3 文件树与 RAW Viewer 的 MacOS／Frameworks 三个具体目录，共 83 个普通文件、483,617,525 字节，搜索五个确切容器标记，未命中。这不是对所有固件／程序的穷尽搜索，也不排除无字符串或混淆的加载器。[完整范围和文件摘要](loader-marker-scan-results.json)
