## 原Open分支生成了什么

先执行`2de7364`原序言至日志入口，保留原保存帧和输入指针；再从DMM映射之后的原`2de74a8`进入，明确给出输出地址。没有执行或补造DMM分配/映射结果、日志返回或整个Open成功。原指令从哨兵填充的98字节输出区生成格式、宽高、帧率、扫描、质量、色度和位深字段。

## 4208结论的具体来源

原应用构包体明确把输出`+94/+95`写为0。原调用点分别从对应字段读取色度和位深标量，原转换及名称函数把它们解释为`CHROMA_420`和`BIT_DEPTH_8`。本轮没有通过宿主预填输出0来取得该结果，原始输出区开始为A5或C3。

HEVC分支还由原代码生成外层格式字节31、原视频格式字节10；原编码转换器据此返回`STREAMING_HEVC_BSF`。这与目标MAIN逻辑中要求的MP4分类和10bit参数不同。

**这只是此原构包分支在已声明输入下的参数含义。** 没有实测SRT流/SPS，也没有证明所有FX3网络模式只能8bit、硬件不能10bit、或这条命令绝不能用于其它编码实例。它说明的是：这份推流Open配置不能直接作为目标42010 MAIN已实现的证据。
