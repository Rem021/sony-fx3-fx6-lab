## 原 CP 解析与独立交叉核对

CP 原件 SHA-256 为 `c90d00d807874a5309dc1b65b203287e83608ceee513cc57b53409333fb6bcba`，VA = 文件偏移 + `0x108000`。

在 Unicorn RAM 中执行原 `0xab8b70` 公共配置解析和 `0xaba7b6` 单位表解析。唯一数据适配是：把原 `dmm_module_GetConfigData` 入口替为**明确的顺序文件读取适配器**，逐次从上述原 CP 文件读取指定长度并记录偏移、目标、摘要。原解析、内存复制、终止标记处理、索引写入和保存寄存器检查执行；未提供内核／上下文、物理映射、分配器、锁或服务回复。

因此此实验证明“原解析器如何解析这份文件”，不证明正常启动确实把该文件通过参数 `0xfa0182` 交给它。

原公共配置解析返回 0，文件偏移到 `0x9344`；原单位表解析返回 0，最终偏移 **`0xa938 = 43,320`**，无剩余字节。结果为 1 个根组、164 个规则组、348 个单位，以及原 44 字节版本字段：`for ilc8g8g-ipsxcp       2025/02/10 10:35:08`。

复用阶段128的纯宿主解码函数作为独立参照，只提取其纯函数 AST，不导入或运行内核／设备工具。与原客体结果比较：

- 165 个组头的原字段完全一致；客体首指针为原解析器新写入的 RAM 指针，单独核对其指向。
- 1,052 条原 20 字节记录及每组终止标记完全一致。
- 348 个单位的顺序、编号和 extent 列表完全一致，原文件消费字节数一致。

## 当前 NRV 单位 `0x4af` 的对应关系

原单位表解析结果：`0x4af → [0x62a]`。此后执行原查询函数：

1. 原 `0xab9830` 用 `0x4af` 找到配置，停在 `0xab9a5c` 槽位申请第一条指令前；没有申请槽位或图像缓冲。
2. 原查询对不存在的 `0xfffffffe` 返回 `0xfffffffd` 并写 `0xffffffff`，原保存寄存器和栈检查通过。
3. 原 `0xab8ea6/0xab8ef2/0xab8eb2` 返回规则根、extent `0x62a` 的映射数 1 和规则索引 1。在该规则中找到两条相同的原记录：

```
u32+0x0 = 0
u16+0x4 = 7
u16+0x6 = 0
u32+0x8 = 0x62a
u32+0xc = 0x25b480  (2,471,040)
u32+0x10 = 0x10f
```

这些是文件中的原配置字段。**一条单位列表项不等于一次真实申请只产生一个物理块；两条规则记录也不等于已分配两个图像缓冲。** 活跃规则选择、物理区域、缓存属性、真实句柄／占用、尺寸语义、MAIN 像素绑定仍未证明。报告保留原字段宽度与值，不从大小猜图像分辨率、位深或缓存芯片型号。

## 正常参数与地址域缺口

原 `0x4982ee` 调用 `0x4985c4` 时提供 `0x04000000`，后者检查 `BK4` 并建立参数表；原 `0xa85174` 查询逻辑从该表查参数。DMM 获取配置仍通过 `0xfa0182` 查询 64 位源值。没有取得该表的正常上游生产者或本机当前内容。

按只读常量范围表 `0xb54930` 推导，CP 逻辑地址 `0x04000000` 对应的候选物理地址是 `0x804000000`；这只是静态映射表推导，未证明当前 MMU 状态。重新核对原 WBI SHA 和 1,399 条记录，其物理范围在 `0x400001000..0x420000000`，没有记录覆盖该候选地址。**AP WBI 不能作为这里 CP RAM／BK4 参数的回读证据。** 未合成遗漏页、物理地址或参数值。

下一步查 CP `BK4` 参数表的上游装载／`0xfa0182` 写入者，并核对原单位槽和 extent 分配依赖。完整 FX5 私有系统、VENICE 内层／实时 ISP、传感器 RAW 与校准、整套菜单移植、修改包准入和正常启动／独立恢复门槛仍未通过。目标保持 active，实际刷机前停止，未输出修改固件。
