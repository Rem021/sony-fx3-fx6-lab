# FX3 Linux AArch64 只读工作器候选

`fx3_p1_reader.c`是新编写的显式入口`fx3_p1_read_window()`，没有构造函数、preload修改、USB、认证、加载器或相机分区写入。0.3仅有可重定位对象；0.4新增`entry.S`与限定链接器，生成**静态ELF64 AArch64可执行文件格式**，在ARM64模拟环境中执行自写机器码，内核调用仍是夹具。没有在相机上加载或执行。它不是完整的机身读取后端；权限、同机绑定、启动、传输与退出路径仍缺。

## 固定合同

- 仅接受root身份。固定打开`/tmp_wbshd`，以打开的目录描述符调用`fstatfs`，要求tmpfs、可写和足够可用空间；不自动挂载或清理。输出使用0700新目录和0600独占新文件。
- 请求固定为该RAM目录内的`fx3-p1-request-v1.bin`，64字节、root所有、0600、单链接普通文件。检查完整请求、CRC、随机capture ID、三组固定范围与保留位；不会创建、修改或删除请求。
- 从`/proc/partitions`核对唯一的`pnflasha1`／`cnflasha1`及各25,100,288字节容量，选中`cnflasha1`。固定以O_RDONLY／NOFOLLOW打开`/dev/cnflasha1`，核对块设备、内核设备号及前后元数据，不假定252:129。
- 使用FX3原DeviceIo已识别的`BLKGETSIZE` ioctl0x1260，要求49,024个512字节扇区，读取前后都核对；不提供其它ioctl或回退路径。它仍需要实机确认支持性及当前容量。
- 每次调用只读一组，最多128个65,536字节块，使用显式`pread64`偏移；每块仅调用一次，不补短读、不重试。检查实际长度、缓冲保护区和调用前后的单调时钟。块预算5秒、读取阶段总预算60秒是返回后检查，不能打断阻塞调用，也不能保证所有元数据／文件操作的完成时间。
- 只向已核验tmpfs目录输出`request.bin`、`chunk-NNN.bin`和`manifest.bin`，不修改源分区，不碰`/etc/ld.so.preload`，不删除任何旧文件。空间不足或同名目录存在即拒绝。三组累计约24MiB，必须由未来传输方案另行规划内存与残留处理。
- 分区关闭成功后才生成清单。清单本身的写入／关闭／目录同步仍可能失败，因此**必须同时取得正常函数返回0**，不能只看manifest文件存在。所有close仅尝试一次；失败保留未知状态，不重新关闭。
- 同进程入口只允许一次。只有HOST_FIXTURE构建有重置入口，生产对象不存在该入口。

固定长度来自已有静态研究配置，未在当前7.02机身上测量。单组内部有元数据检查，但分组间仍可能发生内容变化；它不提供原子快照、当前机身身份认证或独立救砖证明。首次真实备份仍需另外评审的同机绑定与独立一致性方案。

## Wire与主机接入

请求64字节、块头128字节、完成清单128字节，均显式小端编码，带capture ID、固定全局偏移、真实长度、设备号及CRC。格式由[Python解码器](../fx3_recovery/worker.py)独立解析。保存三组输出后可用`assemble-worker`在本机重新组合完整文件并回读；这个命令不启动C代码或接触相机。

调用者提供的返回码会明确标为未在相机独立观察，全部硬件／来源／救砖标志保持false。伪造一个0不能成为认证、机身身份或服务已正常退出的证明。

## 构建与验证边界

本机Clang交叉编译固定C与汇编入口；新编写的限定链接器只支持当前对象中出现的ADRP、ADD低12位、64／128位LDST低12位及CALL26共5类重定位。59处均核对指令、目标、范围、对齐和回算，不支持的类型、外部导入、初始化段、RWX或异常入口均拒绝。未安装新链接器。

输出为20,480字节静态ELF、固定研究布局；R／RX／R／RW四个载入段，GNU_STACK为RW／不可执行，无动态加载器或导入。`_start`调用读取函数后以Linux syscall93返回实际状态；阻塞调用不返回时不会越过它退出或清理。不提供设备启动／上传入口，Linux ELF格式本身不证明Sony内核接受或相机能恢复。

当前47项本地检查包括原有Mac构建的系统调用夹具，以及Unicorn2.1.4实际执行本次生成的ARM64机器码。后者完整跑三组、383块，通过链接器生成的地址和原始SVC寄存器传参，不替换工作器内的CRC／循环／清理指令。系统调用才进入自建提供者，设备节点、root身份、Linux元数据、容量、时钟、FP／SIMD状态和tmpfs属性均是声明的模型条件。输入为明确标记的合成参考文件，输出为真实本地文件。它是指令级程序验证，不是FX3整机仿真、真实Linux启动或设备驱动验证。

构建命令只需本机既有Clang和Python标准库；ARM64测试复用项目既有的`stage4-windows-collab/mac-verification/.venv`，不安装新依赖。所有生成文件留本地新目录，原件和旧版本保留。

[Linux4.9 statfs UAPI](https://github.com/torvalds/linux/blob/v4.9/include/uapi/asm-generic/statfs.h)用于核对fstatfs字段；`pread`允许短读，工作器按合同拒绝而不填充或补读。[pread手册](https://man7.org/linux/man-pages/man2/pread.2.html)。源结构沿用已保存的FX3原代码研究，不能以通用Linux文档替代当前Sony内核实测。
