# FX3 EXBL 启动信息来源与 MIS 原读取格式（2026-10-29）

**仍没有可正常刷入 FX3 的 VENICE／FX5 色彩链修改固件。** 本轮将上一阶段缺失的引导表与原 `EXBL` 检查对应起来，排除了公开 FDAT 中唯一明文命中作为信息块的可能，并从 FX3 原代码确认了 MIS 的三项参数表。没有将配置地址或单独函数前缀当作真实启动、DDR 初始化、CMOS RAW 或完整 ISP 的证明。

开始及写入前核验目标外盘 UUID，沿用 Mac 的非 Git 项目根；独立回读[上一阶段](../cetus-sender-20261029/README.md)28个封存文件，原件和另一 agent 的文件保持只读。

## EXBL 引导信息尚未取得

原 NOR `0xfe0588a4` 将 `0xfe040000` 开始的4字节与原字符串 `EXBL` 作有界字符串比较，不匹配时返回 `-409`。此处的比较函数有 NUL 处理，宜称有界字符串比较；对本轮不含中间 NUL 的 `EXBL`／`MIS_HEAD` 前缀，其比较结果与定长字节相等判断一致。

原信息读取器 `0xfe058794` 采用 `0xfe040050 + (index-1)*0x40`，第2、3、5项字段分别落在 `0xfe040090`、`0xfe0400d0`、`0xfe040150`。上一阶段的 CPAPP-B 块加载器正是还缺这一信息区的数据。

维护者公开的[另一型号 boot0 解析器](https://github.com/DavidBuchanan314/ILCE-7M4-RE/blob/eed29146304bb08576711a5e702a42c27df2cd0d/scripts/parse_emmc_boot0.py)把首 `0x800` 字节信息块复制到 `0xfe040000`，并列出 `+0x68/+0x6c/+0x74/+0x78` 四个装载字段。这与当前 FX3 原配置的 awake 地址关系提供了比较线索。已固定源码提交及 SHA，并且**只保存为文本、只比较元数据**；没有运行解析器、取得 BootROM／密钥或解密其他型号载荷。它不能证明 FX3 的实机 boot0 已可读取，也不能证明两型号格式完全兼容。

对完整 **808,704,512字节**原解码 FDAT 作明文 `EXBL` 搜索，只有一个命中：

| 坐标 | 值 |
| --- | --- |
| FDAT | `0x2faf06ff` |
| 外层成员 | `0750_nor_loader/loader_nor.tar` |
| 内层 NOR 文件偏移 | `0x166ff` |
| NOR 静态地址 | `0xfe05f6ff` |

已从嵌套 tar 原字节独立核对，它是 NUL 分隔的四字符比较字符串，恰被上述原检查引用；按公开格式读取的候选字段也是后续日志文本，不是信息块。**本轮没有得到完整 FX3 EXBL 前缀。** 搜索结论限定于该原解码容器的明文；它不排除另外压缩／加密的表示、其他来源或机身上的独立数据。

## MIS 三项表由 FX3 自己的读取器确认

只读复用另一 agent 阶段198的原件，核对固定 SHA，并在封存时另从原 p8 FAT12 镜像独立回读比对；没有导入或运行该阶段带顶层写入的脚本。

- DGU：24,336字节，SHA `39eeb6d572a060149194463507800ed66b866a20dceb8ed49b01a04eb6fb2ba7`。
- MIS：119,296字节，SHA `4cd3e9bc3a0a4aec4793bff77e7ca4dccdba8637212cd632cdc5ecbe550daf98`。

原 `0xfe056024` 先通过引导信息第2、3项取 DGU／MIS 指针，再以模式参数 `0x10` 尾调用 `0xfe055d14`。后者比较8字节 `MIS_HEAD`，从 `+0xc` 取32位基址，从 `+0x12` 取16位计数，再从 `+0x14` 起逐项读取32位偏移。原 `0xfe055e30` 将基址与偏移相加，随后作为第二参数间接调用 DGU。

当前原 MIS 的文件长度与 `+8` 长度字均为 `0x1d200`，声明基址 `0xfe080000`，原读取器得到计数3：

| 项索引 | 原偏移 | 原加法得到的第二参数 |
| --- | --- | --- |
| 0 | `0xa00` | `0xfe080a00` |
| 1 | `0xc200` | `0xfe08c200` |
| 2 | `0x13200` | `0xfe093200` |

三项首16位数值均为 `0x100`；本轮未恢复完整解释器语义，没有将这些数值命名为芯片容量、DDR 时序或图像尺寸，也没有仅凭相邻偏移定义每段实际长度。原版本日志使用的 `MIS+0x123` 文本为 `600019`。DGU 原入口含缓存维护指令，只作静态核对，没有执行。

## 两组原指令前缀的实际边界

仅在隔离的 Unicorn RAM 中运行原 NOR 指令，不适配函数成功返回，不提供引导表、控制器或设备回复：

| 实验 | 结果 |
| --- | --- |
| 原完整调用入口 `0xfe056024` | 11条原指令后，在 `0xfe0587b0` 读取未知 `0xfe040090` 时停止 |
| 独立直接调用原 MIS 读取器，明确传入原 MIS 与原配置地址 | 99条原指令；原头比较返回0，走版本日志分支；在日志函数入口停止 |

第二例是明确输入下的独立函数检查，没有补齐第一例的真实引导信息。它停在原 DGU 调用之前，不能表示 DDR 初始化完成或正常启动。没有非栈 RAM 写入，也没有执行任何 DGU、CPU 维护或原生 Sony 程序。

## 对完整移植目标的影响

本轮确认了原内存初始化参数的组织方式，同时更明确地限定了缺失的早期启动输入。下一步可继续查原 DGU 对这三段参数的消费和装载信息生产格式；不能用人工构造的信息块把真实交接、DMM 装入或硬件能力标为通过。

[2026-10-29 再查的 Sony 日本 FX5 下载页](https://support.sony.jp/electronics/support/camcorders-and-video-cameras-interchangeable-lens-camcorders/ilme-fx5/downloads)仍显示该页暂无更新信息。本轮没有取得新的完整 FX5 私有包，不据此声称全网不存在包。既有 VENICE type3/type4 内层、完整实时 ISP、CMOS 校准与 RAW 读取、专业菜单／主录绑定、修改整包准入、正常启动和独立恢复均仍待证。

持续目标保持 active，未达到用户指定的可正常刷入门槛。未生成修改固件包、未刷写，也未操作另一 agent 的 USB／恢复工具、设备或租约。公开源码一次 TLS EOF 和随后的正常 TLS 取回均保留记录。
