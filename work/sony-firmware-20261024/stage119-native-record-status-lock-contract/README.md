# FX3 原录制状态与锁配对

2026-10-27，仅 Mac 的 Unicorn 客体。完成 30 例、50 个原代码有界片段。**发现原录制状态更新 API 的锁配对要求，并定位参数保存、RecStart、RecStop 共享的 API 互斥锁；尚未得到真实空闲状态或配置代次证明。** 所有锁/日志/事件/录制服务本体均未执行，未访问 Windows、UU、相机接口或媒体，未修改固件。

## 可以据此改进的方案

| 原 API／数据 | 本轮证据 | 对诊断候选的影响 |
| --- | --- | --- |
| `getMovieRecStatusOutParam` 构造器 `c9660` | 原 memset 清 136 字节，再写头字 `0x53` | 全零正文只是构造默认值，不代表机身处于空闲 |
| `GetMovieRecStatusInternal` `f3f7c` | 读锁后复制 136 字节，随后解锁并返回 | 仅保留为内部读取候选；实际调用上下文、装载及锁仍须验证 |
| `GetMovieRecStatusForUpdate` `f41ec` | 写锁后复制同一状态区，原函数返回前无解锁 | 排除出只读诊断；这是更新事务的一半，不能按普通 getter 使用 |
| `SetMovieRecStatus` `f3d2c` | 本体没有加锁；比较后按条件复制，并走解锁/通知路径 | 不单独调用，不作为只读 API。所需预持锁是本轮声明前提，未真实获取 |
| `UnlockMovieRecStatus` `f4250` | 经原包装器将锁对象地址加 8，进入 pthread 解锁前停止 | 不能凭函数名称跳过事务配对和所有权验证 |
| 无输入版 `GetMovieRecStatus` `f4168` | 构造 48 字节输入、头字 `0x52`，转发至完整重载前停止 | 不能把它等同于本轮已经执行的内部读取器 |

地址均为原 `libmpr.so` 的 ELF 虚拟地址，**不是当前相机进程的绝对地址**。动态加载基址、符号绑定及 Sony ABI 没有实机验证。

## 三个同步对象必须区分

- 录制状态：`s_movieRecStatus` 位于 `38d4f8`，长度 136；`s_movieRWlock` 位于 `38d478`，原 pthread 调用使用对象 `+8`。
- 录制参数：阶段 116 已核对 `38c810` 的 445 字节保存/读取，以及 `38cc30` 锁对象。它与状态锁不是同一对象，独立读取不能构成共同快照；参数内的辅助数据指针也不因此变成独立拥有的数据。
- `SetMovieRecParam`、`RecStart`、`RecStop` 的原调用片段都通过同一 GOT 项加载 `g_integApiMutex`（ELF `372190`），然后调用 pthread mutex lock。本轮只核对这三处进入锁之前的实参，没有执行锁，也没有证明它覆盖全部异步写者、完成回调或配置切换。

这给后续方案提供了原生同步边界候选，不能直接把自编译前端里的人工 `idle/epoch` 字段替换成某个状态字节。真实上下文、锁顺序、重入和异步生命周期仍缺。

## 状态写回与通知的实际范围

两种填充值下分别对照不变、强制通知、三处已比较字段改变，以及头字/填充字节改变。原函数仅在被比较字段变化时复制整个 136 字节；强制通知且被比较字段未变时，只准备通知。单独修改本轮所测头字或填充字节不触发复制。因此它不是完整结构合法性检查，也没有提供递增配置代次。

本轮观察的通知输入为事件值 `0x1004`、16 字节载荷和 9 个变化标记，停止于 `SetIssueEvent` 前。这个整数及变化标记不能直接绑定至阶段 118 的应用层注册项；跨命名空间/回调路由没有在本轮执行。没有把“准备了通知”称为已经发布或已被消费者处理。

原 `UpdateStartSlotId`、`GetStartSlotId` 和 `ProcessWriterEvtStopCmp` 等上下文也调用状态更新配对 API。本轮保留相关反汇编作为静态后续入口，没有执行它们或给状态数值命名为空闲/录制中。
