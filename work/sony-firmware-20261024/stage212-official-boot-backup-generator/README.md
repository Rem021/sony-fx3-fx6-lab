# FX3 官方启动配置生成器与 AP／CP 写入边界

2026-10-29（本地日期）；经典 ILME-FX3 7.02；仅本机现存文件静态分析和公开来源核对。

**已核实官方 `bksb.elf` 怎样区分 AP、CP 启动属性，并纠正此前 NOR 加载器的适用范围。** 当前包的 `nor_loader_writer.sh` 将该 NOR 组件用于 SPI／CP 更新流程；AP 则另有 `loader_writer.sh`，调用 eMMC 启动区域。不能把 NOR 组件中的早期菜单、模式、计时或初始化代码当作独立 AP 救砖入口的证明。

这里说的是包内脚本和选中代码路径。没有执行真实启动，没有测量这台机身实际的 CP／NOR 硬件配置，也没有证明官方脚本的每一条分支都会在经典 FX3 上运行。

## 启动属性块的真实合同

当前 7.02 Ubody 中提取的 `bksb.elf` 为 18,568 字节，SHA-256 为 `c14f9fd70302d67f45ab50b3edc130b40d471f3415bc40a20e7a30d7b815ddb9`。原件、ELF 虚拟地址映射、15 个原始字节范围及脚本行号均有固定记录。

- `-m` 将输出路径放在索引 0；`-c` 放在索引 1。主流程把这个索引传给记录选择函数。
- 索引 0 直接使用 `Backup.bin` 首记录。索引 1 按首记录中 `data_offset + data_bytes` 向上对齐到 4,096 字节，取得第二记录，再初始化读取器。与第 208 轮当前主程序的 AP／CP 记录分工相符。
- 输出为 `BKSB` 四字节魔数、四字节小端项目数、每项 12 字节的 `ID/offset/size` 表，以及按四字节补齐的属性数据。首数据偏移为 `8+12*N`。
- 这是按清单抽取的**启动属性子集**。它不是完整 `Backup.bin`，不是完整启动分区，也不包含可独立恢复整机的全部数据。

## AP 与 CP 不能共用这份清单

当前包内 `loader_nor.tar` 的 `LdrBkupList.txt` 有 65 个唯一属性。其配置为 `LdrBkup.bin` 分配 4 个 512 字节扇区，即 2,048 字节。清单和配置属于所审查的 **CP NOR 路线**。

重新核对第 207 轮保存的 11 份经典 FX3 官方默认模板，共 22 份有效 BK4 记录：

| 记录 | 65 项清单的结果 | 按静态格式预测的长度 |
|---|---|---|
| 第一份 AP 记录 | 均缺少 `5D000B/5D000C/5D0011/5D0012` 四项 | 不产生完整长度结论 |
| 第二份 CP 记录 | 每份均有全部 65 项 | 每份 1,088 字节，可放入该 CP 配置的 2,048 字节区域 |

现存属性的 1,386 次原始数据／属性比较与固定版本 PMCA 主机解析器一致；44 次缺失属性也由 PMCA 独立拒绝。全部输入仅是公开默认模板，输入缓冲区只读；没有执行 Sony 原程序或 guest，没有生成 `LdrBkup.bin` 或改包。

因此不能把 CP 的清单、生成结果、配置或镜像直接当作 AP 适配输入。AP `loader_emmc.tar` 及其实际属性清单仍未取得。不能把 AP 的缺失属性补零后继续，也不能用默认模板替代这台机身的完整原始数据。

## 两条官方写入路线

`loader_writer.sh` 使用 `loader_emmc.tar`，挂载设置分区后复制 `/setting/Backup.bin`，以 `-m` 生成 AP 启动属性，随后把 `/dev/nflashaB0` 交给 `pformat.elf`。可选 DDR training 路径还会从运行中内存取数据，按 MIS 信息定位后向同一启动设备写入。脚本包含可写挂载和持久写入，不能作为只读检测执行。

`nor_loader_writer.sh` 使用 `loader_nor.tar` 与 `-c`。若更新包包含 Backup 文件，脚本可能选择包内文件；否则取设置分区文件。它通过 SPI 装入 `loader_spi.bin`，随后使用 CP updater，并按检测条件更新 NOR 组件。生成的 `nor_ldr.img` 还会被复制到所挂载的 p8。**包内默认配置、更新侧副本与当前同机配置需要分别识别。**

审查的当前官方包外层 155 个成员中，没有 `loader_emmc.tar`；NOR 内层四成员也不含现成的 `LdrBkup.bin`。这只是已审查包的成员事实，不是“相机没有 AP 启动数据”的结论。

## 工具返回成功不能充当写入或恢复验收

`pformat.elf` 的选中写入函数以 `0x101002` 打开传入设备，并对其偏移 0 创建长度 `0x200000`、可读写、共享的映射。后续可见向映射写入 header 和配置选择的组件。因此这是可修改启动区域的实现；映射 2 MiB 不等于每个字节都会被覆盖。缺少 AP 配置时不能推算其全部组件足迹。

另一个需要纳入适配器的事实是：主流程在 `0x4093D0` 把返回用的 `w19` 设为 0，调用写入函数后直接跳转到返回尾部，没有把写入函数结果转入 `w19`。返回尾部以 `w19` 为程序结果。这个**选中调用路径**会丢弃底层返回码，不能仅以退出 0 或日志 OK 判定成功。5 项独立原始指令字检查确认了这些赋值、调用和分支。

没有据此声称实际设备写入失败，也没有泛化为所有官方更新路径均不报错。适配器仍须有独立内容回读、重启及恢复结果，不能转发官方日志作为最终收据。

## 对既有结论的修订

第 210、211 轮当前 `loader_nor.bin` 的字节、SIO 字段、计时叶函数相等、C 初始化清零等结果仍保留，但其证据范围收紧到 **CP NOR 组件**。涉及该组件的第 196、197、198 轮条件路径也不能升级为 AP p1／p3 选择或独立救砖证明。旧封存不改写，本轮在 canonical 中新增更正并给相关字段加范围说明。

第 208 轮的 AP 首记录／CP 第二记录分工，以及第 211 轮来自官方默认 AP 属性和公开 A7 IV AP 参考的 `rate=3/channel=0/port=4/bit=2` 离线候选继续保留；它仍不是这台 FX3 的实测设置、可执行载荷或可刷镜像。
